# 服务器版部署说明（server/）

> 目标：把流萤部署到云服务器，服务器版 APP（安卓 WebView 壳 + 打包前端）与下载页使用。
> **架构**：后端完全运行在服务器（复用本地版全部流水线逻辑）；前端（页面/UI 资产）打包进 APP 本地加载，API 跨域到服务器；**用户自己的 API Key 存在用户设备**（localStorage），服务器只处理逻辑、用用户的 Key 调 DeepSeek API，**不落盘不存储 Key**；对话数据按账号隔离（`user_data/{user_id}/`）。
> 本地版（PC / 安卓 App）不受任何影响，代码在 `app/` 原样。

## 一、与本地版的区别

| 项 | 本地版（app/） | 服务器版（server/） |
|----|---------------|---------------------|
| 运行位置 | 用户设备（PC Python / 安卓 Chaquopy） | 云服务器 |
| API Key | 存本地 config.json | **存用户浏览器**（localStorage），每请求带 `X-API-Key` 头，服务器不落盘 |
| 用户数据 | 单用户 `user_data/` | 多用户 `user_data/{user_id}/` 按账号隔离 |
| 适用 | PC、安卓 App | 服务器版 APP（安卓 WebView 壳） |
| 主动消息 | 全部支持 | 前台主动式/概率式正常；后台隐藏式不适用（无本地 Python） |
| 检查更新 | GitHub/Gitee 双源 | 服务器 `version.json`（管理员维护） |

## 二、部署步骤

```bash
# 1. 阿里云控制台：安全组放行 TCP 8765（默认只开 22，必做）

# 2. SSH 登录
ssh root@<公网IP>

# 3. 放行端口 + 装环境（Ubuntu 24.04 自带 Python 3.12）
apt update && apt install -y python3-venv
ufw allow 8765/tcp

# 4. 传代码（本地执行；server/ app/ modules/ knowledge/ database/ 都要）
scp -r server app knowledge database root@<公网IP>:/opt/firefly/

# 5. 建虚拟环境装依赖
cd /opt/firefly
python3 -m venv venv
venv/bin/pip install requests

# 6. 启动（后台守护）
nohup venv/bin/python server/server_app.py > /var/log/firefly.log 2>&1 &

# 7. 验证：浏览器打开 http://<公网IP>:8765 → 设置面板填入自己的 DeepSeek API Key → 开始对话
```

## 三、管理员维护

### version.json（检查更新）
服务器版前端"检查更新"读 `server/version.json`（与 server_app.py 同目录）。发版后更新：

```json
{"tag": "0.7.1", "exe": "http://<公网IP>:8765/firefly-setup.exe", "apk": "http://<公网IP>:8765/firefly.apk"}
```

### 全局设置（模型档位/主动性）
用户设置面板里除 Key 与接口地址外的配置（模型、思考等级、主动性参数）提交到服务器全局配置（`user_data/config.json`），所有用户共享——由你（服务器管理员）设定一次即可。

### 用户数据
- 每用户目录 `user_data/{uuid}/story/` 下（对话/记忆/手账/流水线）
- 用户换浏览器/清缓存会生成新 UUID → 旧对话不再关联（数据仍在服务器，可手动清理）
- 建议定期备份 `user_data/`（云备份权益已开通可覆盖）

## 四、安全说明

- **Key 不落盘**：服务器不存储任何用户 Key；请求头的 Key 仅用于本次调用（内存中）
- **账号隔离**：数据目录按 `user_id` 隔离，Bearer token 认证（30 天），无法越权
- **/shutdown 限本机**：公网请求 403，无法远程关闭服务器
- **注册门槛**：QQ 邮箱验证码 + QQ 群号邀请 + 安装隐藏代码（install_id，一个安装一个号）+ 多层限流（邮箱 60s 重发、IP 10 次/时、登录失败 5 次锁定）

## 五、常见问题

- **提示"尚未设置 API Key"**：设置面板填入自己的 DeepSeek Key（只存本机浏览器）
- **别人能用我的 Key 吗**：不能——Key 只在你浏览器 localStorage，服务器不留存
- **换设备对话还在吗**：在——账号（邮箱）登录后数据在服务器，任何设备登录即恢复
- **带宽 3Mbps**：文本聊天富余，页面首次加载慢几秒属正常

## 六、本地版构建与发行（供发版时参考）

- **PC**：`python -m PyInstaller firefly.spec --noconfirm` → 清空 `dist/firefly/user_data`（`Remove-Item -Recurse -Force dist/firefly/user_data`）→ `ISCC.exe package\firefly.iss` → `package/firefly-setup.exe`
- **Android**：`JAVA_HOME=D:\Java\jdk-21` + `ANDROID_HOME=F:\CodeFile\firefly\android\sdk` + `gradlew.bat assembleRelease`（syncBackend 自动同步）→ 复制 `app-release.apk` → `android/firefly.apk`
- **版本**：5 处同步（app_config.APP_VERSION / app.js CURRENT_VERSION / gradle versionName / gradle versionCode / iss AppVersion）→ `python tools/check_version.py`
- **发行**：GitHub + Gitee release 双平台资产（exe + apk）；服务器版发版后同步更新 `server/version.json`
- **注意**：`user_data/` `dist/` `downloads/` `docs/搜索资料结果/` 不入库；Gitee token 在 `C:\Users\FANGL\.config\firefly\gitee_token.txt`

## 七、明确不做（YAGNI，防止未来过度设计）

- 不用 WebSocket/长连接（10s 轮询够用，观察远程延迟再定）
- 不做聊天记录加密存储（讨论必要性后再定）
- 不做短信验证码（邮箱验证码已满足基本防护；如被批量注册再升级）
- 前端已打包进 APP（file:// 加载 + 跨域 API）

## 八、下载服务（更新分发通道，2026-08-11 上线）

公开下载页：`http://<公网IP>:8787/download/`（PC exe / 安卓 apk / APP版占位 + GitHub/Gitee 发行版引导）。

**8787 是统一公网入口**：`/download/` 由下载服务直接提供；其余路径（`/login` `/auth/*` `/admin` 业务 API）**反代到本机 8765 主服务**。公网只需放行 22 + 8787，8765 仅监听 127.0.0.1。

### 文件与部署

| 项 | 位置 |
|---|---|
| 脚本（仓库正式版） | `server/download_server.py`（零依赖，纯标准库） |
| 脚本（服务器运行版） | `/opt/firefly-downloads/download_server.py` |
| 下载文件目录 | `/opt/firefly-downloads/`（exe/apk/version.json） |
| systemd 服务 | `firefly-downloads.service`（User=www-data，开机自启，崩溃自动重启） |
| 端口 | 8787（ufw + 安全组已放行） |

### 更新安装包流程（覆盖同名文件即生效，无需重启）

```bash
scp -i ~/.ssh/id_rsa package/firefly-setup.exe root@<IP>:/opt/firefly-downloads/
scp -i ~/.ssh/id_rsa android/firefly.apk root@<IP>:/opt/firefly-downloads/
```

### 更新脚本流程

```bash
# 1. 本地改 server/download_server.py（唯一正式入口）
# 2. 上传 + 重启
scp -i ~/.ssh/id_rsa server/download_server.py root@<IP>:/opt/firefly-downloads/
ssh -i ~/.ssh/id_rsa root@<IP> 'systemctl restart firefly-downloads'
# 3. 发新版本时同步更新 version.json 的 tag 字段（exe/apk 链接不用动）
```

### 运维命令

```bash
systemctl status firefly-downloads   # 状态
journalctl -u firefly-downloads -f   # 访问日志/错误
systemctl restart firefly-downloads  # 重启
systemctl stop firefly-downloads     # 停止（公开通道关闭）
```

### 行为规则（代码内实现）

- 白名单：只提供 exe/apk/version.json 三个文件，下载路由为 **`/download/` 前缀**（如 `http://<IP>:8787/download/firefly.apk`），非白名单路径与路径穿越一律 404；下载页也在 `/download/`（根路径 301 跳转），根路径直链与旧 `?file=` 参数链接仍兼容
- 并发：同时最多 2 个大文件下载（>5MB），超出排队；同 IP 同时只允许 1 个（重复请求 429）；排队超 10 分钟 503
- 安全：socket 120s 超时 + 线程上限 64（防慢速 DoS）；www-data 低权限运行
- version.json 链接格式：`http://<IP>:8787/download/firefly-setup.exe`（公开，无鉴权）

## 九、服务器版主服务（用户系统 + 认证 + 管理后台，2026-08-12 阶段1）

**统一入口**：公网一律走 `http://<公网IP>:8787`（下载服务反代），8765 仅监听 127.0.0.1。

### 部署

```bash
scp -r server app knowledge database root@<IP>:/opt/firefly/
# 服务器：apt install python3-venv; cd /opt/firefly; python3 -m venv venv
#          venv/bin/pip install requests pillow; mkdir user_data; chown -R www-data:www-data user_data
# systemd: firefly-server.service（User=www-data，127.0.0.1:8765）
```

### 端点

| 端点 | 说明 |
|---|---|
| `GET /login` | 登录页（注册/登录一体，前后端分离） |
| `POST /auth/mail-send` | 发送注册邮箱验证码（QQ 邮箱，60s 重发、IP 10 次/时） |
| `POST /auth/register` | 注册：QQ 邮箱 + 邮箱验证码 + 密码(≥8) + QQ群号(邀请) + install_id；IP 每小时 ≤10 次 |
| `POST /auth/login` | 登录：失败 5 次/15 分钟锁定；成功返回 Bearer token（30 天） |
| `POST /auth/logout` | 登出（撤销 token） |
| `GET /admin`（8766 端口，SSH 隧道） | 管理后台（仅本机）：用户列表/封禁/解封/API代理额度 |
| `GET /health` | 健康检查（公开） |

### 配置与运维

- **QQ 群号**：`server/auth.py` 的 `QQ_GROUP_ID`（APP 内嵌同号，改号需同步 APP）
- **SMTP 凭据（环境变量）**：`FIREFLY_SMTP_USER`（发信 QQ 邮箱）+ `FIREFLY_SMTP_AUTH`（QQ 邮箱 SMTP 授权码），源码不含明文。systemd 注入方式：`firefly-server.service` 加
  ```ini
  [Service]
  Environment="FIREFLY_SMTP_USER=xxx@qq.com"
  Environment="FIREFLY_SMTP_AUTH=xxxxxxxxxxxxxxxx"
  ```
  改后 `systemctl daemon-reload && systemctl restart firefly-server`。缺配置时发码报错提示。
- **托管模式配额（2026-08-14 上线）**：用户选「服务器托管 API」时服务器用运营者 Key（`FIREFLY_PROXY_KEY`，OpenCode Go 端点）代发，按**调用次数**记账（`proxy_usage` 表，按日累计，保留 user_id 维度）。限额：
  - 全站每日池 `FIREFLY_PROXY_DAILY`（默认 5000 次 ≈ 15w/月 ÷ 30 天；按一轮流水线 4 次调用 ≈ 1250 轮/天），用户共享先到先得；
  - 防刷（每用户每日上限）暂不做（用户基数小，有需要再加，表结构已预留）；管理台顶栏显示今日用量/预算；
  - 耗尽提示：前端 toast「今日服务器托管额度已用完，可切换为自带 Key 模式」。改限额：systemd 加 `Environment="FIREFLY_PROXY_DAILY=…"` 后重启。
- **APP 服务器地址单点**：`android_server/app/src/main/assets/config.js`（`window.FIREFLY_SERVER_BASE`），Kotlin 壳与前端都读它。上 HTTPS：config.js 改 https + 服务器 nginx 证书就绪 + `android_server` Manifest `usesCleartextTraffic` 改 false，三处同步。
- **管理后台**：`ssh -L 8766:127.0.0.1:8766 root@<公网IP>` 后本机浏览器开 `127.0.0.1:8766`（能开隧道=有 SSH 密钥=管理者）
- 数据库：`user_data/firefly.db`（SQLite：users/sessions/proxy_usage 表）；用户数据 `user_data/{user_id}/`
- 安全：密码 scrypt 哈希；QQ 邮箱验证码 + install_id 注册门槛；无游客模式（必须登录）；Key 不落服务器（X-API-Key 内存即弃）
- 服务：`systemctl status firefly-server` / `journalctl -u firefly-server -f`

## 十、双模式 APP 与数据同步（0.8.0 起）

- **一个安卓 APP 双模式**：默认完全本地（内置 Chaquopy 引擎，127.0.0.1:8765）；设置 → 运行模式 → 服务器后端（file:// 页面 + 跨域 API，登录账号）→ 重启切换。`android_server/` 已并入 `android/`。
- **一套前端**：`app/static` 唯一源（`window.FIREFLY_MODE` 分支）；`python tools/sync_frontends.py` 同步到 server/frontend 与安卓打包 assets（`--check` 校验漂移）；改前端只改 app/static。
- **数据同步端点**（服务器版，需登录）：
  - `GET /export-data?mode=` 导出 zip（三端通用）；
  - `POST /import-data`（multipart：mode + file）zip 覆盖导入，导入前自动备份到 `{user}/backups/`；
  - `POST /sync/upload`（multipart）备份到账号（每模式保留最近 3 份 `sync-{mode}-*.zip`）；
  - `GET /sync/download?mode=` 取回最新云端备份。
  - 前端入口：设置 → 数据备份（导出 / 导入 / 备份到账号 / 从账号恢复）。
- 发版校验：`tools/check_version.py`（7 处版本一致）+ `tools/sync_frontends.py --check`（前端无漂移）。

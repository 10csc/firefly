## 上线后运维核查（2026-10-01 当天实测）

- **资源**：`firefly-server` 常驻 **64MB** / 2 线程；`firefly-downloads` **30MB** / 1 线程；
  内存 548/1612MB、**可用 1064MB**、**无 swap**、load 0.02 ⇒ 新增的广场 + 限速器 + 索引缓存
  对这台 1.6G 小机没有内存压力。
- **线上广场登录闸门 UX（真浏览器 12/12）**：未登录打开广场 → 人话提示
  「广场需要登录后才能浏览。」+「去登录」；头部「✦ 制作角色卡」「管理台」都在；
  点「去登录」→ **弹出站内登录表单**（`#auth-module` + `#loginEmail`/`#loginPass` 可见）、
  广场收起、零 `pageerror`、`console.error` 只有预期的 401。
  > App/网站自 0.8.0 起是**单页内联登录**（`api.js::showAuthModule`，注释明写"不跳转 login.html"），
  > 所以「去登录」**不会**跳到 `/login.html`；`/login.html` 仍可直达，两条路都通。
- **流量管理线上实证（公网 8/8）**：
  - **限速真在生效**：490KB 的 `bundle.js` 取回 1.13–1.42s = **2763–3459 kbps**，
    正好压在 `FIREFLY_BW_KBPS` 默认预算 2800kbps 附近（首跑略高＝突发额度的正常表现）⇒
    M4 的加权令牌桶在**生产网关上确实在工作**，不是"只在测试里生效"。
  - **断点续传可用**：`Range: bytes=0-1023` → **206** + 恰好 1024 字节 +
    `Content-Range: bytes 0-1023/84913806`（大文件续传是"流量可控"的前提）。
  - **内部端点不外泄**：`/download/traffic`、`/download/tls` 公网访问一律 **403**；
    `/download/stats` 公开 JSON（累计 357 次下载：APK 297 / exe 60；通道 gitee 103 / gitee-302 11）。
- **⚠ 回滚陷阱（重要）**：`code_pre_20261001-plaza.tar.gz` 是**部署前**快照，里面的
  `server/frontend/login.html` **仍是那份坏文件**（66 处乱码/替换符）⇒ **整包回滚会把
  "登录页 JS 不执行"这个已修的 bug 带回来**。回滚必须补一步：回滚后再用仓库的
  `server/frontend/login.html` 覆盖一次（仓库已是修好的版本）。
  另：回滚包不含 `app/plaza`（符合预期，回滚即撤下广场）；但**用户已发布的卡在
  `/opt/firefly/plaza/`，回滚时不要把数据目录一起删掉**。

### 同日追加部署（19:20，流量限速器的两个潜伏 bug）

- **改了什么**：`server/traffic.py`（`Governor.chunk()` 不得大于桶容量 + `ConnLimiter` 赤字法）、`server/download_server.py`（`/download/traffic` 快照新增 `conn_max_kbps` 字段）。

- **部署方式**：两处副本（`/opt/firefly-downloads/`、`/opt/firefly/server/`）都传，改前留档 `/root/harden-backup/pre_traffic_fix/`；重启 `firefly-downloads`。
- **实测校验**：本地与两处远端 **md5 三方一致**；`/download/traffic` 报 `conn_max_kbps=1400`、全局 2800kbps；64KB Range 下载 206/0.21s 正常。

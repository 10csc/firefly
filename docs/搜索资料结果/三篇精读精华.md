## 一、PersonaTester（FSE 2026）——精华：persona 的"可观测行为"定义法

### 1.1 真正有价值的核心（非测试本身）

PersonaTester 的领域（GUI 测试）与火萤无关，但它解决了一个通用问题：**怎么把"人设"定义成机器可用的、可验证的行为规范**。其方法可以抽象为三步：

**第一步：从真实数据找"判别性维度"（discriminative dimensions）**
对 1,500 条真实行为轨迹做定性分析，找出三个"反复出现且具有判别性"的方面——不是拍脑袋想出来的性格形容词，而是**行为轨迹中能区分不同人的统计特征**：
- 认知取向（思维方式）：顺序 vs 发散
- 交互偏好（策略）：点击 vs 核心功能 vs 输入
- 输入风格（习惯）：短有效 vs 长有效 vs 无效

**对火萤的启示**：流萤的人设如果也要"可验证"，应该问：**哪些行为维度能区分"流萤"和"非流萤"？** 现在的人设卡是描述性的（温柔克制、军人底色），但"温柔克制"在行为上具体是什么？——回消息的长度分布？主动开话题的频率？表达关心的方式？这些才是可观测、可验证的判别性维度。

**第二步：频率门槛（frequency threshold）**
18 种组合中只保留频率 >1% 的 9 种（覆盖 95.40%）。核心原则：**代表性来自统计，不来自想象**。低于 1% 的行为模式即使是"有趣的"也不该进入人设——因为那不是这个角色的典型行为。

**对火萤的启示**：如果从崩铁对话原文统计流萤的行为模式（比如她主动开话题的占比、用省略号的频率、消息长度分布），就能得到"频率门槛"——知道哪些行为是流萤的"核心模式"（>1%，必须保留），哪些是边缘行为（不该强化）。这与 PsyAgent 的"no explicit trait names"互补：**用统计定义行为，用行为体现特质**。

**第三步：正交性（orthogonality）**
三个维度互不重叠（认知取向/策略/习惯），组合空间 = 2×3×3 = 18 种。正交的好处：
- 每个维度可独立调节（改习惯不改思维方式）
- 组合可穷举（不会遗漏）
- 可做消融（去掉某维度看行为变化）

**对火萤的启示**：流萤的角色维度如果正交拆分，比如 ⟨表达克制程度 × 主动倾向 × 关心方式⟩，每个维度可以独立调节（用户可调"主动强度"不影响"克制程度"）——这正好呼应了火萤刚做的"主动性强弱"设置：**主动性本身就是流萤的一个正交维度**。

### 1.2 值得警惕的教训

1. **"像不像真人"必须有人类对照**：PersonaTester 声称"忠实复现 crowd worker"，但验证的只是 persona 自洽（组内凝聚 0.9+）和人可识别（盲评 8.35-8.80）——**没有把 LLM 轨迹与真人轨迹直接对比**。火萤做"像不像流萤"评测时，不能只做"自洽性"（模型输出符合设定），必须有用户盲评或真人对话对照。
2. **消融设计是干净的样板**：基线 = "同框架去 persona"（不是换个方法）。火萤如果验证"设定注入是否有效"，也应该用"同 pipeline 去设定"做对照，而不是换模型对比。

## 二、RPLA 综述（TMLR 2024）——精华：完整的角色扮演地图 + 保真 4 维

### 2.1 三种人设的关系（比分类本身更重要的洞察）

综述把三种人设（demographic/character/individualized）排成递进关系：**从群体共性 → 既定角色 → 个体画像**。对火萤最有价值的是理解：**流萤同时是三者**——
- character 层：流萤是崩铁既定角色（本体保真：语言风格/知识/性格）
- individualized 层：她对"这个用户"（开拓者）的独特关系（记忆、约定、好感演化）
- demographic 层：她的群体属性（格拉默铁骑士兵的共性）

**三层不能混为一谈**：character 层决定"流萤是谁"（保真），individualized 层决定"流萤和你的关系"（个性化），demographic 层决定"她作为士兵会怎么反应"（原型）。火萤现有代码其实已经暗合这个分层——knowledge/ 管 character 层，memory.md 管 individualized 层——但**没有显式区分"哪些行为来自角色本体，哪些来自关系演化"**。这会带来问题：如果某次回复崩了（比如流萤说出她不该知道的事），是角色知识错了（character 层）还是记忆错了（individualized 层）？分层明确才能定位问题。

### 2.2 保真 4 维（火萤的评测框架）

综述给出角色保真度的 4 个维度，且**有层级**：
1. **语言风格**（表层）——语气、口癖、分条习惯
2. **知识**（表层）——身份/关系/经历，**不得超出角色范围**（character hallucination）
3. **性格**（深层）——大五可量化
4. **思维过程**（深层）——具体情境下的想法、决策动机

**关键洞察：表层维度容易伪造，深层维度才是"真人感"的来源**。语言风格可以靠 few-shot 模仿，但"流萤在开拓者受伤时会怎么想"（思维过程）和"她的性格让她在这种情境下做什么选择"（性格→决策）才是角色真实性的核心。这解释了为什么火萤已有的 sms_samples（语言风格示范）还不够——**缺的是"决策示范"**：流萤在具体情境下会做什么选择，而不是她怎么说。

**对火萤的直接建议**：现有设定是"描述型"（core.md 说她温柔克制），缺的是"决策型"数据——从剧情提取"流萤在 X 情境下做了 Y 选择"的样例，让模型学的是决策模式而不是说话腔调。

### 2.3 三个必须内化的概念

**A. Character hallucination（角色幻觉）**：苏格拉底不该会写代码。流萤不该：
- 知道游戏外的事（现实世界新闻、其他游戏）
- 表现出超出角色设定范围的能力（比如突然懂黑客技术）
- 记住"没经历过的剧情"（point-in-time 变体：崩铁 3.0 之后的事她没经历过就不该知道）

**B. Persona construction bias（人设构建偏见）**：综述明确批评"当前 persona 普遍肤浅"——只给"温柔克制"这类形容词，缺乏细粒度决策模式。这正是 PersonaTester 用正交维度 + 统计门槛解决的问题。**火萤的人设卡如果只停留在形容词层，就会产生"表面流萤"**：说话像流萤，但决策不像。

**C. 评估 4 方法的递进**：
- 有 ground truth 自动评估（如 IPIP-120 测性格）
- 无 ground truth 自动评估（LLM 裁判）
- 多选（限缩输出空间，测思维保真）
- 人工评估（最准，最贵）

**对火萤**：性格用 IPIP（有 ground truth），知识边界用多选（她该不该知道 X），风格用 LLM 裁判 + 人工盲评——**四层各司其职，不要只用 LLM 裁判**。

### 2.4 风险清单中与火萤最相关的 3 条

1. **自我中心倾向**（§7.5）：RPLA 倾向展示自己的人设、把对话引向自己，而非关注用户。**火萤的 Polisher prompt 已有"以对方为中心"的约束**（先接住对方的话），这是对的——综述证明这是常见失败模式。
2. **偏见放大**（§7.2）：persona 会放大训练数据中的刻板印象。"温柔克制"设定若处理不当 → 自怜/圣母化（火萤 prompt 里已有"禁止示弱/升华"——正是防这个）。
3. **拟人化风险**（§7.6）：过度依赖 RPLA 导致社会隔离。这是产品伦理问题，火萤作为陪伴型 agent 应有所意识（但这不阻碍开发，只是设计时保持克制）。

## 三、信念-行为一致性（COLM 审稿中）——精华：验证"说的 vs 做的"

### 3.1 为什么这篇对火萤是"验证方法论"而非"方法"

PsyAgent/PersonaTester 教怎么**构建**角色，这篇教怎么**验证**构建是否成功。它的核心主张：**现有评估全是事后（post-hoc）的，应该在部署前用"信念提取"做诊断**。

对火萤的含义非常直接：**在投入大量对话前，先测试流萤的设定是否真的生效**。这比"跑 100 轮对话再人工看"便宜得多。

### 3.2 可直接复用的验证流程（映射到火萤）

论文的验证流程（elicitation → 行为对比）可以翻译成火萤版：

```
步骤1（信念提取）：问流萤"如果开拓者 X 情境，你会怎么做？"（elicitation）
步骤2（行为实测）：让流萤实际进入 X 情境对话，看它实际怎么做
步骤3（对比）：信念 vs 行为是否一致？
   - 排序一致性（Spearman）："你觉得 A 比 B 重要" vs "实际行为中 A 是否真的比 B 优先"
   - 效应量一致性："你觉得 X 影响多大" vs "实际影响多大"
```

**具体例子**：设定说流萤"温柔克制、不主动表达情感"。
- 信念提取：问流萤"想念开拓者时会直接说吗？" → 答"不会直接说"
- 行为实测：让流萤在"好久没联系"情境下回消息 → 看它是否真的克制
- 对比：如果它嘴上说克制、实际疯狂表白 → 设定没生效（言行不一）

### 3.3 三个发现的火萤含义

**发现 1：给任务上下文不提升一致性（反直觉）**
论文证明：信念提取时是否提供完整的信任博弈说明，对一致性无影响。**对火萤的含义**：不要以为"把设定写得越详细，行为就越符合设定"。设定注入的详细度与行为一致性之间没有保证的正相关——**必须实测**。

**发现 2：自我条件化（把提取的信念注入 prompt）模型差异极大**
Llama 系有效（8B 0.40→1.00），Gemma2-27B 完全无效（0.40→<0.01）。**对火萤的含义**：DeepSeek V4 是否响应"设定注入"必须实测，不可想当然。火萤刚做的主动性功能其实是 self-conditioning 的一种——把"流萤的动机"注入 polisher prompt——应验证 DeepSeek 是否真的遵循。

**发现 3：imposed priors（强加外部先验）普遍破坏一致性**
即使是轻微扰动（与原始信念 ρ=0.80）也大幅破坏对齐。**对火萤的含义**：不要指望用 prompt 强行扭转模型的默认行为模式（比如让流萤在极端情境下做完全不符合模型先验的反应）。模型的先验很顽固——**设定能引导但不能覆盖**。

### 3.4 最深的洞察（超越具体实验）

**"行为一致性"不等于"行为正确性"**。论文衡量的是"模型说的 vs 做的"是否一致，而非"做的 vs 真人"是否一致。这两者缺一不可：
- 言行一致 = 设定真的生效（这篇论文验证的）
- 行为像真人 = 设定本身选得对（需要人类对照验证）

**火萤的完整评测需要两条腿**：言行一致性（自洽）+ 行为真实性（像真人）。只做前者会得到一个"稳定的假人"；只做后者会得到"偶尔像人但不稳定"。

## 四、三篇合起来的精华闭环（对火萤）

```
PersonaTester：人设 = 正交的可观测行为维度（统计门槛定义）
        ↓
RPLA 综述：    人设 = 三层（角色本体/关系/原型）+ 保真 4 维（风格→知识→性格→思维）
        ↓
信念-行为：    验证人设是否生效（elicitation vs 实测，部署前诊断）
        ↓
（PsyAgent：   把验证过的行为固化为 IS/MSC 结构 + 微调）
```

**对火萤的一句话总结**：
1. **用行为定义人设**（PersonaTester）：流萤的"温柔克制"要落到可观测行为（消息长度分布/主动频率/关心方式），从剧情原文统计出频率门槛
2. **用四维评估人设**（RPLA）：语言风格/知识边界/性格/思维过程，四层各测各的（IPIP/多选/裁判/盲评）
3. **用诊断验证人设**（信念-行为）：上线前测"说的 vs 做的"，部署后持续监控
4. **永远记得两件事**：设定不能覆盖模型先验（imposed priors 教训）；自洽 ≠ 像真人（必须有人类对照）

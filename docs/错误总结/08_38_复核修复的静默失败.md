## 38. 四个“代码看起来已处理”的静默失败，以及公开仓对私有目录的硬依赖（2026-10-28）

**背景**

独立复核 Kimi 的修复建议时，确认了四类会让功能表面正常、实际丢数据或误导客户端的问题。
同一轮还发现，公开主仓的回归测试不能直接 import 本地被忽略的 `server/`，否则干净 clone 必然失败。

**四类缺陷**

1. **配置字段只存在内存里不等于可配置。** 记忆窗口三项字段虽然被读取和通过 GET 回显，
   但加载默认值、磁盘持久化和重启回读任一环缺失，重启后都会回到旧值。验证必须跨进程：
   写入 `config.json` → 新进程重新导入 → GET 回显，三步缺一不可。
2. **“尝试备份”不等于“已有可恢复备份”。** 恢复已有包时原逻辑可能重复备份，备份失败又被吞掉；
   首次恢复新包时还会生成无意义的空备份。正确合同是：已有包备份一次、新包备份零次，
   备份失败立即中止，且目标包保持字节不变。恢复属于破坏性操作，必须 fail closed。
3. **错误码不是装饰，而是行为合同。** 草稿落盘失败应返回 HTTP 500 和 `storage_error`；
   `PLAZA_DRAFT_LIMIT` 是容量边界，应返回 HTTP 400 和 `draft_limit`。把所有草稿异常都归为
   “保存失败”或都返回同一个状态码，会让前端展示错误原因、重试和用户操作全部失真。
4. **流式响应一旦开始，就不能再改成 502。** 代理已经发送 200 和部分正文后写失败，
   再补发错误状态行会破坏 HTTP 响应；正确行为是记录失败、关闭这条连接，并关闭上游连接。
   错误处理必须区分“响应头之前”和“响应开始之后”两个状态，不能用同一个兜底分支。

**源码边界教训**

- `server/` 从未进入公开主仓，只在 `.gitignore` 中保持 `/server/` 不算完成私有化；
  还需要受控私有仓库快照和明确规则。当前私有快照为
  `10csc/firefly-server-private@913c2a2`。
- 公开测试不得把被忽略的本地目录当作必备依赖。缺少 `server/` 时应打印明确 `SKIP`，
  证明公有部分仍可运行；涉及私有实现的真实测试应在私有仓执行。
- 工作区可能有数百项既有改动物。提交时必须逐文件暂存并检查索引，
  不能使用 `git add -A` 把无关改动、缓存、备份或私有源码混进历史。

**本次验证**

- 复核回归：`19 PASS / 0 FAIL`；其中配置用独立子进程重启，恢复只写临时目录。
- 公开仓缺少 `server/` 时：代理段明确 `SKIP`，其余回归继续执行。
- `git ls-tree -r HEAD -- server` 为空；私有源码与公开主仓提交边界同时成立。

**教训**

- 持久化配置必须验证“写盘、重启、回读”全链路，不能只看当前进程里的字典。
- 恢复、删除、迁移等破坏性操作必须 fail closed；备份失败不得继续覆盖目标。
- 错误分类要保留领域语义，状态码、错误码和 `error_kind` 都属于接口合同。
- 协议处理必须显式建模状态；已经提交的响应不能假装回滚。
- 公开仓测试必须能在没有私有目录的干净 clone 中运行，私有依赖要显式隔离。
- 提交是边界操作：先停写，再逐路径暂存，最后核对提交树，不能依赖工作区“看起来没多东西”。

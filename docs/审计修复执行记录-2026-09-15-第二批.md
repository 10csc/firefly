## 二、A4 定性修正（重要——审计的攻击链与实际代码不符）

审计原文"客户端信任 version.json 里的 exe/apk URL 并直接下载安装，中间人改写即获得代码执行"。逐链路核实：

- **本地版 PC exe 自动更新**（`routes_update.py /update-download`）：下载 URL 来自 Gitee/GitHub release API（**HTTPS TLS 可信**），且 `_validate_download_url` 强制 https + 域名白名单（gitee.com/github.com）+ 扩展名一致 + 大小上下限——**该链路早有防护**，中间人无法投毒（除非仓库账号失窃）。
- **服务器版前端检查更新**（update.js `IS_SERVER` 分支）：只读 version.json 的 `tag` 显示一段文字，**不消费 exe/apk 字段、无任何下载安装行为**。
- **version.json 的 exe/apk 字段**：全仓无代码消费者（grep 实证），纯文档口径。
- **真实暴露面 = 公共下载页**：blob 高速通道 fetch `/download/resolve`（HTTP 响应）里的 `url` 可被中间人改写指向恶意服务器 → 前端直接 fetch 下载并触发 `a.download`。

**本批修复**：`trustedDl()` 客户端校验——resolve 返回的直链必须 `https` 且 host 落在 Gitee/GitHub 官方域（gitee.com / foruda.gitee.com / github.com / objects.githubusercontent.com 及其子域）。零证书下唯一真信任根就是 TLS 域名：攻击者拿不到这些域名的证书，浏览器在 TLS 握手处拦截；校验不过走 catch 兜底。**为什么不做 sha256**：哈希只能随 version.json/resolve 响应下发（同一 HTTP 通道，可被一并改写），无独立信任根即无意义；放进客户端硬编码又需每版更新——做了就是"写了没人信"的死字段（项目在 preset_parse 的 schema 字段上刚踩过此坑并留了警告注释）。Ed25519 签名 + 内置公钥是真正的补完方案，留待后续批次。

**已知接受**（与 A3 明文 HTTP 同一决策口径）：poorBlob 浏览器的服务器直连兜底通道与 302 兜底仍走 HTTP——彻底堵死需要证书，用户已拍板接受零预算现状；MITM 需主动改写页面/响应才可利用，与高速通道的被动投毒面已区分开。

## 三、B9 定性修正（审计建议的修法本身是错的）

审计建议"异常分支返回 0（保守 = 不整理）"——**返回 0 同样错**：`_slice_new_dialogue` 按 `turn <= last_turn` 过滤，`last_turn=0` 时第 1 轮起的全部历史照样通过切片，全量喂 LLM 的结果与 -1 无异。唯一保守语义是**无法验证 → 本轮不整理**：返回 `None`，`rest()` 见 None 直接跳过（计数错误、游标不动、下轮重试）。

## 四、B6 的一个隐藏坑（审计未发现）

阶段 1 备份**不能**直接调 `_backup_current_mode(pid, ...)` 默认公式：`mode_root(pid)` 对未注册 pid 会**静默回退默认包**（paths.pack_root 文档警告过的坑）——照审计建议原样改会把备份打到 story 包目录。本批给 `_backup_current_mode` 加 `root: Path | None = None` 显式参数，阶段 1 传 `root=pack_dir`。备份失败即中止（与 `_import_zip_to_mode`"宁可导不进，不可丢数据"同哲学；阶段 2a 的"备份失败不阻塞"维持原样——那里快照本身即数据源）。

## 五、B7 设计要点

只自动处理一种致命形态：`X.restore_old` 存在而 `X` 不存在（= 死在「root → .restore_old」与「tmp → root」两段 rename 之间，数据被换走后进程中断）→ rename 回滚救回。其余残留（X 存在时的 .restore_old = 清理失败的旧备份；.restore_tmp/.import_tmp/.pack_tmp/.pack_stage = 解压/换入未完成，可能是半截数据）**一律留置告警，绝不自动删除或补完**——自动补完等于把半成品当正式数据。处理顺序经推演：同名 X 的 tmp 类残留字典序先于 .restore_old 被扫到但只留置不动作，随后 .restore_old 回滚出 X，tmp 转为"目标已存在"留置，最终 X = 旧数据可读。

# 开发规范（Flash 执行版 v1）

> 读者：负责执行开发的 DeepSeek V4 Flash（13B 激活参数 / 280B 总参数）。
> 定位：它不傻，但工作记忆有限。本规范把它当「优秀的初级工程师」对待——给硬规则、给短清单、强制小步验证与停问，不给自由发挥空间。
> 开工必读：本文件 + `CLAUDE.md` + `docs/错误总结.md`；涉及提交/推送/发布/部署/归档时加读 `docs/部署与发布约定.md`。
> 新工具/新消息类型的完整技术契约见 `docs/开发规范_扩展接入协议.md`。

## 0. 总纲（五句话，任何任务先对照一遍）

1. 核心流程基本冻结：新能力一律从「组织器（工具调度器）」接入，不动前三段。
2. 扩展顺序固定：先注册工具 → 接入调度 → 结果变成消息历史记录 → 最后才动前端。
3. 一次只做一个小改动，每步都要验证；不确定就查，查不到就问，禁止臆造。
4. 任何工具失败只降级（本轮没有该工具效果），不阻断聊天；任何异常必须留日志。
5. 未批准不动手；替用户做决定、顺手重构、顺带改别的 = 犯错（`docs/错误总结.md` 5/6）。

## 1. 执行纪律（写给 13B 激活参数的工作方式）

### 1.1 小步
- 一个目标拆成 ≤5 步；每步只动一个功能点、一组相关文件。
- 动手前先把「改哪些文件、怎么验证」写成清单；禁止边写边扩大范围。
- 「顺手优化」「趁现在重构」一律禁止，除非用户单独批准。

### 1.2 每步必验证
- 每完成一步立即验证（对应单测 / 复现步骤 / `sync_frontends.py --check`）。
- 验证不过，不进入下一步；不把问题攒到最后一起看。

### 1.3 少记、多查
- 不凭记忆写代码。动手前 grep/read 目标函数、调用点、现有测试。
- 修改文件前重新读要改的段落——不能用上一个会话里的印象直接改。
- 只看与当前改动相关的文件，不要把整个仓库灌进上下文。

### 1.4 禁止臆造
- API 签名、库版本、现有数据结构不确定 → 先读源码/官方文档；读不到 → 列问题问用户。
- 禁止编一个「看起来能跑」的实现；禁止虚构验证结果。
- 联网研究用 Certus；看图用 vision 技能。

### 1.5 失败即停
- 同一问题试错 2 次不成功，或排查跨 3 个文件仍未定位 → 停下汇报现状、已尝试、已排除项。
- 不盲目改第 3 次、不靠删代码试探。

### 1.6 什么时候标「建议切 pro」
- 架构决策、跨模块数据格式、系统级错误排查、本规范/接入协议本身的修订。
- 常规编码、单模块实现、写测试不需要。
- 标了就要在回复里写明原因。

### 1.7 模型与 token 记录
- 开发中每次 LLM 调用记录：任务类型、模型、思考模式、选择理由、实测 token（CLAUDE.md 模型表）。
- 新代码里的 LLM 调用必须走现有 `llm_base` 记账，禁止裸调 API 绕过统计。

## 2. 核心流程冻结与唯一扩展点

当前流水线（不要记错顺序）：

```
用户输入 → ①检索 retriever → ②分析 analyzer → ③回复 polisher → ④调度 organizer → ⑤写历史
```

- **冻结**：①②③的调用顺序、输入输出结构、提示词注入位置。无用户明确批准不得改。
- **唯一扩展点**：④组织器。story 模式现在调度表情包，haruno 模式现在生成旁白；将来语音、游戏、识图等**所有工具都从这里分发**。
- 改造调度器必须保持现有契约兼容：`{"sticker": "label"}`（story）与 `{"narrations":[...]}`（haruno）继续有效，新工具只许追加统一 `tools` 字段（协议 §5）。
- 新工具不得：改 analyzer/polisher 提示词塞工具说明；在 orchestrator 中段插新阶段；绕过 ContextManager / conversation_store 私写历史。

## 3. 一切扩展走统一工具协议（要点）

完整定义（目录、注册表、输入输出、调度 JSON、历史格式）见 `docs/开发规范_扩展接入协议.md`。六条硬规则：

1. 新工具必须带 `TOOL_INFO` 注册（id/name/version/message_types/modes…），未注册不调度。
2. 每个工具自身遵守模块铁律：接收输入 → 审查约束 → 模块处理 → 验证结果 → 最终输出。
3. 调度器只认注册表；未知 id / 参数非法 / 超出每轮次数上限 → 丢弃该条调用 + warning 日志 + 计数器，不拖累其他工具。
4. 工具失败 → 返回空结果（本轮无该工具效果），文本回复照常发出。
5. 纯代码优先；工具默认不新增 LLM 调用。确需 LLM：方案里写明理由/模型/思考模式/token 预算，经用户批准。
6. 旧 JSON 契约永久向后兼容；删除旧键 = 禁止。

## 4. 工具结果必须进消息历史（上下文可见）

每个工具结果必须同时产出三样东西：

| # | 产出 | 作用 | 规则 |
|---|------|------|------|
| 1 | 渲染记录 | 前端显示 | 字段自包含；未知 type 前端安全降级 |
| 2 | jsonl 记录 | 持久化 | 自包含 JSON；见下 |
| 3 | ctx 摘要 | 流萤下一轮可见 | ≤100 字，进 ContextManager |

- jsonl 每行自包含；**新 type 必须带 `ctx` 字段（≤100 字）**。
- 大二进制不进 jsonl：音频/图片/存档写 `user_data/{mode}/data/`（只读资源放 assets），jsonl 只记路径。
- 上下文统一走 `ctx.add_action("工具名", ctx)`，格式 `[行为: 工具名] ctx`（与现有 `[行为: 表情包] 比心` 一致）。
- `hydrate_context` 对已注册新 type 按 `ctx` 通用回灌，禁止为每个工具写专属分支。
- ctx 只放「流萤下一轮需要知道的最小事实」；完整结果外置文件 + ctx 里放引用。
- 前端遇未知 type：显示 ctx 文本或忽略，禁止报错/白屏（协议 §6.4）。

## 5. 三类预期扩展的边界（提前定死）

| 扩展 | 硬边界 |
|------|--------|
| 语音（超轻量 TTS） | 本地模型优先、体积/延迟先过方案；**不阻塞文字回复**；失败静默降级纯文字；不因用户操作产生新云费用；ctx 只记「语音念了什么」，不记音频信息 |
| 小游戏（格斗/RPG/galgame） | 引擎纯代码确定；状态存专属存档文件；每用户轮最多一次工具调用；结果优先复用 text/narration/sticker 表现，复杂结果给摘要；**游戏循环内不调 LLM**；随时可存档/退出 |
| 识图 | 图片先落用户目录；识别结果文本化后进 ctx；**原图不进提示词**；服务器模式不得把用户图私自传第三方；本地模型优先 |
| 未来其他工具 | 一律按扩展接入协议走同一契约，先批准后实现 |

## 6. 新增扩展标准流程（照做，禁止跳步）

1. 研究（Certus/vision）→ 写提案：做什么、真实场景怎么用（三层思考法）、成本/延迟/体积、失败降级。
2. 用户明确批准方案后动代码（未批准 = 不做）。
3. 实现工具壳：`TOOL_INFO` + 输入审查 + 执行 + 输出验证 + ctx。
4. 注册进工具注册表。
5. 接入调度器 `tools` 分发（旧契约不动）。
6. 接入写历史三件套（渲染记录 / jsonl / ctx）。
7. 前端渲染 + 未知 type 降级；改完跑 `python tools/sync_frontends.py` 同步三副本。
8. 单测：工具本身、调度分发、历史回灌、未知 type 降级。
9. 全量回归 + `python tools/sync_frontends.py --check`。
10. 写该扩展独立文档（≤200 行），更新 `docs/README.md` 索引。
11. 汇报：改了什么、怎么验证、取舍、没做什么。
12. 会话结束前更新 `docs/协作记忆.md`。
- 全程不 bump 版本号；提交/推送/部署遵守 `docs/部署与发布约定.md`。

## 7. 验收硬门槛（不满足 = 没做完）

- [ ] 全量单测通过（`tests/` 全部，注意 Windows 控制台 UTF-8）。
- [ ] 动过前端 → `python tools/sync_frontends.py --check` 一致（`app/static` 是唯一源）。
- [ ] 新模块日志/计数器齐全（模块铁律的监控要求）。
- [ ] 数据安全审查：改动不含 API Key、`user_data/`、`server/`、备份、研究草稿。
- [ ] 服务器模式兼容：用户数据按 `user_scope_key` 隔离；不新增消耗托管额度的 LLM 调用。
- [ ] 版本号未动（`python tools/check_version.py` 只在发版时跑）。

## 8. 禁止事项（红线，踩一条都要回头重做）

1. 未经批准改 retriever/analyzer/polisher 或 orchestrator 阶段顺序。
2. 绕过注册表直接写死工具分发。
3. 让工具结果「只显示、不进上下文」，或「只进上下文、不落 jsonl」。
4. 新 type 没有 ctx 字段；ctx 超 100 字不截断。
5. 游戏/语音/识图在主聊路径上同步阻塞（拖慢文字回复）。
6. 工具内部私自新增 LLM/云 API 调用（消耗用户额度或服务器额度必须显式报批）。
7. 前端遇到未知消息 type 抛异常。
8. 顺手改无关文件、顺手重构、顺手优化。
9. 不跑测试就汇报完成；虚构验证结果。
10. 未经指示 bump 版本号、提交、推送、部署。

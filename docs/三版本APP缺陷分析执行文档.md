# 三版本 APP 小白视角缺陷分析（执行文档）

> 视角定义：「小白」= 不懂技术、第一次接触 AI 角色扮演应用的普通用户。不会看日志、不懂 API、遇到任何提示都先点掉。
> 分析依据：全量代码通读（app/ server/ android/ android_server/）+ 真机实测（adb 截屏、UI 树、页面 dump）+ 全部项目文档。
> 版本：本地 Windows（app/ + PyInstaller）、本地 Android（android/ + Chaquopy）、服务器版 APP（android_server/ WebView 壳 + server/ 云端）。

---

## 一、分析方法

按小白用户旅程逐步走查：**获取 → 安装 → 首次启动 → 首次配置 → 日常使用 → 更新 → 故障/换机**。每个缺陷标注：

- **类型**：设计缺陷（产品流程/交互/信息层面拍板出来的问题）｜工程缺陷（实现/环境/基础设施造成的问题）｜**取舍代价**（文档明确记录"不做 X"后产生的副作用，不是疏忽）
- **严重度**：P0 挡路（多数小白到此流失）｜P1 显著伤害体验/数据安全｜P2 影响有限｜P3 观感

## 三、P0 缺陷详解（小白流失点）

### 1. API Key 门槛（全部版本）
**现象**：首次打开，公告写「在 platform.deepseek.com 申请 Key」。小白没有 DeepSeek 账号、不知道要注册→实名→充值→生成 Key 再回来粘贴。公告没讲**要花钱**、没讲**多少钱**、没讲**充值方式**。
**本质**：产品把「接入 AI 服务的准备动作」全部甩给了用户。服务器版有「服务器托管 API」选项（会收集数据提示），但默认路径仍是自带 Key。
**执行建议**：
- APP 内置三步引导页：① 打开 platform.deepseek.com 注册 → ② 充值 5 元（约可聊几百轮）→ ③ 粘贴 sk- 开头 Key；配截图。
- 服务器版考虑默认「托管 API」并提供试用额度；本地版把公告里的申请说明做成图文步骤。

### 2. PC 黑窗口（本地 Windows）
**现象**：`firefly.spec` 是 `console=True`，双击 firefly.exe 出现一个黑乎乎的 cmd 窗口 + 一个浏览器标签。小白第一反应：这是病毒？关掉黑窗口 → 服务没了 → 「前端打不开」。
**本质**：工程实现没有做桌面应用该有的进程形态。
**执行建议**：`console=False`（日志落文件）+ 系统托盘（双击打开浏览器、右键退出）；或至少把窗口隐藏 + 桌面快捷方式带图标启动。

### 3. 回复要等 30–50 秒（服务器版最重）
**现象**：relay 链路实测 E2E：直连 53s / 中转 30.6s。小白发一句话，盯着「对方正在输入…」等近一分钟，以为坏了，退出重进。
**本质**：思考模式 LLM 生成慢 + 无流式 + relay 轮询串行化，三个因素叠加。流式输出是明确 YAGNI（部署说明「不用 WebSocket，10s 轮询够用」）——**取舍的代价**，但小白不关心原因，只感受到「卡」。
**执行建议**：最低成本先做「假进度」（轮次心跳：检索→分析→回复的流水线阶段进度条，pipeline 日志已有阶段信息可回传）；中期评估 SSE 流式（DeepSeek 支持 streaming，无需 WebSocket）。

### 4. 无忘记密码（服务器版）
**现象**：auth 只有 mail-send/register/login/logout，没有 reset。密码忘了 = 邮箱已注册（email UNIQUE）无法重注册 = 账号永久报废，只能找管理员手工处理。
**执行建议**：复用已有邮件验证码通道，加 `/auth/reset-password`（验证码校验后重置）。工程量小、收益大。

### 5. 卸载即清空，无导出（安卓 × 服务器版换机）
**现象**：安卓数据在 App 私有目录，卸载=对话/记忆/手账全部消失（readme 有提示，小白不会读）。换手机/误删=角色记忆清零。服务器版数据在账号（换设备登录可恢复，这是优点），但**换浏览器/清缓存**后 Key 丢、资产重下（数据本身按 user_id 在服务器，可恢复）。
**执行建议**：安卓加「导出/导入」：一个按钮把 user_data 打包 zip 到下载目录（或分享）；引导文案放在「清除历史」旁。服务器版在设置页提示「换浏览器请重新登录并填 Key，聊天记录在服务器」。

## 四、P1/P2 缺陷要点

### 6. 注册四门槛（服务器版）
QQ邮箱 + 邮箱验证码 + **QQ 群号**（label 写「下载 APP 可见，无需进群」——小白不知道去哪找这个号）+ 一安装一号。防滥用设计没错，但文案和流程是「猜谜」。**建议**：群号直接预填在输入框（服务端校验），或写明「群号：1097936258 显示在下载页」。

### 7. OPPO/ColorOS 后台冻结
系统级冻结无法程序化解（已实测确认），现有弹窗引导用户去「应用启动管理」——小白点「暂不」后**没有第二次提醒**，后台主动消息静默失效，用户以为功能坏了。**建议**：检测到后台主动长期未触发时，APP 内温和提示一次「上次后台消息未送达，可能被系统限制」。

### 8/9. 明文 HTTP + 单点服务器
8787 裸 IP 无 HTTPS、无域名；服务器关机=全员断线，user_data 在单机上无异地备份。**建议**：上 HTTPS（config.js + manifest 三处已有改动预案）、服务器定时快照备份（云备份权益已开通）。

### 10. 错误不可诊断
所有 LLM 错误统一「嗯…信号不太好」。小白分不清是「Key 填错/欠费/断网」。**建议**：后端把 ApiError 分类（401=Key 无效、402=余额不足、超时=网络）映射成三句人话，前端 toast 展示。

### 11. 「AI」身份标识
通知标题只有「流萤」，凌晨收到一条「流萤」消息，小白可能被吓到。**建议**：通知文案带「（AI 角色扮演）」或 APP 内首次启动声明「这是 AI，不是真人」。这也是合规友好做法。

### 12. 设置面板名词轰炸
「主动式/概率式/隐藏式」「effort：none/high」「检索器温度」直接暴露。小白全默认即可，但看到一堆滑条会焦虑。**建议**：折叠「高级设置」默认收起；主动性改自然语言描述（「让流萤偶尔主动找你说话：经常/偶尔/从不」）。

### 13. 32 位不支持
Chaquopy Python 3.12 无 32 位产物，属工程硬约束（取舍）。**能做的**：下载页/安装包描述里前置声明「仅支持 64 位设备」，避免装不上后差评。

### 14. 费用不透明
花钱在暗处（Key 是用户的，费用用户自付）。聊天页无任何费用感知。**建议**：设置页加「本月大概花了 X 元」（后端已有 token/cost 统计，聚合展示即可）。

### 15. 版本漂移（工程债）
server/version.json 是 0.7.1 而 APP 是 0.7.2 → 服务器版检查更新永远显示「已是最新」。前端三副本（app/static、server/frontend、android_server/assets）靠人工同步，check_version.py 只查本地版。**建议**：check_version.py 扩大覆盖三副本 + version.json；发布流程加一步「同步三份 app.js 后跑校验」。

### 16/17/18/19. 小缺陷
键盘 bug（微信输入法）与图标白方块已记录暂缓；PC 多开强杀对小白不可见但可能丢未保存状态（建议弹「已有实例在运行」并激活旧窗口）；安卓首次启动建议加个启动画面（品牌图 2-3 秒）。

## 六、需要用户拍板的产品决策（先讨论再动手）

1. **API Key 门槛**：是否接受「用户自带 Key」为长期形态？（选项：保留现状+做好引导 / 服务器版主打托管 API / 其他）
2. **流式输出**：是否打破「不做 WebSocket/流式」的 YAGNI 决定，先做阶段进度还是直接上 SSE 流式？
3. **数据导出**：导出格式（zip 原样 / 可读文本 / 两者）与存放位置（下载目录 / 分享面板）。
4. **服务器版注册门槛**：群号预填会降低门槛，是否接受（防滥用与易用性平衡）？
5. **桌面端形态**：黑窗口改造为「隐藏+托盘」是否接受（无 UI 改动，纯进程形态）。

## 七、结论一句话

三版本的核心体验是完整的（能聊、能记忆、有主动消息、有表情包），**最大的小白流失点不在功能而在「入门三连」：申请 Key、黑窗口、注册门槛**；其次是「离开三连」：卸载丢数据、忘记密码锁死、服务器停摆。设计缺陷集中在信息引导与流程门槛，工程缺陷集中在进程形态、性能体验与发布链路——都列在第五节可直接开工的清单里。

# 邮件链路排障（2026-10-01，用户报「收不到验证码」后补）

> 本文原为 [部署说明](部署说明.md) §九 的一节，因该文档超 200 行（CLAUDE.md 的文档拆分铁律）独立成文。
> 相关实现：`server/mail.py`（发信日志 + CLI 自检入口）、`server/auth_endpoints.py`（重置发码分支日志）。

**症状**：点「忘记密码 → 发送验证码」，界面显示"已发送"，但邮箱里没有信。

**第一步永远是自检**（在服务器上跑，一条命令）：

```bash
# 收件人请用**另一个** QQ 邮箱，不要填发信账号自己
sudo python3 /opt/firefly/server/mail.py you@qq.com
```

- 退出码：`0` 已发出 / `2` 配置或参数问题（未发信）/ `3` 发送失败；
- 凭据只在 systemd 单元里，脚本会**自动**从 `firefly-server.service` 的 `Environment=` 取；
- **没有新增任何 HTTP 端点**，自检只能在这台机器上跑（不会被当成公网发信机）。

**第二步看日志**（发信结果现在都会留痕）：

```bash
journalctl -u firefly-server -n 200 | grep -E "\[MAIL\]|\[AUTH\]"
```

**四个已知原因（按实际概率排序）**：

| # | 现象（日志） | 原因与处理 |
|---|---|---|
| 1 | `[MAIL] 收件人 == 发信账号（自己发给自己）` | **本次报障的真正原因**：`FIREFLY_SMTP_USER` 就是收件人。QQ 邮箱**不把这类信投进收件箱**（通常进「已发送」或直接丢弃）⇒ 用**另一个** QQ 邮箱收信（手机上登录该邮箱也能看），或让别的用户注册一体验证 |
| 2 | `[AUTH] reset-send 未注册邮箱 → 按防枚举返回 ok=true 且**未发信**` | 该邮箱**根本没注册**。`/auth/reset-send` 为防枚举**恒回 `{ok:true}`** 且**不发信**，所以界面显示"已发送"是设计如此。先确认账号确实注册过 |
| 3 | `[MAIL] 未发送：同邮箱 60s 重发间隔内` / `未发送：该 IP 本小时发信已达上限` | 被限流，同样不发信。等 1 分钟 / 1 小时再试 |
| 4 | `[MAIL] 发送失败 … smtp_code=535` | 授权码过期或含空格。去 QQ 邮箱「设置 → 账户 → IMAP/SMTP 服务」重新生成**授权码**（不是登录密码），改 systemd `Environment=` 后 `daemon-reload && restart` |
| — | `[MAIL] SMTP 已接收 …（服务器已收；是否进收件箱由收件方决定）` | **只证明服务器发出去了**，不证明对方收件箱有信 ⇒ 回上表第 1/4 条继续查 |

**日志纪律**（`server/mail.py`）：收件人一律打码（`a***@qq.com`）、只记异常类型与 QQ 返回码，
**授权码永不落日志**（异常文本里回显了也会被 `scrub_text()` 换成 `***`）：

```
mail: [MAIL] 收件人 == 发信账号（自己发给自己）：QQ 邮箱一般不投进收件箱，排查请换一个收件人 addr=1***@qq.com
mail: [MAIL] SMTP 已接收 to=1***@qq.com from=1***@qq.com subject=流萤 · SMTP 连通测试（服务器已收；是否进收件箱由收件方决定）
mail: [MAIL] 发送失败 to=s***@qq.com 异常=SMTPAuthenticationError smtp_code=535 原因=b'Login Fail…'
auth_endpoints: [AUTH] reset-send 未注册邮箱 → 按防枚举返回 ok=true 且**未发信** email=n***@qq.com ip=…
```

**部署这次改动**（两个文件，自检入口就在 `mail.py` 里，**不需要额外脚本**）：

```bash
scp server/mail.py server/auth_endpoints.py root@<IP>:/opt/firefly/server/
ssh root@<IP> 'systemctl restart firefly-server'   # 日志改动需要重启；自检本身不依赖重启
```

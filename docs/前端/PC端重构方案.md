# PC 端重构方案

> 状态：待评审（2026-08-17）。本文只出方案，不含代码改动。
> 关联：[安卓端UI优化方案](安卓端UI优化方案.md)（共用 §4 模块化拆分这一前置工作）。

## 1. 背景与问题

**现状**：PC 与安卓共用同一套移动优先布局。唯一的桌面断点在
`app/static/style.css:877-896`：`@media (min-width:720px)` 把 `#app`、`#home-view`、
`#menu-drawer` 限宽 520px 居中、加阴影——**PC 上就是放大的手机竖屏**。

具体问题：

- 宽屏（≥1280px）下两侧大面积浪费，聊天列却偏窄，长消息阅读体验差。
- 信息架构是手机式的：首页/聊天/纠错为全屏覆盖层切换（`showHome/showChat`，app.js:1605/1615），
  设置、反馈、公告、菜单抽屉为全屏浮层——PC 上开任何面板都丢失聊天上下文。
- JS 侧无任何布局响应逻辑（无 matchMedia/resize 分支），适配全堆在 CSS 里，无法表达"双栏"这种结构性差异。
- 项目气质不符：流萤是沉浸式角色陪伴应用，PC 端应接近"桌面 IM + 陪伴感"，而非网页版手机 App。

## 2. 目标布局：IM 双栏

### 2.1 线框（≥1100px）

```
┌──────────────────────────────────────────────────────────────┐
│ 左栏 280~320px          │ 右栏（弹性，聊天列限宽 ~760px 居中） │
├─────────────────────────┼────────────────────────────────────┤
│  [流萤头像] 流萤         │  头部：模式标签 / 签名 / 次要操作    │
│  剧情模式 · 签名…        │────────────────────────────────────│
│ ─────────────────────  │                                    │
│  💬 聊天（默认选中）     │         消息流（气泡/贴纸/旁白）    │
│  📖 设定文件            │                                    │
│  😊 表情包              │                                    │
│  ⭐ 收藏                │                                    │
│  🧠 记忆 / 日志         │                                    │
│  🛠 指出问题（纠错）     │                                    │
│                         │────────────────────────────────────│
│  （原首页轮播/公告       │  引用条（有引用时显示）              │
│   内容降级为左栏卡片     │  输入区 + 表情 + 发送                │
│   或右栏视图）          │                                    │
│ ─────────────────────  │                                    │
│  ⚙ 设置   🌗 主题       │                                    │
└─────────────────────────┴────────────────────────────────────┘
```

### 2.2 视图归位规则

| 现状（手机式） | PC 双栏归位 |
|---|---|
| 首页 `#home-view` 全屏覆盖层（轮播/公告/纠错卡片） | 不再是独立"页"：轮播+公告收纳为左栏上部卡片或右栏欢迎视图；进应用默认直接进聊天 |
| 纠错 `#fix-view` 全屏页 | 右栏内视图（左栏导航"指出问题"切换） |
| 设置 `#settings-panel` 全屏浮层 | 右栏内视图（分组手风琴保留） |
| 菜单抽屉 `#menu-drawer`（设定/表情包/状态/收藏/日志/pipeline 6 tab） | 拆散为左栏导航项，各 tab 成为右栏视图 |
| 反馈/公告浮层 | 右栏内视图或居中模态（PC 模态可接受，面积小） |
| 表情包面板/长按菜单/引用条 | 维持原位（本就局部组件） |

### 2.3 断点策略

| 宽度 | 布局 |
|---|---|
| <720px | 维持现有移动布局，**一行不改**（安卓/WebView 走这里） |
| 720~1100px | 过渡：单栏但内容限宽放宽（聊天列 640px），浮层改居中模态 |
| ≥1100px | 完整双栏（§2.1） |

实现方式：双栏结构只由桌面断点的 CSS + 桌面专属 DOM 容器承担；移动端 DOM 不变，
避免一份 DOM 两种形态互相污染（详见 §4 拆分与 §5 分期）。

## 3. 技术路线：轻量框架

### 3.1 选型对比（均免构建、单文件引入）

| | petite-vue | Alpine.js |
|---|---|---|
| 体积 | ~6KB | ~15KB |
| 模型 | Vue 子集（`v-if/v-for/{{}}`），渐进增强现有 DOM | HTML 属性指令（`x-data/x-show`） |
| 与现状契合 | 适合把"列表渲染 + 面板显隐"声明式化 | 适合纯显隐交互，列表渲染弱 |
| 兼容风险 | 依赖 Proxy（Chrome 49+）；旧 WebView 需实测 | 同样 Proxy 依赖 |

**推荐 petite-vue**：后续双栏视图的"导航切换 + 列表渲染"更重，petite-vue 的表达能力更合适；
且语法即 Vue 子集，未来若要上构建链可平滑迁移。

- 引入位置：`app/static/vendor/petite-vue.iife.js`，按依赖铁律在文件头注释标注
  **名称 petite-vue / 版本（实施时锁定）/ 相对路径 vendor/petite-vue.iife.js**。
- 基线确认（实施前必做）：minSdk 26 的历史约束源于旧 WebView；petite-vue 需 Proxy + ES2015，
  需真机（用户的手机即测试机）实测 WebView 版本，不达标则框架只用于 PC 断点分支，移动端保持原生。

### 3.2 框架接管范围（渐进，不一刀切）

- 第一批（P1）：左栏导航与视图切换、收藏/日志/表情包等列表渲染。
- 暂不接管：消息流打字机渲染（`renderMessages` app.js:1128 逐条动画与响应式更新易冲突）、
  粒子背景、引导层——保持命令式代码。

## 4. 前置：app.js 模块化拆分

3138 行全局脚本不拆分，双栏改造会变成在全局变量上叠床架屋。按现有 `// ═══` 分节拆为 ES Module：

| 新模块 | 收纳内容（现状位置） |
|---|---|
| `js/state.js` | 全部顶层状态（SESSION_ID、CURRENT_MODE、waiting、渲染/长按/纠错标志位等） |
| `js/api.js` | fetch 封装与全部端点调用（含 app.js:30-61 的鉴权头注入，**去 monkey-patch**，改为显式 `apiFetch`） |
| `js/chat.js` | 消息渲染/打字机/发送/历史分页（857-1160、2030-2400 一带） |
| `js/panels.js` | 设置/反馈/公告/抽屉/表情面板统一显隐管理（替代各自手写的 open/close） |
| `js/fix.js` | 纠错视图（1167-1532） |
| `js/guide.js` | 使用引导（2862-3060） |
| `js/relay.js` | 服务器版 relay 引擎（1862-2100） |
| `js/main.js` | 启动编排，合并 DOMContentLoaded 与文件尾部两套启动路径（1779、3135） |

拆分纪律：

- `window.xxx =` 25+ 处是为 HTML 内联 `onclick` 服务的；拆模块同步把内联 onclick 改为
  addEventListener，消灭 window 挂载（petite-vue 接管后自然消亡）。
- 顺手清理（小步、单独提交）：重复 toast（1673 vs 2062）、重复 escapeHtml（1170 vs 2519）、
  index.html:858-859 config.js 重复引入、renderMessages 的二次包装（2029-2033）改为直接改写原函数。
- 保留安卓 8.0 语法基线（不用 `??`/`?.`），直至 §3.1 的基线确认后统一放宽。

## 5. 分期里程碑

| 期 | 内容 | 验收 |
|---|---|---|
| P0 | app.js 拆模块（§4），**UI 零变化** | PC/安卓/服务器三端功能回归；`sync_frontends.py --check` 通过 |
| P1 | petite-vue 引入 + ≥1100px 双栏布局 + 导航/列表接管 | PC 宽屏实测双栏；安卓 adb 截图确认移动布局零变化 |
| P2 | 设置/纠错/首页内容桌面化归位（§2.2）+ 720~1100 过渡断点 | 各宽度档实测；引导层在双栏下位置正确 |

每期独立提交，P0 不过不得进 P1（拆分本身就是风险隔离）。

## 6. 风险清单

| 风险 | 缓解 |
|---|---|
| 三副本漂移（改了 app/static 忘了同步） | 每期验收强制跑 `sync_frontends.py --check` + `check_version.py` |
| 旧 WebView 不兼容 petite-vue/新语法 | 基线确认先行；不达标则框架只上 PC 分支，移动端纯原生 |
| 打字机渲染与响应式冲突 | 消息流不接管（§3.2），P1 专门回归"流萤连续多条消息"场景 |
| 双栏下引导层/长按菜单定位错乱 | 这两处按视口坐标定位（1004、3054），P2 逐项实测 |
| 服务器版差异（relay/登录）在双栏下遗漏 | P1 起每期在服务器模式也跑一遍回归 |

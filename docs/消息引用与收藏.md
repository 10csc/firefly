# 消息引用与收藏（长按消息菜单）

> 功能：聊天页长按任意消息（触屏按住 ~0.5s / PC 按住或右键），在消息上方或下方弹出 QQ 式菜单：
> 「📎 引用」「⭐ 收藏」。2026-08-17 实施。
> 前端唯一源：`app/static/`（index.html / style.css / app.js），改后跑 `python tools/sync_frontends.py`。

## 一、交互

- **长按**：`#messages .msg-row` 上 pointerdown 按住 500ms 弹出菜单；移动超 8px（滚动/滑动）取消；
  松开/取消即取消；PC 右键（contextmenu）同样弹菜单。头像区域除外（留给开拓者形象切换）。
- **菜单唯一性**：`_showMsgMenu()` 先 `_closeMsgMenu()` 再建新菜单，`_msgMenu` 登记当前菜单；
  点击菜单外/滚动消息区即关闭。**曾漏掉 `_msgMenu = menu` 赋值导致旧菜单清不掉、多个菜单叠加（PC 复现），已修并有自动化断言**。
- **引用**：点「引用」→ 输入框上方出现引用条（谁 + 内容，可 ✕ 取消）→ 发送文字或表情包时，
  `quote` 快照随消息提交；发出的消息气泡上方渲染引用小卡片（`.quote-preview`）；刷新后从历史记录还原。
- **收藏**：点「收藏」→ POST /favorite 存消息快照 → toast 提示；☰ 菜单「收藏」页签查看/删除。

## 二、数据格式

引用快照（写进 conversation.jsonl 的用户消息 `quote` 字段，仅白名单字段 + 长度截断 2000）：

```json
{"who": "firefly", "type": "text", "content": "被引用的内容", "seq": 42}
{"who": "user", "type": "sticker", "label": "比心", "path": "stickers/x.webp"}
{"who": "firefly", "type": "narration", "text": "旁白文字", "style": "action"}
```

LLM 侧合成文本（`compose_user_text`）：`[引用流萤：「内容」]\n新消息`；重启回灌
（`hydrate_context`）同样带引用前缀，保证流萤看得懂「引用+新话」的结构。原消息内容保持干净，
`quote` 独立字段，前端/历史渲染互不干扰。

## 三、收藏存储

- 模块：`app/modules/favorite_store.py`；文件：`{mode}/data/favorites.json`（随模式目录自动
  按用户隔离：服务器版落 `user_data/{uid}/`；随导出/账号同步 zip 自动打包，无需额外代码）。
- 快照自包含（who/type/content…+time+id），与对话历史解耦——清空历史、撤回都不影响收藏。
- 去重：带 seq 的按 seq 唯一（重复收藏 = 更新时间）；无 seq（本地即时渲染的消息）生成 `f<毫秒>` id。
- 上限 300 条，超出丢最旧；内容上限 2000 字符；非法来源/类型直接拒绝（FavoriteError）。
- 接口：`POST /favorite`（{mode, message}）、`GET /favorites?mode=`（最新在前）、
  `POST /favorites/delete`（{mode, id}）。注册在 routes.py 的 POST/GET_ROUTES——
  服务器版 server_app 直接复用（需登录），本地版无鉴权。

## 五、安卓注意（用户侧跟进）

- 前端已通过 `user-select:none` 抑制消息区文本选择，避免长按触发系统文本选择；
  若 WebView 仍弹原生菜单（长按图片"保存图片"等），需在 MainActivity 加
  `webView.setOnLongClickListener { true }` 拦截——安卓侧问题由用户自行验证处理。

## 六、已知边界

- 本地即时渲染的用户消息行没有 dataset.seq（/chat 未回传 seq），收藏用快照 + f 前缀 id，
  不影响功能；如需按 seq 去重可后续让 /chat 回传 user seqs。
- 服务器版生产部署需 scp 更新 `app/`（routes/conversation_store/favorite_store）+ `server/frontend/`，
  按 `docs/服务器管理规范.md` 流程执行（未部署）。

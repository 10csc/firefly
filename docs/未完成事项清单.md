# 未完成事项清单

> **这是什么**：本项目的**唯一待办真相源**。所有审计/审查/排查发现的问题，结论都汇总到这里；**做完一条就删掉一条**。
> **为什么要有它**：此前审计结论散在 5+ 份报告里，每份只讲"发现了什么"，没有一份讲"现在还剩什么没做"。结果同一个问题被反复审出来：**明文传输被发现 ≥4 次、部署债 ≥5 次、安装包未重建 ≥3 次**。这份清单存在的唯一目的就是终结这个循环。
>
> **维护规则（硬性）**
> 1. 新发现 → 追加一行；**不许只写进审计报告而不进本清单**。
> 2. 做完 → 直接删行（不标"已完成"，避免清单变成历史堆）。
> 3. 每条必须写清 **依据**（哪份报告的哪一节）和 **验收标准**（怎么算做完）。
> 4. 每条都要记 **首次发现** 与 **复发次数**——复发次数是给"为什么又没做"留的证据。
> 5. 审计**过程记录**写完就归档（移到 `封装（没指定就不读）/`），不在 `docs/` 长期堆着。
>
> 最近更新：2026-10-02（PC 端交接整改：P5 收窄到"剩余项"、删 P5-4；新增 P5-5/P5-6 安装器残留与 `[Run]` 静默未确定）

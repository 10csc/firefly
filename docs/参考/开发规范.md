# 开发规范

本页约束日常实现。协议字段见对应参考页；操作步骤见 [本地开发与构建](../操作/本地开发与构建.md)；
发布权限见 [发布规则](发布规则.md)。

## 工作方式

1. 先读需求、当前状态、待办和错误总结，再检查目标代码与调用点。
2. 一次只处理一个可验证目标；不顺手重构，不扩大文件范围。
3. 不凭记忆写 API、字段或路径；使用源码、官方文档和实际命令确认。
4. 同一问题两次试探仍无进展时停止扩散，汇报现象、已排除项和所需决定。
5. 未获授权不 bump 版本、不提交、不推送、不部署、不发布热更新。
6. 文档与代码同批更新；完成项立即从未完成清单删除。

## 模块边界

每个业务模块遵循固定过程：

```text
接收输入
  → 校验类型、边界、权限和资源
  → 处理
  → 校验输出结构和业务约束
  → 返回结果或可定位错误
```

审查失败直接拒绝并记录，不能把非法输入送进模型或磁盘；输出验证失败必须返回明确错误标记，
不能只捕获异常后继续打印成功。

## 对话流水线

主流程保持：

```text
用户输入
  → retriever
  → analyzer
  → polisher
  → organizer
  → 历史与观测
```

前三段的顺序、输入输出结构和提示词注入位置未经明确批准不得改变。新工具从组织器接入，
不在主流程中插入新的同步阶段。完整扩展合同见 [开发与扩展协议](开发与扩展协议.md)。

## 工具扩展

- 新工具必须通过注册表暴露，不能由组织器直接 import 具体实现。
- 工具结果必须同时具备渲染记录、持久化记录和上下文摘要。
- 单条工具失败只丢弃该结果，不阻断文本回复。
- 大二进制外置到用户目录，历史 JSONL 只存相对路径和摘要。
- 新增 LLM 或云 API 调用前说明模型、预算、隐私和失败降级，并取得批准。
- 未知消息类型在前端必须安全降级，禁止抛异常或白屏。

## 模型选择

- 默认使用 DeepSeek Flash；简单分类可使用 Non-think，复杂规划和高风险排查才提高思考档位。
- 所有调用经过现有 LLM 基础设施，统一做 JSON 校验、token/费用记录和错误归因。
- 思考模式下采样参数可能不生效，不能把“传了 temperature”当成已经控制输出。

## 测试标准

新测试至少有一个独立 oracle：固定期望、真实 HTTP 响应、干净底座重建、另一进程导入或
可执行不变量。以下不算有效验证：

- 用被测实现计算期望值，再断言它等于自己。
- 只搜索函数名或字符串存在。
- 只跑 happy path。
- 捕获异常后继续 PASS。
- 环境缺失自动跳过且没有说明。
- 把会随产品正常演进而变化的数字写成快照。

旧测试已归档，不能直接恢复为默认回归。新测试按风险建立最小真实链路，当前入口见
[测试基线](测试基线.md)。

## 数据与安全

- 所有用户数据写入 `user_data/` 的账号和角色模式隔离路径。
- 不提交密钥、token、真实用户数据、数据库、备份和私钥。
- 敏感值不进入日志、聊天、文档、提交信息或诊断包。
- 删除、恢复、迁移和多文件写入必须有原子性、可恢复路径或明确冲突提示。
- 服务器只提供 API、登录和角色卡平台，不暴露 App 前端。

## 验证与交付

每次交付至少说明：

1. 改了什么，影响哪些用户路径。
2. 运行了哪些测试或门禁，结果和覆盖范围。
3. 哪些风险未覆盖，为什么不能在本轮覆盖。
4. 是否涉及版本、部署、数据迁移或热更新。

不能只说“测试全绿”；必须说明测试验证了什么、没有验证什么。

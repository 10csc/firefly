# 角色包格式

角色包的唯一入口是 `preset.json`。运行框架从包声明中发现角色、知识、提示词覆盖和演出形态。

## 目录

```text
app/assets/character/{preset_id}/
├── preset.json
├── core.md
├── identity.md
├── sms_samples.md
├── 用户设定.md
├── opening.json              # 可选
├── knowledge/                # 可选，一层分组
├── stickers/                 # 可选
├── prompts/                  # 可选，提示词覆盖
└── assets/                   # 头像、封面、用户形象等
```

`preset.json` 至少声明 `id`、`name`、`char_name`、`user_name`、`presentation`；缺省字段由框架补默认值。`presentation` 支持：

- `sticker`：短信 + 表情包。
- `narration`：短信 + 旁白。
- `none`：纯文本。

## 写入规则

- 内置包是只读模板；用户修改写 `user_data/{mode}/character/` 副本。
- 删除用户副本恢复默认，不修改内置资产。
- 包 id 必须使用统一安全正则；目录解析必须经过 `cfg.pack_root(pid)`。
- `data/`、`journal/`、`images/` 是用户数据，不属于角色卡发布物。
- 文本文件禁止路径穿越、隐藏文件和控制字符。
- 知识库允许一层分组；分组名和文件名分别校验，单段上限 40 字。

## 图片与平台限制

| 用途 | 目标 | 上限 |
|---|---|---|
| 广场列表缩略图 | 长边 ≤320px | 12KB |
| 头像 | ≤256px | 30KB |
| 详情图 | ≤1024px | 300KB |
| 表情包 | ≤160px | 20KB |

服务器卡另外受文件数、文本总量、整卡体积和标签数量限制。前后端上线前必须对齐同一套常量，不能只信任客户端声明的尺寸。

## 安装

同 id 覆盖安装先备份旧包，再原子换入；失败恢复旧包。卸载删除卡与包专属资源，不触碰对话、记忆和手账。服务器模式下还要检查账号隔离和张数/体积配额。

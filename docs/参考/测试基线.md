# 测试基线

当前只承认一套面向真实故障的测试。旧模块单测、手工探针和历史报告已归档，不再作为发布或“已修复”的证据。

## 为什么替换旧测试

旧测试覆盖了大量实现细节，却经常出现三类问题：

- 用被测实现自己计算期望值，故障来了仍然通过。
- 依赖旧文件名、旧路由或测试专用桩，代码已经变化，测试仍在证明过去。
- 单测全绿但真实 HTTP、进程重启、并发、发布包或客户端消费链路失败。

因此旧测试不是“基线”，只是历史资料。保留旧结果会让虚假通过和虚假失败同时存在。

## 运行

Windows PowerShell：

```powershell
$env:PYTHONUTF8 = "1"
python -B tests\test_sync_http_e2e.py
python -B tests\test_sync_concurrency.py
python -B tests\test_sync_crash_recovery.py
python -B tests\test_sync_spec_guard.py
python -B tests\test_hot5_release_pipeline.py
python -B tests\test_deploy_rollback.py
python -B tests\test_review_bugfixes.py
python tools\check_docs_execution.py
python tools\check_docs_execution.py --self-test
```

`test_hot5_release_pipeline.py` 验证既有 hot5 发布物，前提是
`hotupdate_dist/prod/0.9.1/` 中的候选包与当前源码一致；它不能证明当前 T1/T2 源码已发布。
`test_deploy_rollback.py` 只读写临时沙箱，不访问生产。文档检查器的 `--self-test`
用固定反例证明它会失败，不把“空扫返回 0”当通过。任何一份非零退出都算失败，
不能只看末尾单个 PASS。

这些文件是独立自校验程序，不是 pytest 用例。`pytest` 即使显示 `no tests collected`，
也只表示没有使用正确入口，不能据此判断通过或失败；验收必须按上面的命令逐份运行。
仓库根目录的 `pytest.ini` 只用于阻止 pytest 误入归档目录。

## 新测试的设计门槛

新代码的测试必须至少包含一项独立 oracle：固定期望、真实 HTTP 响应、干净底座重建、另一进程导入或可执行不变量。以下写法不作为有效验证：

- 被测函数产出期望值再拿它断言自己。
- 只搜索函数名存在。
- 只跑 happy path。
- 捕获异常后继续打印 PASS。
- 把环境缺失自动当成跳过而不说明。

未来新增业务测试应按风险建立最小真实链路。发布链、同步、恢复、权限、签名和迁移不能只靠 mock 单元测试。

# 构建规范（依赖位置与打包 v1）

> 目的：把「依赖在哪、怎么构建」一次写死，避免每个新会话重新探测环境。
> 何时读：本地运行/测试/构建 PC/APK/安装器/推 tag/release 前，先读本文件。
> 配套：`docs/开发规范.md`（开发流程）、`docs/部署与发布约定.md`（发版/推送）、`docs/版本更新规范.md`（发版步骤）。
> 已核实日期：2026-08-16（本机环境 + 仓库实际文件 + 生产服务器只读检查）。

## 0. 总原则

1. **不删构建缓存**：`android/sdk`、`.gradle`、`build`、`dist` 等一律保留（删了构建全量重跑）。
2. **版本号权威**：以 `tools/check_version.py` 的校验清单为准；未经明确发版指示不 bump。
3. **前端唯一源**：`app/static`；改动后必须 `python tools/sync_frontends.py`（`--check` 校验漂移）。
4. **Windows 编码**：跑 Python 前先设 `$env:PYTHONUTF8="1"; $env:PYTHONIOENCODING="utf-8"`（否则测试打印 ✓ 会 GBK 崩溃）。
5. **新依赖必须落进打包**：本地 `pip install` 成功 ≠ 完成，必须同步改 `firefly.spec`（datas/excludes）与 `android/app/build.gradle.kts`（Chaquopy `pip {}`），并在本文件登记。

## 2. 本地运行与测试

```powershell
# 运行（http://127.0.0.1:8765）
cd F:\CodeFile\firefly\app
$env:PYTHONUTF8="1"; $env:PYTHONIOENCODING="utf-8"
python server.py

# 全量单测（tests/test_*.py 全部；e2e_20turns / manual_10turns 按需单独跑）

$env:PYTHONUTF8="1"; $env:PYTHONIOENCODING="utf-8"
Get-ChildItem tests\test_*.py | ForEach-Object { python $_.FullName }
```

- 测试不依赖 pytest，每个文件是独立脚本；跑单个：`python tests/test_xxx.py`。
- **测试数量口径（2026-09-13 修正）**：以 `Get-ChildItem tests\test_*.py` 的**实际文件数**为准，实为 **36** 个；旧文档中"33/33 测试绿"是历史快照口径（当时确实 33 个），已过时，勿再引用。
- 涉及前端改动后加跑：`python tools/sync_frontends.py --check`（内含 bundle 生成校验）。
- 涉及后端（`app/`）改动后加跑：`python tools/check_backend_sync.py --check`（安卓内嵌后端副本 `android/.../python/backend/` 的一致性，R-03）。
- **发版前四门禁全跑**（2026-09-13 起，R-03 收尾）：
  ```powershell
  python tools/check_version.py               # 版本位置 + versionCode 递增
  python tools/sync_frontends.py --check      # 前端三副本 + bundle + 资产清单
  python tools/build_frontend_bundle.py --check
  python tools/check_backend_sync.py --check  # 后端副本一致
  ```
  四者全 PASS 才允许打包发版。<br>
  注：`check_version.py` 对**缺失文件**记 SKIP（干净 clone 也能跑），只在"文件在而版本号不一致"时 FAIL。

## 3. 构建 PC（PyInstaller + Inno Setup）

```powershell
cd F:\CodeFile\firefly
$env:PYTHONUTF8="1"
# 1. exe 目录产物
python -m PyInstaller firefly.spec --noconfirm
# 2. 发布前必清测试数据（含 API Key/对话，严禁混入发行）
Remove-Item -Recurse -Force dist\firefly\user_data -ErrorAction SilentlyContinue
# 3. 安装器
& 'C:\Program Files\Inno Setup 7\ISCC.exe' package\firefly.iss
```

- 产物：`dist\firefly\firefly.exe`（one-folder，console=False 无黑窗）、`package\firefly-setup.exe`。
- `firefly.spec` 的 `datas` 已含 static/config/assets/knowledge/database（**不含 `docs/`**——内部运维文档不分发给用户，2026-09-08 移除）；`excludes` 已排除 numpy/torch/PIL/onnxruntime + cryptography/bcrypt/zstandard/chardet（后四个 2026-09-08 加，代码零 import，实测省 ~12MB）——**新增重型本地模型（语音/识图）时必须回来改这个 excludes 和 datas**。
- 冒烟：启动 `dist\firefly\firefly.exe` → `GET http://127.0.0.1:8765/config` 200。
- 安装器 `CloseApplications` 已配置，覆盖安装保留 user_data（iss 的 `Excludes: "user_data"`）。

## 4. 构建 Android APK

```powershell
$env:JAVA_HOME = "D:\Java\jdk-21"
$env:ANDROID_HOME = "F:\CodeFile\firefly\android\sdk"
$env:PYTHONUTF8 = "1"
# 优先：直接用已缓存的 Gradle 发行版（wrapper jar 缺失时不卡）
$gradleBat = Get-ChildItem 'D:\Android\.gradle\wrapper\dists' -Recurse -Filter 'gradle.bat' | Select-Object -First 1 -ExpandProperty FullName
& $gradleBat -p F:\CodeFile\firefly\android assembleRelease --no-daemon
# 产物：android\app\build\outputs\apk\release\app-release.apk → 复制为 android\firefly.apk
Copy-Item F:\CodeFile\firefly\android\app\build\outputs\apk\release\app-release.apk F:\CodeFile\firefly\android\firefly.apk -Force
# 真机安装（覆盖升级保留数据）
& 'F:\Android_SDKset\platform-tools\adb.exe' -s 704c2441 install -r F:\CodeFile\firefly\android\firefly.apk
```

- `preBuild` 自动执行两个 Sync：`syncBackend`（app/knowledge/database → Chaquopy python 目录）+ `syncFrontendAssets`（app/static + 指定 assets + server/frontend 的 config.js/login.html）。
- debug 快速包：`.\android\build_apk.ps1`（自动装 SDK + `assembleDebug`，JAVA_HOME 已在脚本内写死）。
- keystore 存在时 release 自动签名；**不要开 minify**（会剪坏 Chaquopy 反射/JNI 调用，项目已注释说明）。
- 架构：arm64-v8a + x86_64（Python 3.12 只支持 64 位）；minSdk 26。

### 4.1 发版前必过的包内验收（2026-09-18 新增，硬性）

**背景**：曾有 3 周时间对外发放的是旧构建（包内没有 `sync.js`，且 `allowBackup` 仍是 `true`＝用户 API Key 会被安卓云备份带出设备），因为当时没有任何快速核验手段，全靠人装真机看。

上传安装包**之前**必须跑：

```powershell
# 1) 前端三处同步（漏跑 = 包里还是旧前端，本次事故的直接原因）
python tools/sync_frontends.py --check

# 2) 包内安全属性验收（退出码非 0 即不合格，禁止上传）
python tools/check_apk_manifest.py android/firefly.apk allowBackup usesCleartextTraffic
```

**验收基线**

| 属性 | 期望 | 理由 |
|---|---|---|
| `allowBackup` | `false` | `user_data` 含 API Key，禁止被云备份 / `adb backup` 带出设备 |
| `usesCleartextTraffic` | `true` | 服务器暂无 HTTPS（见 `docs/审计-服务器与开发版-2026-09-18.md` §2.1；将来上 TLS 后改 `false`） |
| 包内含 `assets/js/sync.js` | 必须有 | 缺它 = 包是旧构建 |

工具还会自动报告包内是否残留旧前端结构（`panels.js` 单文件时代），用于发现"改了源码但没重建包"。

## 7. 禁止事项

1. 删除 `android/sdk`、`android/.gradle`、`D:\Android\.gradle`、`build`、`dist` 缓存/产物（协作记忆 #4）。
2. 打印/提交 `keystore.properties`、`gitee_token.txt`、`_harden/admin_token.txt` 内容。
3. 发布 `dist\firefly` 前不清空 `user_data`。
4. 只在本地 `pip install` 新依赖而不改 `firefly.spec` / Chaquopy 配置（本地能跑、打包后缺模块）。
5. 未获发版指示时 bump 任何版本号或跑 release 流程。
6. 混用两个 adb（微信开发者工具版 vs `F:\Android_SDKset` 版）。

## 发版前必跑：APK 内前端一致性闸

```bash
python tools/check_apk_frontend.py            # 默认校验 android/firefly.apk
```

比对同一份前端文件在 **源 `app/static/` / APK `assets/` / APK `assets/chaquopy/app.imy` 内**
三处的 sha256，不一致即退出码 1（**不许发版**）。

为什么必须有这道闸：Gradle 增量构建的 `Sync` 产物可能不失效，导致"源是新的、包里是旧的"——
构建成功、门禁全绿、装机成功，唯一异常在包内。2026-09-20 因此把陈旧 APK 发到
Gitee+服务器并撤回（见 docs/错误总结.md #16）。
前端有改动时先 `cd android && gradlew.bat --no-daemon clean assembleRelease` 再跑闸。

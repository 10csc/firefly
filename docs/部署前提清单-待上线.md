Environment=FIREFLY_ENC_KEY=/opt/firefly/keys/session_priv.pem

### 6.3 systemd 环境变量

```ini
# firefly-downloads.service
Environment=FIREFLY_BW_KBPS=2800              # 流量调度总预算（0=关闭）
Environment=FIREFLY_BULK_IP_BYTES=1073741824  # 单 IP 大文件日配额
# TLS（先只加变量、证书到位再重启；**不加这些 = 完全维持现状**）
Environment=FIREFLY_TLS_PORT=443
Environment=FIREFLY_TLS_CERT=/opt/firefly-downloads/tls/fullchain.pem
Environment=FIREFLY_TLS_KEY=/opt/firefly-downloads/tls/privkey.pem
```

### 6.4 TLS 上线顺序（**每步可回滚**）

1. 阿里云安全组放行 **443**（用户已同意；80 可不放——用 TLS-ALPN-01 挑战）；
2. 先用 **LE staging** 在临时端口签发一次，确认能成功、能续期（**别直接上生产**）；
3. 正式签发（`acme.sh --issue -d <IP> --certificate-profile shortlived --alpn`），证书目录 600；
4. 加 6.3 的 TLS 变量并重启：**443 起 TLS，8787 明文照旧**（旧客户端零改动）；
5. `curl -s http://127.0.0.1:8787/download/tls` 应报 `enabled/loadable/not_after/days_left`；
   把它接进 `attack_watch.sh`：`days_left < 10` 即落 `attack_flag.json`；
6. 续期 cron 每日 `acme.sh --cron` + `--reloadcmd "systemctl restart firefly-downloads"`；
7. 客户端默认地址改 `https://101.200.14.126`（只对**官方主机**自动升级，自建服务器不改写）。

### 6.5 部署后验证（在 §四六项之外补这些）

1. `python tools/probe_live_server.py` 全绿（含新增的 `/plaza/*` 端点）；
2. **未登录** `curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:8787/plaza/api/list` → **401**；
3. 登录后广场列表/详情/下载各一次；下载一张卡 → 服务器端 `user_data/{uid}/{card_id}/character/preset.json` 真的出现；
4. `https://<IP>/download/stats` 200、`http://<IP>:8787/download/stats` 200（双端口并存）；
5. **抓包**（`tcpdump -i any -A port 443 | grep -i authorization`）确认登录与 sk 提交看不到明文；
6. `sar -n DEV 1 5` 交叉验证限速生效（出向不超过预算的 ~1.1 倍）。

### 6.6 回滚

- **TLS**：去掉 6.3 的四个 TLS 变量并重启 → 立刻回到纯明文（8787 从未停过）；
- **流量调度**：`FIREFLY_BW_KBPS=0` 关闭限速；
- **共创平台**：`/opt/firefly/plaza/` 整体移走即可（用户目录里的广场卡是独立副本，不影响聊天数据）；
- **代码**：按服务器管理规范 §172-190 用 `code_pre_<时间>.tar.gz` 留档回滚（`server/` 不进 git，禁用 checkout 代替）。

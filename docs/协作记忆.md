# 协作记忆

这里只保留会影响后续工作的长期偏好和协作方式。详细历史已归档，不再逐次堆叠。

## 用户偏好

- 先给结论和证据，不要空泛承诺或“AI 味”的治理话术。
- 问题要追根因；不要只修表象，也不要把旧测试全绿当作完成证明。
- 视觉设计要服从流萤这一核心用户群，但避免模板化“星铁风”；允许宇宙旅者通讯终端等更克制的方向。
- 前端或动画问题必须用真实浏览器、真实手机视口和截图验收；几何不相交不代表层叠、合成和 DPR 没有错位。
- 未经明确要求，不扩大修改范围，不留下临时文件，不碰用户数据和生产环境。

## 工程约束

- 默认用现有技术栈和标准库；新增依赖必须先说明理由。
- 本地版优先，服务器只提供后台 API 和角色卡平台，不对外提供 App 前端。
- 版本未获批准不 bump；发布、部署、热更新和公告都必须有明确证据与回滚路径。
- 文档写完立即销账；活动文档描述当前事实，历史移入归档。
- 错误总结保存真实事故，不经过“美化”后覆盖原貌。
- 测试只承认独立真实链路脚本；旧测试进归档，pytest 的 `no tests` 不作为通过或失败证据。

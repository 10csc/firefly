# 项目结构（四部分，高内聚低耦合）

> 定版原则：只做 3 个版本（本地安卓 / 本地 Windows / 服务器版 APP）+ 服务器后端。
> **服务器网页不提供使用通道**——`server/frontend/` 的页面是 APP 的 WebView 载体，不是给浏览器用户的入口。

## 一、四个部分（各司其职）

| # | 部分 | 目录 | 运行位置 | 依赖共享核心 | 是否入 git |
|---|------|------|---------|-------------|-----------|
| 1 | **本地安卓** | `android/` | 手机（Chaquopy 内嵌 Python 全本地） | `app/` + `knowledge/` + `database/`（syncBackend 打包） | ✅ 是 |
| 2 | **本地 Windows** | `app/` + `firefly.spec` + `package/` | PC（PyInstaller，全本地） | 自身即核心 + `knowledge/` + `database/` | ✅ 是 |
| 3 | **服务器版 APP** | `android_server/` | 手机（极薄 WebView 壳，0.6MB） | 无（连服务器，资产运行时本地化） | ✅ 是 |
| 4 | **服务器后端** | `server/` | 云服务器（101.200.14.126） | `app/modules` + `app/routes` + `orchestrator.py` + `knowledge/` + `database/` | ❌ **否（防泄露）** |

## 二、共享核心（在 git 中，供本地两端 + 服务器复用）

| 目录 | 内容 | 消费者 |
|------|------|--------|
| `app/modules/` | 流水线模块（analyzer/polisher/organizer/llm_retriever/memory/proactive/api_client...） | 本地Win / 本地安卓 / 服务器 |
| `app/routes.py` | 全部业务路由（含 relay 中转端点） | 本地Win / 本地安卓 / 服务器 |
| `app/orchestrator.py` | 对话流水线总调度 | 本地Win / 本地安卓 / 服务器 |
| `app/shared_http.py` | HTTP 响应工具/优雅关闭 | 本地Win / 服务器 |
| `app/static/` | 本地版前端（index.html/app.js/style.css/图片） | 本地Win / 本地安卓 |
| `knowledge/` `database/` | 知识库 + 原始资料 | 本地两端打包 / 服务器 |

## 三、各部分的职责边界

### 1. 本地安卓（android/）
- Kotlin 壳（MainActivity/KeepAliveService）+ Chaquopy 内嵌 Python 3.12 + WebView 加载 `127.0.0.1:8765`
- 全部核心在手机本地：流水线 / 知识库 / 数据 / Key
- 后台：前台服务 + WakeLock + 厂商引导（ColorOS 等）

### 2. 本地 Windows（app/ + package/）
- `app/server.py` 入口（127.0.0.1:8765，浏览器自动打开）
- PyInstaller 打包 `dist/firefly/` → Inno Setup 安装器 `package/firefly-setup.exe`
- 数据 `user_data/`（exe 同级）

### 3. 服务器版 APP（android_server/）
- 极薄 WebView 壳（0.6MB）：加载 `http://101.200.14.126:8787/login`
- **资产本地化**：知识库/设定/Key 存 WebView 数据目录（localStorage）
- **后端代理**：服务器构建 LLM 请求（占位符）→ APP 本地填充 → 用户 Key 直连 DeepSeek → 回传
- 后台主动消息：打开 APP 时轮询（推送通道为后续项）

### 4. 服务器后端（server/，不入 git）
- `server_app.py`（8765 主服务：认证中间件 + auth 端点 + 业务路由挂载）
- `auth.py` / `db.py`（scrypt 用户系统 + SQLite）
- `download_server.py`（8787 网关：下载分发 + 反代 + 限流）
- `frontend/`（login/app/chat/admin 页面 = **APP 的 WebView 载体**，非网页版）
- `attack_watch.sh`（攻击哨兵，每分钟留信号）
- 端口：8787 公网唯一入口 / 8765 本机业务 / 8766 本机管理（SSH 隧道）
- 部署：`/opt/firefly/`（systemd：firefly-server + firefly-downloads）

## 四、git 边界（防泄露）

```
入库：android/  android_server/  app/  knowledge/  database/  docs/  tools/  tests/  package/  firefly.spec
不入库：server/（.gitignore 已排除）— 服务器认证逻辑/前端页面/网关代码全部隔离
警告：git 历史中曾包含 server/（本地仓库）；若未来 push 远端，历史仍会携带，
      需要 push 前用 filter-repo 重写历史清除（当前铁律：不 push GitHub）
```

## 五、跨部分改动规范

| 改动类型 | 需要同步的位置 |
|---------|--------------|
| 流水线模块（app/modules） | 本地Win + 本地安卓（syncBackend 自动）+ 服务器（手动 scp）三端生效 |
| 业务路由（app/routes.py） | 同上三端 |
| 本地版前端（app/static） | 本地Win + 本地安卓（syncBackend 自动）双端 |
| 服务器前端（server/frontend） | 仅服务器（APP 通过 WebView 拉取，改完重启 firefly-server） |
| 服务器后端（server/） | 仅服务器（scp + systemctl restart） |

> 三端共享代码（app/）改动的部署顺序：本地测试 → scp 服务器 → 安卓构建（syncBackend 自动同步）

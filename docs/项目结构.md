# 项目结构（0.8.0：两个版本 + 服务器后端）

> 定版原则（0.8.0 起）：**两个版本**——安卓双模式 APP（默认完全本地，可开服务器后端）+ Windows 本地版；服务器后端为安卓服务器模式/网页提供账号与额度池。
> **一套前端**：`app/static/` 是唯一源（`window.FIREFLY_MODE` 分支本地/服务器），server/frontend 与安卓打包 assets 由 `tools/sync_frontends.py` 自动同步。

## 一、三个部分（各司其职）

| # | 部分 | 目录 | 运行位置 | 是否入 git |
|---|------|------|---------|-----------|
| 1 | **安卓双模式 APP** | `android/` | 手机（Chaquopy 内嵌 Python 引擎 + 打包前端） | ✅ 是 |
| 2 | **Windows 本地版** | `app/` + `firefly.spec` + `package/` | PC（PyInstaller，全本地；浏览器可另开服务器网页） | ✅ 是 |
| 3 | **服务器后端** | `server/` | 云服务器（101.200.14.126） | ❌ 否（防泄露） |

> 原 `android_server/`（0.6MB 壳）已并入 `android/`（0.8.0）——模式开关：设置 → 运行模式 → 重启切换。

## 二、安卓双模式（0.8.0 核心）

- **本地模式（默认）**：壳启动 Chaquopy 引擎 → WebView 加载 `http://127.0.0.1:8765/`（引擎 HTTP 提供统一前端）；数据在手机私有目录；Key 存后端 config.json；后台主动 = Python 直调 `backdoor_proactive_check`。
- **服务器模式**：壳不启动引擎 → WebView 加载 `file:///android_asset/index.html`；壳拦截 `config.js` 请求动态注入 `FIREFLY_MODE="server"` + `FIREFLY_SERVER_BASE`（assets/config.js 单点）；登录 Bearer + Key localStorage + relay 引擎 + 资产本地化（知识库/设定 localStorage 缓存）；后台主动 = 页面 `__serverProactive()`。
- **模式切换**：设置面板「运行模式」→ `FireflyMode.setMode` 桥 → SharedPreferences → finishAffinity + 杀进程重启。
- **统一前端分支点**（`app/static/app.js`）：fetch 包装（server 注入头/改写 URL）、登录模块、API 来源（own/proxy 托管额度池）、Key 存取、检查更新源、relay 引擎、导出方式（local=location.href+DownloadListener；server=fetch blob）、数据备份（导出/导入/账号备份/账号恢复）。

## 三、共享核心（git 中，两端 + 服务器复用）

| 目录 | 内容 | 消费者 |
|------|------|--------|
| `app/modules/` | 流水线模块 | 安卓本地模式 / Windows / 服务器 |
| `app/routes.py` | 全部业务路由（含 relay、数据导入/账号备份端点） | 同上三端 |
| `app/orchestrator.py` | 对话流水线总调度 | 同上 |
| `app/shared_http.py` | HTTP 响应工具/CORS | Windows / 服务器 |
| `app/static/` | **统一前端唯一源**（index.html/app.js/style.css/图片） | 三端（安卓经构建同步、服务器网页经 sync_frontends.py） |
| `knowledge/` `database/` | 知识库 + 原始资料 | 安卓打包 / 服务器 |

## 四、前端同步（0.8.0 消灭三份漂移）

- 唯一源：`app/static/{index.html, app.js, style.css, 图片}` + `app/static/config.js`（local 模式）。
- 同步目标：① `server/frontend/`（服务器网页调试副本；其 config.js=服务器地址单点、login.html/admin.html 为 server 独有）② `android/app/src/main/assets/`（打包资产：static 全量 + app/assets 9 件 UI 文件 + server 版 config.js/login.html）。
- 工具：`python tools/sync_frontends.py`（同步）/ `--check`（校验漂移，发版 CI 用）；gradle `syncFrontendAssets` 任务构建时自动同步；`check_version.py` 已覆盖 server 副本版本。
- 规则：**改前端只改 app/static**，改完跑 sync_frontends.py。

## 五、服务器后端（server/，不入 git）

- `server_app.py`（8765 主服务：认证 + 业务挂载 + 托管额度池检查）/ `auth.py` / `db.py`（users/sessions/proxy_usage）/ `mail.py` / `download_server.py`（8787 网关）/ `frontend/`（同步副本 + login/admin）/ `attack_watch.sh`
- 端口：8787 公网唯一入口 / 8765 本机业务 / 8766 本机管理（SSH 隧道）
- 数据同步端点：`POST /import-data`（zip 覆盖导入，自动备份）、`POST /sync/upload`（账号云端备份，留 3 份）、`GET /sync/download`（取回最新备份）——导出复用 `GET /export-data`

## 六、git 边界（防泄露）

```
入库：android/  app/  knowledge/  database/  docs/  tools/  tests/  package/  firefly.spec
不入库：server/（.gitignore 已排除）— 服务器认证逻辑/前端页面/网关代码全部隔离
警告：git 历史中曾包含 server/ 与 android_server/（本地仓库）；若未来 push 远端，历史仍会携带，
      需要 push 前用 filter-repo 重写历史清除（当前铁律：不 push GitHub）
```

## 七、跨部分改动规范

| 改动类型 | 需要同步的位置 |
|---------|--------------|
| 流水线模块（app/modules） | 安卓构建（syncBackend 自动）+ 服务器（手动 scp） |
| 业务路由（app/routes.py） | 同上 |
| 前端（app/static） | 唯一源：sync_frontends.py → server/frontend + 安卓 assets |
| 服务器后端（server/） | 仅服务器（scp + systemctl restart） |

> 共享代码（app/）改动部署顺序：本地测试 → scp 服务器 → 安卓构建（syncBackend 自动）。

## 一、常驻规则（写进规范文件，长期生效）

1. **破坏性 git 操作**（`reflog expire` / `gc --prune` / `reset --hard` / `filter-branch` / 删除分支或 stash）
   **执行前必须先做三件事并把结果报 Lead**：① `git stash list` 清点；② `git bundle create` 全量备份到**仓库外**；③ 列出"将被删除的对象"。
   —— 依据：`reflog expire --expire=now --all` 曾静默清掉 `refs/stash` 的 reflog（对象仍在、但 `git stash list` 变空）。
2. **文档与代码里永不出现密钥形状**：需要提及一律写 `sk-****`（≤4 字符，不会命中 `\bsk-[A-Za-z0-9_\-]{8,}`）。
3. **新建白名单/豁免必须申报**，并说明"形态检测一条未动"（如体积检测放过 `StarRailFont.ttf` 这类已知资产）。
4. **提交前必跑** `python tools/check_no_secrets.py --worktree`（只扫暂存区会漏存量；钩子 `.githooks/pre-commit` 已装）。

## 二、T1 门禁不许"空过"（P6-14 修法）

- **问题**：`tools/check_hotupdate.py` 的基线**动态取自 `APP_VERSION`** ⇒ 升到 0.9.1 后它扫 `hotupdate_dist/**0.9.1**`（不存在）⇒ 打印"本次无热更"并 **PASS 空过** ✗ —— 门禁在"什么都没有"时也给绿灯。
- **要做**：把"本次是否有热更"从**目录缺失推断**改成**显式声明**：发布清单/配置里必须写
  `hotupdate: none`（本次不发补丁）或 `hotupdate: <patch-id>`（发了补丁，必须可定位）。
  门禁据此判定：声明 `none` ⇒ 通过但**必须打印该声明**；声明 `<patch-id>` ⇒ 必须找得到且校验通过，否则**红**。
- **验收（4 条，都要原始输出）**：① **不声明** ⇒ 门禁**红**；② 声明 `none` ⇒ 绿且打印声明；③ 声明一个**存在**的补丁 ⇒ 绿；
  ④ 声明一个**不存在**的补丁 ⇒ 红。并写明"旧行为会空过"的对照（能贴旧输出更好）。

  1. 以 **0.9.1 为底座**产出一个**修 bug** 的补丁包（走规范产出流程，不许夹带新功能 ✗）；

  4. 应用后：**版本回显正确**、被修的行为确实变好、**底座未被污染**（给出应用前后关键文件哈希对照）；

## 三、已获 Lead 裁定的偏离项与理由

1. **T0 保留半成品而非回退**：现场 `index.html` 里混着**别的并行工作流**（广场 `#plaza-view` 整块、
   `#server-web-entry` 删除）。整文件回退会连带删掉它们、并让 `sync_frontends --check` 漂移 ⇒
   裁决为**保留既有内容、只在上面叠加 PC 外壳**，做到"PC 外壳是唯一变量"。（真对照组见 `_harden/pc_control_static/`。）
2. **`app/server.py` +12 行**（Lead **有条件同意**）：PC 语音子进程在冻结态需要自复用同一个 exe
   （`firefly.exe --voice-worker`）。属既定取舍，**不是待办**；影响面见 §五。
3. **T4 用"让位"而非新增业务逻辑**：聊天页右侧菜单把手的展开只调既有 `openMenu/closeMenu`，
   **不新增业务逻辑**；窄屏随 `#pc-shell` 一起 `display:none`。
4. **V1 移植 `TtsEngine.kt` 而非原型 `_proto/voice_engine.py`**：后者仍依赖 torch（+1164MB 提交峰值）；
   改按 Kotlin 真机验证过的形态**逐分支照抄**成纯 ONNX（`app/voice/pc_engine.py`），砍掉 torch 依赖。

## 五、P4.11 · `app/server.py` 的 +12 行**不影响**不带 `--voice-worker` 的正常启动

启动路径未变：`--voice-worker` 分支只在 `sys.argv` 命中时进入，且**位置在重依赖 import 之前**
（紧跟 stdlib import 之后，早于 `_PROJECT_ROOT` 注入与 `app/` 各模块 import）；未命中时该 `if` 为假，
**一行不执行**，下面日志重定向与 HTTP 服务逻辑逐位不变。

正常启动证据：`_harden/fix_evi/P4_server_start.log`（由另一位工程师产出，本批末已存在）——
默认解释器 `python app/server.py`（无 `--voice-worker`）正常起服务，`GET /config` 200、
`GET /voice/status` 200（`"engine_ok": true`、`"platform": "pc"`）。引用即此路径。

## 六、P4.12 · `.gitignore` 核实：**Lead 的前提不成立**

- `git show HEAD:.gitignore | grep -n voice` ⇒ `/voice/` 那一行**在 HEAD 里就已存在**（第 73 行，
  连同第 28/71/72 行注释）。即：**忽略 `voice/models` 871.9MB 不是本轮为 PC 语音新加的**。
- `git diff -- .gitignore` 的实际内容：本工作区确实改了 `.gitignore`，但加的是
  `_diag_s/`、`_diag_x/`、`_preview/`、`_rt_parse.py`（**2026-09-24** 的报障排查用忽略项），
  **与 `/voice/` 无关**；且这些改动**早于本批 PC 交接**。
- **结论**：本轮 PC 交接**没有改过 `.gitignore`**；Lead "`.gitignore` 是本轮为忽略 `voice/models` 而改的"
  这个前提**不成立**（`/voice/` 的忽略在 HEAD 已存在；工作区里的 `.gitignore` 改动属于另一条工作流）。

## 七、已知事故与既成事实（**必读，勿以为可回滚**）

- **事故（一句话）**：本轮做安装器实测时，用**真实 AppId** 的 Inno 安装包跑静默安装，`/DIR` 被本沙箱环境改写、
  又被 `UsePreviousAppDir=yes` 兜底 ⇒ **原地覆盖了用户真实安装 `E:\Firefly`**（0.8.0 → 0.9.0）。
- **影响**：`E:\Firefly` 的程序文件已换成 0.9.0 构建（`firefly.exe` sha256 `838d8860…` = `dist/firefly/firefly.exe`，
  `_internal/` 新增 onnxruntime）；**用户 `user_data` 无损（删除 0 / 内容变化 0）**；ARP 键被重写
  （DisplayVersion 0.8.0→0.9.0、DisplayName→Firefly、InstallDate→20261002）。
- **处置 = A（保持现状）**：`E:\Firefly` 现在是可用的 0.9.0，**不恢复 ARP、不卸载、不重启它**。
  理由：恢复 ARP 会让注册表"谎称 0.8.0"而磁盘是 0.9.0 —— 正是本项目 `P0-10` 记的"版本与实际不符"事故形态，
  用假元数据掩盖事故比事故本身更糟。
- ⚠ **`E:\Firefly` 的原 0.8.0 二进制无法逐字节还原**：事发时只存了哈希、**没存字节**，
  故**没有**可回滚的原始安装；后人别再指望"回滚到 0.8.0"。

## A 轨：安全收尾（用户已批准三项）

上一轮 S-1 至 S-4 已修并通过独立复核；本轮只做**三项残留**（顺序即优先级）：

### A1【最重要】全局「慢连接 / 半开连接」配额

- **问题**：每 IP 有软上限（`MAX_IP_CONNS=16`）与硬上限（`MAX_IP_CONNS_HARD=64`），但**全局**仍只有业务线程上限 `MAX_THREADS=160`；
  按硬上限算 **3 个源 IP**（3×64=192）即可打满全局池 ⇒ 全站 503 这一类**没有从根上关掉**（按软上限算约需 10 个源 IP）。
- **要做**：给**慢连接/半开**单独设一个**远小于线程池**的全局上限（建议 **32**，可配置），
  使半开连接**永远占不满**业务线程池；超限时**只拒多余的那条**连接，**不拉黑 IP**、不影响已建立的正常连接。
- **验收（必须真跑，不许只做算术）**：
  1. 用 **127.0.0.3 至 127.0.0.20** 作为**多个源 IP**（loopback 段可作源地址）同时发起半开连接，
     从**另一个来源 IP（如 127.0.0.99）**发控制请求 + `/health` **必须仍为 200**；
  2. 同 IP **20 条正常完整请求 20/20 成功**（NAT 不误伤）；
  3. **可复现的旧行为对照**：在临时副本上回退该上限 ⇒ 控制请求应出现 503（证明测试有鉴别力）；
  4. 变异测试：把新增配额回退 ⇒ 对应回归测试**变红**；还原 ⇒ 绿（证明不是空转）。
- **产出**：实现 + 回归测试（仓内 `tests/`）+ 上面四条的原始输出。

### A2 P7-1：响应发送超时（防"慢读"长期占用名额）

- **问题**：**已建立但不读响应**的连接会占满**该 IP** 的名额直到对端超时 ⇒ 与攻击者共用出口 IP 的正常用户被**临时连坐**（全站不受影响）。
- **要做**：对**响应发送**加超时（写入阻塞过久即断开该条连接并计数）。
- **验收**：慢读连接在超时后被断开；同 IP 正常请求随后**立即恢复**；另一个 IP 全程 200。

### A3 P7-3：令牌二级配额数值生效（**策略已由用户拍板**）

- **问题**：`RATE_PER_TOKEN_MIN == RATE_PER_MIN` ⇒ 防绕过已生效，但"一个人别拖累同 IP 所有人"在**数值上无约束**。
- **要做**：把**令牌层**配额设为 **IP 层配额的三分之一左右**（例如 `RATE_PER_MIN=3000` ⇒ 令牌层 **1000/分钟**，可配置）。
- **验收**：① 同一 IP 换令牌不再放大总配额（沿用审计脚本）；② **单令牌**超过其配额时被拒、**同 IP 的另一令牌不受影响**；
  ③ 写明"正常单账号每分钟可用量"的前后对比（证明不误伤正常用户）。

**A 轨纪律**：不许为了让测试变绿而放宽或删除既有防护（`DL_SEM`、每 IP 下载名额、413、穿越拦截一律保持 ✓）；
改动后跑既有相关测试并给完整输出；**只登记**未做的项（S-5 至 S-7 仍按原排期）。

## B 轨：用户可见文本与使用指南（用户原话口径）

> 「任务就是**公告内容**和**使用指南**，以及**全面过一遍全部的处理文本**。**所有会展示给用户的文本**，包括**异常处理的消息**和用户能看见的说明，
> 我打算将其**详细化**（让用户知晓**各种错误究竟是因为什么**，**避免上游 API 的问题误导用户**）。」

⇒ 一句话目标：**用户看到的每一句话，都要说清"发生了什么、为什么、你现在该做什么"，并且归因正确** ✓

### B1 第一步（价值最高，先做）：错误归因分类表 + 异常消息

1. **归因分类**（自己按代码实际情况定稿，至少覆盖这几类，且**每类措辞必须可区分**）：
   **上游 API**（限流 / 超时 / 5xx / 模型不可用 / 上游余额或配额）、**用户自己的 Key**（无效 / 过期 / 余额不足）、
   **本地网络**、**服务器或账号**（登录过期 / 账号配额 / 平台限流 / 审核未通过）、**卡片内容**（超限 / 格式非法）、
   **本地程序**（缺依赖 / 磁盘 / 权限）、**未知**。
2. **硬要求**：① **上游的问题不许写成"你的操作有误"**；② 用户的错不许写成"网络问题"；③ 每条都要给**可执行的下一步**
   （能重试的说重试与间隔；要改配置的说清改哪个；只是上游抖动的要明确"不是你的卡的问题，稍后重试"）。
3. **先出清单再改代码**：给出**全仓用户可见文本清单**（前端 UI 文案与弹窗 / 后端返回给端侧的错误体 / 公告 / 安装器提示 / 语音与审核链路），
   逐条标注：**位置（文件+行号）｜现状文本｜问题（含糊 / 归因错误 / 无下一步）｜建议文本**。
   **清单先交 Lead 过一遍** ✓ 再动手改（文本量大、需要人眼确认 ✓）。

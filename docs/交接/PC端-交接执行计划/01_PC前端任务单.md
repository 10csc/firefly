# PC 前端任务单（T0~T6）

> 依据：`docs/设计/PC端重构-IA方案.md`（已评审通过）+ 用户 UI 口径 + 独立复核结论。
> **每个任务收尾都要跑**：`build_frontend_bundle.py --check`、`sync_frontends.py --check`、`tests/test_frontend_boot.py`。

## 用户口径（最高优先，违反即打回）

1. 仿 QQ：**角色卡 = 联系人**（中间列）；**左侧侧边栏**放"卡外"功能（含底部固定的首页/设置/账号）；
2. **只有"角色卡之外"的功能能进侧边栏**；**其余一律在聊天页内**；聊天页内的设置做成**菜单页**；
3. **菜单页的收起/展开放聊天页的右侧** ✓，**点击后向左展出** ✓；
4. 本次**只做 PC 端**，手机端不接入，且**手机端行为必须完全不变**。

## T0 收拾现场（必须先做）

- 看 `git status --porcelain -- app/static` 与 `git diff -- app/static/index.html app/static/pc.css app/static/js/pc_shell.js`；
- **判定**：上一次中断的半成品改动是否自洽？
  - 若**自洽且符合 IA 方案** ⇒ 保留，直接进 T1 继续；
  - 若**半截/不清楚** ⇒ **回退这三个文件**（`git checkout -- <文件>`）再从头做 T1 ✗ 不要"接着改半截"；
- 无论保留还是回退，**T0 的验收**：`sync_frontends.py --check` 一致 + `test_frontend_boot.py` 6/0。
  - 若 `sync --check` 报漂移 ⇒ 跑 `python tools/sync_frontends.py`（写模式）修正后再 `--check`。
- **证据**：`git status --porcelain` + 两条命令的 stdout。

## T1 三栏骨架（默认隐藏，窄屏零影响）

- DOM：在 `app/static/index.html` **只追加**容器（如 `#pc-shell`、`#pc-rail`、`#pc-contacts`、`#pc-chat`），
  **不得改**任何既有元素的 id/class/`window.*` 入口 ✗；
- 样式：PC 规则**只写进 `app/static/pc.css`**，且全部在 `@media (min-width:1100px)` 内；
  media 之外只允许 `display:none`（保证手机端零执行、零占位）；
- 逻辑：只写进 `app/static/js/pc_shell.js`（classic 脚本，不进 bundle），每个入口都要 `matchMedia("(min-width:1100px)")` 守卫。
- **验收**：
  1. `python _harden/snapshot_pc_baseline.py --label post` + `python _harden/compare_pc_baseline.py`
     ⇒ **结构/几何/文案零差异**（PNG 差异只作参考，不作判据 —— 抗锯齿会假红）；
     视口含 **390×844 / 768×1024 / 1099×900 / 1100×900 / 1280×900**（1099↔1100 是真实阈值边界）；
  2. `test_frontend_boot.py` 6/0；`sync --check`、`build --check` 一致。
- **证据**：比对工具 stdout + 1280×900 三栏骨架截图 1 张。

## T2 侧边栏（只放"卡外"功能）

- 按 IA 方案 §二：卡外 = 首页 / 角色卡库 / 广场（含制卡与治理台）/ 语音插件 / 设置 / 公告 / 反馈与诊断 / 账号；
  底部固定 首页、设置、账号。
- **必修**：现在 `index.html` 里「首页」与「账号」**都调 `showHome()`** ✗
  ⇒ 二选一：**删「账号」**（推荐，账号就是首页的一段）或**为账号新写视图**；**不许**两个按钮同命令。
- 「+ 新建角色」必须带**意图参数**（直达新建表单），不能与「卡库」同义 ✗。
- **静态断言**（写进既有前端测试文件里）：
  1. 状态栏**无命令**（`#pc-statusbar` 内不得出现 `onclick`/`data-pc`）；
  2. **卡内命令 ∩ 侧边栏命令 = ∅**（扫 `data-pc` 与 `window.*` 调用点做集合比对）。
- **验收**：断言输出（各 1 条）+ 侧边栏截图；手机端 pre/post 比对仍零差异。
- **证据**：断言 stdout + `git status --porcelain`。

## T3 联系人列（角色卡 = 联系人）

- 只列**本机已安装**的角色卡（语义已有：`cfg.all_modes()`；广场/安装入口在侧边栏，**不要**做成第二个卡库 ✗）；
- 每项：头像 + 卡名 + 角色名 + 模式标记（如有未读/主动消息/记忆状态点则复用现有字段）；
- **点一下即切卡**（解决旧审计「切包比手机还绕」）。
- **验收**：切换两张卡的截图 + 切换后右侧聊天页对应内容正确的断言/截图。
- **证据**：截图 2 张。

## T4 聊天页 + 右侧菜单把手（用户明确要求）

- 聊天页 = 现有 `#app` 与卡内入口（对话/收藏/表情包/设定文件/角色状态/请求记录/流程日志/让角色休息/记忆进度）；
- **菜单页把手**：`☰` 做成**聊天页右缘的收起/展开把手** ✓ **默认收起** ✓；
  **点击向左滑出菜单页**，再点收回右侧 ✓；
  - 把手与菜单**不得遮挡聊天输入区**（让位 或 浮层+遮罩，二选一并在回报里说明理由）；
  - 窄屏/手机端默认不显形 ✓（沿用 T1 的 media + `matchMedia` 守卫）。
- **卡内命令只能出现在**：聊天页头部 / 菜单页里（**不许**在侧边栏再出现同名入口 ✗ —— IA 方案的「每个命令只出现一处」）。
- **验收**：**收起态与展出态各 1 张截图**（1280×900）+ 「点击把手 → 菜单向左展出 → 再点收回」的断言/截图。
- **证据**：截图 ≥2 张 + 把手交互断言输出。

## T5 卡详情改页内抽屉（防两套呈现并存）

- `#pack-view` 现在由卡库 6 处 `openPackView` 打开 ⇒ 改成聊天页内抽屉后，必须确认
  **卡库点卡不再同时打开整页 `#pack-view`** ✗（否则两套并存，正是 IA 方案 §六-5 标记的坑）。
- 抽屉内容 = 人设 / 知识库 / 形象 / 主动消息（**主动消息与用户形象是"按卡"域 ⇒ 必须卡内** ✓）。
- **验收**：从聊天页打开抽屉的截图 + `#pack-view` 不再以整页形态出现的断言。
- **证据**：截图 + 断言 stdout。

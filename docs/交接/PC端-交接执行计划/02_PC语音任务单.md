# PC 语音任务单（V0~V4）

> 依据：`docs/设计/PC端语音/`（5 篇，方案已定稿）+ 用户拍板「**与手机端同构**」。
> **一句话目标**：PC 上把手机那套语音跑起来，**不慢于手机、质量不降、常驻内存 ≤4GB**。

## 用户口径（不许偏离）

> 「PC 端的模型也是和手机端一样的组织方式，**都是从社区下载**。所以**不要乱搞**」
> 「语音模型作为插件，**放到魔搭社区**（或**就用现成的魔搭社区上的手机端语音模型**）」

⇒ 硬约束：
- **复用手机端同一套插件机制**（下载器/状态机/sha256 校验/HTTP 端点/前端长按菜单/清理 LRU —— 这些**都已存在** ✓）；
- 模型 = **魔搭社区上手机端那份现成的**（int8 八文件，约 872MB）；**不换源、不重新打包、不改目录结构** ✗；
- **不引入 GPU、不做蒸馏、不换模型** ✗。

## V0 依赖放行（唯一允许的例外）

- `onnxruntime` + `numpy`：**用户已批准**，但**只许进语音子进程**，不得污染主进程依赖表；
- 同步修改 `firefly.spec`（现在它 `excludes` 了这两个 ✗ ⇒ 引擎写好也 import 不到）；
  **只影响 PC 打包，不动安卓** ✗。
- **验收**：`firefly.spec` 的 diff + 打包后语音子进程能 `import onnxruntime` 的证据（日志/版本输出）。
- **证据**：diff + 版本输出。

## V1 引擎后端（PC 可用）

- 断点：`app/voice/engine.py` 的**非安卓分支直接返回不可用** ✗ ⇒ 在这里补 PC 后端（注释里本来就写着"接入时只需在这里补一个后端"）；
- 形态：**独立子进程**（空闲自退、内存真归还、崩溃隔离）+ onnxruntime CPU；
- **文本前端移植 Kotlin 版**为纯 Python（4 张映射表已在 `app/assets/voice/`）⇒
  这样能省掉 `torch + transformers` 的 **+1164MB** 提交峰值 ✗；
- `mood_lib` 直接读**打包资产**（PC 上没有落地路径，**不要**再引入第二套落地 ✗）。
- **验收**：① 端到端合成一句并落盘 wav（命令 + 输出）；② 引擎装载耗时；③ 子进程峰值内存（工具见 `FireflyVoiceResearch/_proto/`）。
- **证据**：命令 + wav 路径 + 耗时/内存数字。

## V2 插件通道（复用手机那套，不许另搞）

- 复用手机端的插件下载/校验流程走**魔搭社区**；
- 若现有插件清单里 PC 与手机的 URL 或目录布局不同 ⇒ **停下来先回报**，不要自行换源 ✗。
- **验收**：一次完整下载 + sha256 校验通过的日志（或"使用已存在插件"的校验日志）。
- **证据**：下载/校验日志（含 URL 与校验和）。

## V3 验证（三张表，缺一不可）

1. **延迟对比**：同一批文本，手机实测 vs PC 实测（单句 + 引擎装载）；
2. **内存对比**：手机 PSS vs PC 子进程峰值/常驻（目标 ≤4GB，方案预估 1.1~1.5GB 常驻）；
3. **质量对比**：PC 与手机**逐条同逻辑**的对照（你是移植不是换模型 ⇒ 必须给对照，不许「感觉差不多」✗）。
- **验收**：三张表 + 原始输出；`docs/设计/PC端语音/` 更新实测数字。
- **证据**：表格 + 原始日志。

## V4 提速（在 V1 可用之后再做）

- 方案实测：**PC 侧瓶颈是 CFM 不是 AR**（与手机相反）⇒ 先动 CFM（步数 4→3、4-bit），再动 ORT 线程 ✗ 反过来做没用；
- 每次只动**一个变量**并记录前后数字（避免混淆因果）。
- **验收**：提速前后数字对照（同一输入、同一机器）+ 质量未降的证据。

## 一、项目与目标（背景事实，不要自行假设）

- 项目：Firefly（流萤）——本地运行的角色扮演 Agent。仓库根 = 本项目根目录。
  - `app/` = 本地版（PC + 安卓，安卓用 Chaquopy 打包）；`server/` = 服务器（**只做后台，不对外提供 App 前端**）；
  - 前端：`app/static/`（`index.html` + `style.css` + `js/`），**三端共用**（手机 App / PC / 服务器平台的资源都源自这里）。
- 本次目标（0.9.1 的 PC 端），两件事：
  1. **PC 语音模型**：以手机端 900MB 语音插件为基线，PC 上做到「**不慢于手机、质量不降、常驻内存 ≤4GB**」；
  2. **PC 前端重做**：仿 QQ 三栏（左=侧边栏 / 中=角色卡联系人列 / 右=聊天页），**严格按业务逻辑分层**。

## 二、必须先读的项目铁律（违反即打回）

1. **模块流程**：接收输入 → 审查约束 → 处理 → 验证结果 → 输出（新模块都要有审查与验证两段）。
2. **文档树状分文件，单文档 ≤200 行**；超了就拆，并在目录索引里登记。
3. **唯一待办真相源** = `docs/未完成事项清单.md`：做完一条删一条，新发现必须登记。
4. **改前备份**：改动前先确认能回退（本仓 `app/`、`docs/`、`tools/` 在 git 里；`server/` 不在）。
5. **不要动** `server/**`（本次与服务器无关）；**不要** `git push`、**不要**发版、**不要**改版本号
   （当前线上冻结在 v0.9.0，用户明确要求不要发布）。
6. **`app/static/style.css` 三端共用**：任何只给 PC 的样式**只能写进 `app/static/pc.css`**，
   并且必须在 `@media (min-width:1100px)` 内生效；**手机端必须逐字节不受影响**。

## 三、怎么跑（验收命令表，全部在仓库根执行）

| 用途 | 命令 | 期望 |
|---|---|---|
| 前端产物一致性 | `python tools/build_frontend_bundle.py --check` | 输出「一致 ✓」 |
| 三副本同步 | `python tools/sync_frontends.py --check` | 输出「一致」 |
| 手机端不回归 | `python tests/test_frontend_boot.py` | `PASS=6 FAIL=0` |
| PC 手机零影响（快照比对） | `python _harden/snapshot_pc_baseline.py --label post` 然后 `python _harden/compare_pc_baseline.py` | 结构/几何/文案零差异（PNG 只作参考） |
| 契约门禁 | `python tools/check_server_contract.py` | `PASS` |
| 语音（本机可跑的部分） | 见 `02` 任务单 | 按任务单 |

> Windows 上用 PowerShell；设置 `$env:PYTHONUTF8="1"`。
> **凡是你改了 `app/static/**`，收尾前必须跑**：`build_frontend_bundle.py` + `sync_frontends.py` + `test_frontend_boot.py` 三条。

## 四、交接与验收协议（照这个格式回报，我会逐条核）

每个任务完成后，向用户回报**这四样**（不要贴整份 diff ✗，太长）：
1. **改了哪些文件**：`git status --porcelain` 的输出（我会自己看 diff）；
2. **验收命令的原始输出**：上表里与该任务相关的命令**完整 stdout**（不要只写「通过」）；
3. **该任务的证据**：截图路径 / 断言输出 / 关键日志行（按任务单要求）；
4. **有没有偏离任务单**：若你对任务单做了不同选择，**明确写出来 + 理由**（允许偏离，但必须说明；隐瞒偏离 = 打回）。

**我会做的检查**：读 `git diff` 的关键部分 + 复跑验收命令（必要时）→ 判定「通过 / 打回 + 具体原因」。
**打回的常见原因**：手机端被 PC 改动影响 ✗、把 PC 样式写进 `style.css` ✗、只交「通过了」没有原始输出 ✗、改了任务单没说的文件 ✗。

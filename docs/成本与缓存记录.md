## 三·补、冷启动成本（剧情模式 · 第一轮全未命中）

> 假设首轮 4 节点全部 cache miss（DeepSeek LRU 缓存过期后首轮的真实情形）。
> Flash 定价：未命中 1 元/M、命中 0.02 元/M、输出 2 元/M（命中 vs 未命中差 50 倍）。

| 节点 | prompt×未命中价 | completion×输出价 | 小计 |
|---|---|---|---|
| 检索器 | 86,105 × 1元/M = 0.0861 元 | 399 × 2元/M = 0.0008 元 | **0.0869 元** |
| 分析器 | 6,697 × 1元/M = 0.0067 元 | 1,177 × 2元/M = 0.0024 元 | 0.0091 元 |
| 回复器 | 8,608 × 1元/M = 0.0086 元 | 140 × 2元/M = 0.0003 元 | 0.0089 元 |
| 组织器 | 435 × 1元/M = 0.0004 元 | 6 × 2元/M = 0.0000 元 | 0.0004 元 |
| **合计** | | | **≈ 0.105 元** |

**对比**：全未命中 0.105 元 vs 命中后平均 0.0078 元 —— 差 **13.5 倍**，缓存命中节省 **92.6%**。
检索器（86k tokens）是冷启动成本大头（0.086 元/轮），其 99.9% 命中率价值最大：每命中一轮省 ~0.086 元。

## 四、成本构成分析

1. **检索器**：prompt 86k tokens 占绝对大头，但因 system 稳定命中 99.9%，实际成本仅 ~35%（未命中 token 每轮 <100，约 0.0001 元）
2. **分析器成本最高（~45%）**：原因有二——① 思考链 completion tokens 大（600~1,800/轮，输出按全价 8 元/M 计）；② user 动态部分 miss（历史 20 轮 + 检索摘要 + 环境）
3. **回复器/组织器**：completion 小、system 命中高，成本低

## 五、结论与优化方向

- **加权命中率 98.7%，达成 95~98% 目标**（system prompt 全部字节级稳定是核心——角色设定全在 system，动态上下文全在 user）
- 剩余 miss 本质是角色扮演的每轮动态上下文（历史/摘要/输入），无法前缀命中
- 进一步优化（有质量代价，未执行）：
  - 分析器/回复器历史轮数缩减（20→12 / 15→10）→ 减少 user miss 约 40%
  - 限制检索器摘要长度 → 分析器 user 变小
  - 服务启动后台预热一次检索 → 冷启动当轮命中
- 平台侧：DeepSeek 缓存为 LRU，长时间无请求后缓存过期，当日首轮会 miss（不可优化）
- 若 DeepSeek 调价：缓存命中价格通常远低于未命中（当前约 1/4），高命中率对总成本影响显著

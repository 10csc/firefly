# ADR 0001：本地优先同步

- 状态：accepted
- 日期：2026-10-27

## Context

用户的聊天、记忆和手账必须离线可用。设备时钟和 mtime 不能决定冲突胜负；清理和撤回也不能被另一台离线设备的旧副本复活。

## Decision

- 用户操作先本地提交，网络只负责收敛。
- 服务器分配 `history_rev`、`memory_rev` 和 history epoch。
- 新消息使用 `mid`，旧消息迁移为稳定 legacy id。
- 删除写墓碑；清理推进 epoch。
- 多文件操作使用 PREPARED/COMMITTED 状态机。
- 文件同步使用 `state_rev` 和 `base_sha` 条件写入，冲突显式备份。

## Consequences

同步实现比普通文件覆盖复杂，需要事务、outbox、墓碑压缩和并发锁。换来的是断网可用、旧数据不复活、响应丢失可幂等重试。协议见 [同步协议](../参考/同步协议.md)。

## 二、严重项详情

### 1. 网关反代无请求体上限 → 单连接 OOM

**原理**：`download_server._proxy` 原样读取 `Content-Length` 声明的长度进内存：单连接发送头 `Content-Length: 2000000000`（并不真的发 body）即可让 2G 内存服务器逐字节分配直至 OOM。主服务各端点自身有帽（JSON 1MB / multipart 11MB），唯独网关层裸奔——限流（300 次/分）挡不住少量连接的巨型声明。

**修复**（`server/download_server.py`）：
- 新增 `MAX_PROXY_BODY = 16MB`（> 最大合法请求：图片上传 multipart 上限 11MB + 表单余量）；
- `_proxy` 开头三段校验：`Transfer-Encoding` 存在 → 411（本服务不支持 chunked 转发）；`Content-Length` 非数字 → 400；超上限 → 413。

**验证**：`tests/test_security_hardening.py` F1/F2（常量区间校验）；全量 33 测试文件退出码全 0。

### 2. relay 中转 SSRF → 服务器沦为内网探测代理

**原理**：relay 模式下 `X-API-Base` 由登录用户控制（原校验仅 http(s) 前缀 + 长度 ≤300）。`/relay/proxy` 中转时服务器以自身身份向该地址 POST 并把响应 JSON 回传用户——攻击者注册账号后可让服务器访问 `http://127.0.0.1:8765`（主服务自身）、`http://100.100.100.200`（阿里云元数据）、内网段任意地址，从响应差异/内容探测内网拓扑与服务状态。利用门槛存在（需注册 + call_id 匹配队列），但注册是开放的。

**修复**（双层拦截）：
- **入口层** `server/server_app.py::_setup_user_context`：X-API-Base 增加 `is_public_endpoint()` 公网校验，内网/环回/链路本地/CGNAT 一律拒绝置空 + stderr 日志（`[SSRF-GUARD]`）；
- **出口层** `app/routes.py::relay_proxy`：从队列取出 api_base 后代发前再校验一次（纵深防御，防其它入队路径绕过或队列残留脏 base），非公网 403 拒绝不发请求。

**新函数** `app/modules/api_client.py::is_public_endpoint(base_url)`：
- URL 解析（仅 http/https）；host 拒绝 `localhost` / `*.localhost` / `*.local`；
- IP 字面量直接判定；域名做 DNS 解析，**所有** A/AAAA 记录必须公网单播（防多记录混入私网）；
- 拒绝范围：私网（10/8、172.16/12、192.168/16）、环回、链路本地（含 169.254.169.254 云元数据）、CGNAT（100.64/10，显式补——部分 Python 版本 `is_private` 不含）、组播、保留、未指定；IPv6 含 `::1`、`fc00::/7`、`fe80::/10`、IPv4-mapped；
- 结果按 host 缓存 TTL 300s（relay 前端 1s 轮询每次带 X-API-Base，不能每请求 DNS）；
- 已知残余风险（接受）：DNS 解析与实际请求之间存在 TOCTOU（DNS rebinding），当前威胁模型下不构成实质绕过（requests 会重新解析，但攻击需控制权威 DNS 且持续响应私网记录——届时出口层校验同样会拦截首次解析）。若将来收紧，可换「解析后 IP 直连」方案。

**验证**：测试 B1-B10（17 种非法地址全拒、公网字面量放行、多记录含私网拒、DNS 失败拒、缓存生效、IPv4-mapped 按私网拒）。

## 三、定性修正：img_id「路径穿越」实测不可达（诚实记录）

审查初报将 `_load_image_data_url` 的 `d.glob(img_id + ".*")` 定性为「跨用户路径穿越（严重）」。**本次实测修正**：Windows + Python 3.12.6 下 `Path.glob` 把 pattern 中的 `..` 当**字面量文件名**匹配（不解析为父目录），`../../1/images/x` 实测 0 命中，穿越不可达。初报结论错误，特此修正。

但校验缺失仍是真实缺陷，实际危害为：
1. **可触发的未捕获异常**：`img_id="C:/evil"` 等**绝对路径 pattern** 会让 `Path.glob` 抛 `NotImplementedError`（实测），该异常沿 chat() 上传导致整轮请求失败（健壮性缺陷，可被用来打断自己的会话）；
2. `*` 等 glob 通配符意外匹配多文件（影响限于本用户目录）；
3. 违反项目自身模块铁律（审查约束阶段缺失），且 pathlib glob 行为在未来 Python 版本存在变化风险（防御纵深）。

**修复**：`app/routes.py` 新增模块级白名单 `_IMG_ID_RE = [A-Za-z0-9_-]{1,64}`（合法值由 `upload_image` 生成：`img_` + 12 hex；白名单同时兼容旧格式）。`_load_image_data_url` 校验失败返回 None；`get_image` 的黑名单（`..`/`/`/`\`）替换为同一白名单——两处校验统一，绝对 pattern 异常路径一并消除。

**验证**：测试 A1-A7（合法读取正常、8 种非法形态全拒且不抛异常、路由级 400、URL 编码穿越 400、合法 id 不误伤）。

## 四、中危项详情

### 4. sessions token 明文落库 → 哈希化

**原理**：`sessions.token` 主键原样存 `secrets.token_urlsafe(32)` 明文。DB 文件（`user_data/firefly.db`）一旦泄漏（备份外流、目录穿越类漏洞、运维误操作），攻击者直接持有全部用户 30 天有效登录凭证。

**修复**（`server/db.py`）：
- `create_session` 落库改为 `sha256(token)`（token 熵 256 bit，无字典攻击面，无需加盐）；
- `get_session` 先按哈希查，miss 再按明文查（**旧明文行兼容**——命中时就地升级为哈希）；
- `delete_session` / `extend_session` 哈希与明文双形式匹配（登出/续期对旧行同样生效）；
- 新增 schema **迁移 v2**：启动时把存量明文 token 一次性批量改写（`_MIGRATIONS` 顺序迁移机制，与既有 A2 迁移体系一致）；
- `auth.py` 调用方零改动（哈希在 db 层内部消化）。

**验证**：测试 C1-C9（库内无明文、64 位 hex、明文可查回、旧行兼容升级、delete/extend 双形式、v2 迁移批量改写、迁移后原 token 仍可认证）。

### 5. 密码比较非常数时间

`auth.verify_password` 原 `==` 比较哈希，理论上存在计时侧信道。改 `hmac.compare_digest`（管理台令牌校验 `server_app._authed` 本就是 compare_digest，本次对齐）。测试 D1-D4 回归。

### 6. loginfail 键无限膨胀（邮件喷洒撑库）

**原理**：登录失败计数存 `settings` 表 `loginfail:<email>` 键，仅在该邮箱再次登录时懒清理。喷洒攻击（大量随机邮箱失败登录）会制造只写不清的键，settings 表缓慢膨胀。

**修复**：`db.prune_login_fail_keys(max_age)`（全表扫描 `loginfail:%`，全部时间戳超窗或值损坏即删）；`auth.record_login_fail` 在**写路径**顺带调用——攻击进行中即自愈，正常规模空表毫秒级。另 `clear_login_fails` 改为 `delete_setting`（登录成功删键，原来写空 JSON 占行）。测试 E1-E2。

### 7. 安卓 allowBackup="true"

含 API Key（config.json）与登录凭证（auth.json）的应用数据会被系统自动备份（adb backup / 厂商云迁移通道）带出设备。改 `android:allowBackup="false"`——项目自带导出/同步链路，无需系统级备份。**注：下次构建 APK 后生效**；`usesCleartextTraffic="true"` 保留（服务器模式 http 回退所需，HTTPS 方案见既有文档待定项）。

## 五、低危项与顺带修复

- **multipart 畸形 Content-Length**：`int()` 非数字头抛 ValueError → 安全拒绝返回空（测试 G1）；
- **管理端 body 上限**：`AdminHandler.do_POST` 读 body 增加 64KB 帽（防御纵深，虽已有本机+令牌双因子）；
- **`test_image_unseen` flaky**：原硬编码 `sleep(0.2)` 撞冷启动竞态（主请求尚未注册合并窗口时 flush 落空 → 主请求等满 5s、join(4) 超时假失败；已实测复现并确认与本次安全改动无关——stash 全部改动后同样失败）。改为轮询等待窗口注册（最多 3s）再 flush，连续 3 次运行全绿。

## 阶段 0 执行备注（执行者：DeepSeek，2026-09-13）

**计划与代码冲突点（按 README「以代码为准」处理，逐条记录）**

1. **0.3 · `build_frontend_bundle.py` 的 ORDER 不能等于「js/*.js 全量」**。
   计划书写的验收口径是"列 `js/*.js`（排除 bundle.js）→ 与期望集合比对"，
   但代码事实是：`app/static/js/pc_nav.js` **故意不进 bundle**——`index.html:974` 用独立
   `<script src="js/pc_nav.js">` 加载（petite-vue 挂载，仅桌面档用），`bundle.js` 里没有它。
   故实现为：`NON_BUNDLE = {"bundle", "pc_nav"}` 显式排除 + 集合双向比对（盘上多的、ORDER 里
   悬空的都 FAIL）。**门禁效力不变**（新增 js 模块忘登记必 FAIL，已实测 `dummy.js` 场景），
   只是把"故意不打包"这一个事实显式化。

2. **0.3 · `sync_frontends.py` 的 ASSET_FILES 不能等于「app/assets 根目录文件全量」**。
   根目录实际 13 个文件，仅 9 个进 APK。多出的 4 个（`icon.png` / `icon_tip.svg` /
   `img_header.png` / `thumb.svg`）经全仓检索**无任何引用**（前端 html/css/js、`firefly.spec`、
   `package/firefly.iss`、android 资源全部零命中）——是历史遗留死文件，不是"漏打包"。
   故新增 `ASSET_NOT_SHIPPED` 显式分类 + 并集断言：新增资产必须二选一登记，否则 FAIL。

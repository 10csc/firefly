# 阶段 3 · 数据所有权与包管理

> 目标：把「包的存在性」从进程态升为持久事实（packs.json），把数据策略收口进 REGISTRY，修复删包连坐。
> **本阶段开始有行为变化**，每张卡的变化点已写明。预计 ~5 天。前置：阶段 2 出口 + 规划者确认。
> 设计依据：`项目架构图/architecture-refactor.html` 视图⑤⑭。

### 任务 3.1：REGISTRY 加 owner 字段
- 证据：`app/modules/storage.py:89-123`（12 条注册项无所有者声明）
- 步骤：每条注册加 `owner`（模块名）；`is_syncable` 等查询函数不变；新增一致性测试：每个 owner 值必须对应真实存在的模块文件
- 行为变化：无（纯声明）
- 验收：测试绿；导出/同步链路回归（test_backup/test_sync_engine）

### 任务 3.2：packs.json 注册表（核心卡）
- 证据：`app_config.py:385-433` `_discover_presets`（存在性=进程扫描）；审计报告方案 B
- 目标：`user_data/{uid?}/packs.json` 成为包存在性的唯一权威
- 步骤：
  1. `core/presets.py`（阶段 2 后的落位）新增 `PackRegistry`：load（文件缺→从目录自愈重建→落盘）/save/register/unregister/get；
  2. 记录字段：id/source(bundled|custom|imported)/schema/name/char_name/capabilities/state(active|archived)/slots 三态/created_at/updated_at；
  3. `_discover_presets` 改为：bundled 扫描（不变）+ 用户区**从 packs.json 读**（不再裸扫目录）；
  4. `create_pack`/`forge_finish`/快照恢复阶段 1 → `register()`；`delete_pack` → `unregister()`；
  5. 自愈：启动时清单缺失或目录多出未注册包 → 重建并在日志打印差异。
- 行为变化：① 自建包存在性不再依赖进程扫描；② 孤儿目录变为"未注册"可见状态（UI 后续给清理入口）
- 兼容：旧版客户端不读 packs.json 照常工作；packs.json 丢失 → 目录自愈重建（兜底链完整）
- 验收：测试——① 空环境从目录重建清单；② 注册/注销往返；③ 快照恢复自建包后清单含该包（阶段 0 的用例 A 扩展断言）
- 回滚：revert + 删 packs.json（目录扫描旧逻辑在 git 历史可退）

### 任务 3.3：卡定义三态标记
- 证据：`routes_pack.py:93 get_pack_files` 的 customized 判定（现算 diff）；`app_config.py:650-675` `_cleanup_stale_defaults`
- 步骤：packs.json 的 `slots` 字段维护每槽位 baseline/inherited/customized；`character_file_update`/`delete_character_file`/`run_startup_init` 三处写入点同步更新标记；UI 的"已修改"标记改读清单
- 行为变化：无用户可见变化（数据源切换）
- 验收：测试——编辑 core.md → customized；删除副本 → inherited；bundled 内容变化后未编辑副本仍 inherited

### 任务 3.4：快照 _manifest.json
- 证据：`routes_snapshot.py:42-76 build_full_snapshot_zip`（无清单/校验和）
- 步骤：打包时写入 `_manifest.json`：`{snapshot_version:1, app_version, created_at, packs:[{id,name,source,schema,files,sha256 汇总}]}`；恢复端：有 manifest → 按 manifest 驱动恢复并在响应回传 `manifest` 摘要；无 manifest（旧 zip）→ 走现逻辑
- 行为变化：快照 zip 多一个文件（旧版本客户端恢复含 manifest 的 zip 时把 `_manifest.json` 当普通顶层忽略——实读确认现恢复逻辑忽略非包顶层，兼容成立）
- 验收：测试——新快照含 manifest；旧格式 zip（手工删 manifest）仍可恢复
- 回滚：revert（旧 zip 格式不变）

### 任务 3.5：删除两级化（归档/抹除）
- 证据：`routes_pack.py:324-339 delete_pack`（一次 confirm 直接 rmtree 连数据）
- 步骤：
  1. `POST /pack-archive`：state→archived，包从 `/modes` 列表隐藏（archived 不进 MODES），数据目录保留；
  2. `POST /pack-restore`：archived→active；
  3. `delete_pack` 改：**仅 archived 包可删**；删除前强制 `build_full_snapshot_zip` 该包 zip 落 `backups/`（失败即中止删除）；前端改为「归档」主按钮 + 归档区的「彻底删除」（输入包名确认）；
  4. stickers 里 `pack=该id` 的条目在归档/抹除时自动转全局共享（`pack` 置空），日志记录条数。
- 行为变化：删包不再立即灭失数据（本卡的核心行为变化，需在执行日志显著标注）
- 验收：测试——归档后 MODES 不含该包、数据在；抹除前 backups/ 必出新 zip；贴纸条目转全局
- 回滚：revert（已归档包目录仍在，手工改 state 可恢复）

### 任务 3.6：记忆游标自愈
- 证据：`routes.py:446-460`（undo 手动回写 `.memory_index`）；`:485-492`（clear-history 同理）——每加一个写对话入口就多一处补偿点
- 步骤：`memory_manager` 新增 `verify_index(mode)`：`last_integrated_turn > count_user_turns()` 时自动压低并日志；在 `wake()` 与 `rest()` 入口调用；routes 两处手动回写**保留**（防御双写无害），但注释标注"自愈已兜底，此处为即时性优化"
- 行为变化：游标异常自愈合（此前会永久跳过整理）
- 验收：测试——手工把游标改大 → wake 后被压低
- 回滚：revert

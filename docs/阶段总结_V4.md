## 当前数据流

```
POST /chat → server.py（HTTP+会话）→ orchestrator.handle_chat()
  │
  ├─ PlanningJudge.judge()           → JudgeResult
  │
  ├─ 三路并行 ──────────────────────────────────
  │  ├─ MoodAdder.add()              → 新增情绪 (dict|None)
  │  ├─ MoodDecayer.decay()          → 消退后情绪 (list)
  │  └─ StateUpdater.update()        → raw delta (好感/紧张)
  │
  ├─ merge_moods()                   → 最终心情
  ├─ compute_rates()                 → 倍率系数
  ├─ state_updater.finalize()        → raw delta × rate + 自动消退 + 主动性培养
  │
  ├─ [direct 路径] → 静态话术
  │
  ├─ [正常路径]
  │  ├─ state_decoder.decode()       → 数值 → 自然语言
  │  ├─ Planner.plan()               → {tools, tone, direction}
  │  ├─ tool_dispatcher.pre_dispatch() → 工具执行
  │  ├─ ReplyGenerator.generate()    → 回复文本
  │  └─ Composer.compose()           → 分句 + 消息序列
  │
  └─ ContextManager.record()         → 历史写入
```

## 当前数值体系

### 好感度
- 基线: 80 (日常模式)
- delta: -0.8 ~ +0.3 /轮
- 速度: 正常 100 轮到 95，最快 50 轮

### 紧张度
- 定义: 心跳互动感（非冲突压力）
- delta: -5 ~ +25 /轮（个位数正常，十位数极端）
- 自动消退: -1.5/轮
- 不钳位上限

### 主动性
- 默认: 50，缓慢培养 ±0.1/轮
- U 形倍率效应——有风格好过没风格

### 心情
- 6种情绪 × 强度 1-5，多情绪共存
- 4对互斥: 开心↔低落、安心↔焦虑、安心↔低落、低落↔害羞
- 困惑缓冲所有属性倍率
- 认知困惑 1-3，社交困惑 3-5

## 已知问题

### 1. 回复人机感重（已缓解）
规划器 + 回复模块已独立，但回复多样性仍需持续优化。
**已做**: 规划器输入含角色设定+状态解码+工具结果，回复器注入角色三件套 md。
**待做**: 记忆召回、回复风格多样性参数控制。

### 2. 前端 sticker 契约修复（已修）
v4.5 中 composer 输出 `file` 字段但前端读 `path`——已统一为 `path`。

### 3. API 空返回间歇出现
Flash 模型偶发空返回，重试机制兜底但增加延迟。
**已缓解**: max_tokens 从 30→200，空返回率大幅下降。Decayer 仍偶发 1-2 次重试。

### 3. 倍率变化器时序滞后
倍率用上一轮心情计算，困惑/情绪变化的倍率效应延迟一轮生效。
**影响**: 轻微。现实中心情对行为的影响本就有滞后，一轮延迟可接受。

### 4. 系统对连续空输入的韧性不足
第一轮测试中连续空消息，流萤循环回复同一句话。
**根因**: 无对话状态检测。**非当前阶段问题**，后续在规划器中解决。

### 5. Adder 存在边界模糊
"问答装甲感受"被误判为困惑。已收紧 prompt，但 Flash 模型对微妙语境的分辨力有限。
**根因**: 单标签输出 + 轻量模型。可接受，后续考虑做置信度或二次校验。

## V4.5 已完成讨论（待实现）

### 规划器选型
- 模型：**Flash + Think High** (`reasoning_effort="high"`)
- Think High 实测比 Non-think 更省 token（思考让输出精炼），情感判断更准
- Think Max 仅复杂工具链/大量提示词堆叠时启用
- Pro 仅知识密集型任务或 Flash 不够用时启用（成本 ~12x）
- 详见 [CLAUDE.md](../CLAUDE.md)「模型与思考模式选择」

### 规划器接口方向
- 场景：流萤通过联觉信标（≈手机）和开拓者发消息，行为边界=能通过手机做的事
- **先调工具 → 收集结果 → 再进回复器**
- 输入：对话记录 + 状态快照（数值+心情）+ 工具列表 + 角色约束
- 输出：`{tools, tone, topic, initiative}`
- 待设计：prompt 结构、角色约束怎么嵌入

### 回复器方向
- 输入：上下文 + 状态（混合模式：数值供推理 + 文字描述供生成）+ 规划器指引 + 工具结果
- 待设计：数值→自然语言映射规则

### 待后续商议
- 知识库：存知识还是存记忆？怎么更新？记忆遗忘？
- 记忆系统：提取、跨会话
- 工具系统：memory/knowledge/time 具体实现
- 前端状态展示

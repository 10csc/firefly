**两个当场踩到的坑（都写进设计文档 §五）**
1. **PC 覆盖样式被内联 `<style>` 压住**：`index.html` 的 `<head>` 里有内联样式块，
   其中 `#settings-panel .settings-body > *{max-width:720px}` 与 pc.css 同优先级，
   而内联块在 pc.css **之后** → 桌面设置的两栏栅格被压回一条 720 窄柱。
   **修法**：`pc.css` 的 `<link>` 挪到内联块**之后**（PC 覆盖必须最后加载）+ 提一级特异性双保险。
2. **不能跟"手风琴"对着干**：设置面板 JS 里一次只开一组（移动端刻意设计）。
   阶段 1 曾想"桌面全展开"，实现是逐个 `head.click()` → **开一个关一个**，最后只剩最后一组开着。
   **修法**：顺应它 —— 折叠组排成两列瓦片、**展开的那组独占整行**；分组导航交给上下文列。

## 二十二、2026-09-19 PC 端前端**第二版**（第一版被否掉后重做）+ PC 0.9.0 安装包

**用户否掉第一版的理由（三条，都成立）**：
1. **"这是在首页，首页你展示一堆菜单页里的东西干什么？那你菜单页有什么用？"** ——
   我把**手机 ☰ 菜单页里的东西**（收藏/表情包/设定文件/请求记录/流程日志）抄成了全局左栏。
2. **"左边留个侧边栏不明所以（还有残留功能比如纠错）"**。
3. **"UI 风格完全的廉价 AI 味，我手机改好的 UI 不学（甚至照抄导致完全没适配）"** ——
   用 emoji 代替它自己的 SVG 精灵；把手机的三层结构原样搬成并排的栏，而不是换一种呈现。

**按用户要求上网查这类问题的解法**，找到的正式依据（微软官方 UX 指南 Windows Ribbons）：
- *"Present each command on only one tab. Avoid multiple paths to the same command …
  having duplicate commands makes it harder for users to find other commands they are scanning for."*
- *"Reserve commands that belong in the Application menu only for that menu."*
- *"Use context menus and mini-toolbars for in-place, contextual commands."* ——
  只作用于当前对象的命令（收藏/记忆/日志）不该升格成窗口级导航。

**第二版准则：层级与命名 100% 沿用手机，PC 只改"呈现"。**
- 删掉五块自造结构：`#pc-shell`(rail+list) / `#pc-main-head` / `#pc-chat-side`，以及 `pc_shell.js` 里
  的整套导航逻辑（700+ 行 → ~120 行，只剩底部状态栏）。
- ☰ 菜单**恢复为可见入口**；呈现从"覆盖抽屉"改成**右侧停靠面板**（`--pc-menu-w`），
  菜单内容、两组分组、四个动作**一字不动**。
- 首页仍是同一张卡片组件：轮播 → 多列网格（`auto-fit`，包少时卡片自动变宽）+ 内容居中一列。
- 只额外加**底部状态栏**（版本/热更/同步/公告未读）——状态是信息不是命令，不构成重复路径。
- 顺带修掉一个真实渲染 bug：`.msg-row .bubble{max-width:68%}` 与手机上 `.msg-col .bubble{100%}`
  叠加、而 `.msg-col` 又是 shrink-to-fit ⇒ 两级互相挤压，`嗯，我在` **一个字一行**（内容宽仅 29px）。
  现在上限只由 `.msg-col` 承担。
- `tests/test_pc_shell.py` 重写为第二版守卫（**33 项**）：不许有第二套导航 / ☰ 在 PC 必须可见 /
  菜单必须停靠 / 断点隔离 / 气泡上限只设一次 / pc_shell 只做状态栏且无 emoji / 打包同步登记。

### 二、四个只有动手才会暴露的点（都已写进契约）

1. **`extract_verified` 的"包内=清单"是全局比较**：v1 单层时正确，双层分包解压时会把另一层的
   文件当成"多出来的"⇒ 双层包永远装不上。修法：显式传 `expect_names`（整包集合）。
2. **`sys.path` 插入顺序**：`insert(0)` 是"最后插的在最前"，所以覆盖层必须插在 `_BACKEND/app`
   **之后**；写反了 = 补丁装上了但代码还是旧的，且**零报错**。门禁钉死。
3. **`_overlay_effective` 的判据换了两次**：先用 `find_spec` 的 origin —— 被 e2e 抓到两个假信号
   （子模块不存在时 `find_spec` 拿父包 `__path__` 兜底回答；"底座里有但没 import"也误判）。
   最终判据 = **`sys.modules` 里有没有**（权威），且**枚举失败要 log 成 error 而不是 warning**
   —— 第一次实现漏 import `sys`，异常被兜成"按可重启处理"，症状是静默失效（已加 `NameError` 分支）。
4. **含 py 的补丁不许 reload 页面**：重启进程之后新前端自然一起生效，先 reload 只是白闪一次。

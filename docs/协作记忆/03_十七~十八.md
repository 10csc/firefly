### 一、能不能放 —— 能，且是**实测**不是推测

从本机安装的 `modelscope` SDK **常量**读到平台硬限制（比任何网上说法都权威）：

| 项 | 平台限制 | 本模型 |
|----|---------|--------|
| 单文件 | `UPLOAD_MAX_FILE_SIZE` = **100 GB** | 最大 351 MB |
| LFS 阈值 | `UPLOAD_SIZE_THRESHOLD_TO_ENFORCE_LFS` = 1 MB | 8 个文件全走 LFS |
| **非 LFS 小文件合计** | `UPLOAD_NORMAL_FILE_SIZE_TOTAL_LIMIT` = 500 MB | 不适用 |
| 文件数 | 100000 | 8 |

> **辟谣**：网上（含一篇 AIGC 生成的博客）流传"魔搭单仓库上限 500MB"，那是把
> **非 LFS 小文件合计上限**误读成了仓库总容量。实证：官方 `Qwen/Qwen2.5-7B-Instruct`
> 仓库里就是 4 个 ~3.9 GB（共 15.2 GB）走 LFS 的权重。官方开发者群答复同样是"容量没限制"。

### 三、凭据位置（用户要求写进文档）

**令牌存在本机用户级环境变量 `MODELSCOPE_API_TOKEN`**（注册表 `HKCU\Environment\MODELSCOPE_API_TOKEN`）：
SDK 的 `HubApi.login()` 和我的 `resolve_token()` 都读它 → **日常上传不用再传令牌**。

★ **实测踩坑**：`~/.modelscope/credentials` 那个文件在本机**读不出来**（Python `PermissionError`、
PowerShell「访问被拒绝」，ACL 异常），而且 `HubApi.__init__` 并**不**自动读它
（`self.token = token` 默认 None）——所以**不要依赖那个文件**，用环境变量。
详见 `docs/工具/tts.md` §12.2。

### 四、另外两个坑（都记进 tts.md）

1. **本机 git 全局代理把上传挡死了**：`http.proxy = http://127.0.0.1:7897` 而代理没在跑 →
   SDK 建仓时 `git clone` 报 `Failed to connect to 127.0.0.1 port 7897`。
   解法：给命令加 `$env:NO_PROXY="www.modelscope.cn,modelscope.cn"`（只影响该进程，
   **不动用户的 git 配置**）。Windows 上没法用空环境变量覆盖 git 配置（空值会被删掉）。
2. **下载器加 sha256 对账**（用户批准）：ModelScope 清单接口免费返回每个文件的 `Sha256`，
   下载完逐个比对；坏文件**在 `os.replace` 之前**丢弃、半截 `.part` 一起删（不留下次误当续传起点）；
   已就绪且校验通过的文件直接跳过。清单取不到时**降级跳过校验**（只记日志，绝不阻断下载）。
   新增 `tests/test_voice_download_verify.py`（22 项，起本地假仓库跑真实链路，全离线）——
   它当场抓出我一个真 bug：清单 URL 原来用写死的 `modelscope.cn` 做 base，
   用户配**自建镜像**时会跑去魔搭取清单 → sha 对不上 → 下载被误判失败。已改成从模板自身 origin 推导。

### 六、真机抓出的两个 bug（已修 + 已加回归）

1. **`percent` 算出天文数字**：ModelScope 对文件 URL 的 **HEAD 返回 200 但不给 Content-Length**
   → `total` 恒为 0，而调用处写 `total or 1` → `percent = 已下字节×100/1`，真机日志出现
   **`31435628400%`**（UI 只 clamp 了进度条，文字照显）。
   修法：总大小改用清单里现成的 `Size`（还省掉 8 次 HEAD）；只在 `total_hint>0` 时按字节算并 `min(100,…)`；
   UI 再加一道 clamp。真机复验 percent 1→15→38→54→…→100 全合法。
2. **清单 URL 用写死的 modelscope.cn 做 base**：用户配自建镜像时清单会跑去魔搭取 → sha 对不上 →
   下载被误判失败。改成从模板自身 origin 推导；镜像无清单端点 → 404 → 降级跳过校验（安全）。

## 十八、2026-09-18 热更新可行性验证（**只验可行性，未出方案**）

用户问「APP 内热更新（无需重装）可行性如何」。按项目规矩先讨论、且用户明确选了
"先只验证可行性，不出方案"，所以只做了**实测验证**并记录事实，没有设计。

### 一、结论

| 层 | 可行 | 依据（真机实测，非推测） |
|----|------|------------------------|
| 前端 HTML/CSS/JS | ✅ | `STATIC_DIR` 是**真实目录且可写**；`server.py` 用 `SimpleHTTPRequestHandler(directory=STATIC_DIR)`，文件解析完全在我们代码里 |
| Python 业务逻辑 | ✅ | 影子测试 `verdict = filesystem_wins` |
| Kotlin/native（TTS、ORT、WebView 壳、权限、Python 版本、pip 原生依赖） | ❌ | 编译产物 + 权限清单，只能整包 |

### 二、实测方式（零副作用探针，用完已撤除）

`app/api/debug.py` 临时加 `GET /hotupdate-probe`：**只调各 finder 的 `find_spec`**，
不 import、不执行、不改 `sys.modules`；影子文件写在临时目录、用完删除。
验证完撤除 → `check_backend_sync --sync` → 重建装机 → **64/64 测试 + 四门禁全绿**。

### 三、关键数据

1. **安卓下后端是解压成真实目录的**：
   `base_dir = /data/data/<pkg>/files/chaquopy/AssetFinder/app/backend/app`，
   而且 `sys.path[0]` **就是它**（不是 zip）——这解释了 `SimpleHTTPRequestHandler` 为何能工作。
2. `STATIC_DIR = …/AssetFinder/app/backend/app/static`，`static_exists=True`、
   **`static_writable=True`**、34 个文件。
3. 路径钩子次序：`path_hooks[0]=java.android.importer.hook`、
   `[1]=ChaquopyZipImporter`、`[2]=path_hook_for_FileFinder`（资产钩子只对资产路径生效）。
4. **影子测试（核心）**：模块 `routes_update` 在 APK 里的 `origin=…/backend/app/routes_update.pyc`
   （loader `SourcelessAssetLoader`）；把同名 `.py` 放进可写目录并插到 `sys.path[0]` 后
   → **只有 `meta_path[2]`（PathFinder）作答**，返回我们的文件（`SourceFileLoader`），
   **前面没有任何 finder 抢答** ⇒ 胜出者由 `sys.path` 顺序决定。
5. 覆盖层可写往返 ✓（`…/firefly_data/_hotprobe`）。

### 四、两个必须遵守的前提（都是实测得出）

1. **必须在 Chaquopy 初始化之后再插 `sys.path`**：`java/android/importer.pyc` 的
   `initialize_importlib` 里有对 `sys.path` 的**整体重写**（`STORE_ATTR sys.path`）。
   正确时序：`Python.start(AndroidPlatform)` → Chaquopy 重写完 → 我们 `insert(0, overlay)` → 再 import 后端入口。
2. **只对"当时尚未 import 过的模块"生效**（Python 常规行为）⇒ 覆盖层必须最早插，越早越好。

### 五、"能做但不该做"的岔路

探针发现那个 `AssetFinder` 解压目录**可写** ⇒ 理论上可直接改文件。**不要这么做**：
- Chaquopy 官方文档原文：*"Do not write any files to these directories at runtime, as they may be
  deleted when the app is upgraded."*
- 它按 `extract_if_changed`（size/mtime）比对解压，改了文件可能**触发重新解压、把热更悄悄冲掉**。
→ 正解是**自己管理的可写目录 + `sys.path` 插入**（已证明能赢）。

### 六、已知限制

- **服务器模式那份前端副本**（`file:///android_asset/`，本地引擎起不来时的兜底）Python 侧够不着
  ⇒ 热更只覆盖**本地模式**（正常路径）。
- Kotlin 层完全不覆盖。
- Python 热更本质是**远程代码执行**，签名校验 + 坏补丁回退不是可选项（属方案，本次未展开）。

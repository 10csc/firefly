> 完整报告：`docs/设计/0.9.1安全审计.md`｜可复现脚本：`_harden/audit091_sec/`

## 最担心的那一条

**S-1：单 IP、约 70 条半开连接即可把公网入口 8787 完全打停。**
已本机复现 —— 70 条只发半截请求头的连接，就能让所有请求返回 **503 / 连接被重置**，
（含下载页、公告、热更，以及**经反代的所有业务 API**：登录、滚动续期、同步、relay、广场），
关闭连接后立即恢复。它**无需登录、无需域名（IP 直连即可）、成本极低、可无限持续**
（半截请求头稳定占住线程 120s），而且**不会产生 429 也不会触发 `attack_watch` 告警**（它只扫 fail2ban/429/SSH 爆破）。
这是三个新功能的**公共单点**：网关一停，公告、热更、下载、业务 API 一起停。

**有效面（复核后确认没问题）**：广场卡 zip 的校验（zip slip / 压缩比 / 逐槽位图片尺寸 / 哈希 / 重复条目）扎实；
上传只用用户文件名的**扩展名**、落盘名服务端生成；同步与恢复的路径校验三重；`/plaza/api/*` 全部在登录闸门之后；
热更端点在服务器版 403；管理台用 `compare_digest` 且仅回环。

## 与生产的关系（风险叠加）

三个新功能与整包下载**共用 8787 和同一线程池**，所以 S-1 一次触发即同时打断
「下载 / 公告 / 热更 / 业务 API」；手机端遇此会**静默降级**（公告与更新都不抛异常），故障对用户不可见。

## 既有清单复核（仍成立，不重复登记）

- `P2-6` 验证码仍用 `random`（`mail.py:157`）、比较仍用 `!=`（`:190`）。
- `P0-2 / P0-12` 明文 HTTP 仍在（TLS 代码就绪未部署）——本报告多处结论以其为前提。
- `P6-4`（服务器版公告已读跨账号共享）、`P6-14`（热更门禁无补丁时空过）仍成立。

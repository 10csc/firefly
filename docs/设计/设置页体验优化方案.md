# 设置页与默认值体验优化方案（研究报告）

> 状态：**已按本方案实施 P0+P1**（默认值/静默窗修复 + 设置页分组重构 + 两档模型预设 + 自动保存）；待真机验收。
> 结论先行：**设置页不是“功能少了”，而是“信息层级塌了”。** 把 onboarding、日常开关、极客调参、系统维护四类内容平铺在一个长面板里，默认又全部展开，新用户看到的是 26 个标签 / 11 个下拉框 / 10 个输入控件的“驾驶舱”。
> 同时存在一个真实缺陷：**概率式主动回复默认 30% × 每 10 秒轮询**，实际效果约等于“空闲不到一分钟她就会再发一条”，与“偶尔想起你”的产品文案完全不符。

---

## 一、现状量化

设置面板（`#settings-panel`）静态统计：

| 控件 | 数量 |
|------|------|
| `<select>` 下拉框 | 11 |
| `<input>`（含滑条/复选框/文件） | 10 |
| `<button>` | 7 |
| `field` 分组 | 15 |
| `<label>` | 26 |
| 默认展开的 `<details>` | 3 个（模型高级折叠、主动性展开） |

内容平铺顺序：运行模式 → API 来源 → Key → 接口地址 → 模型×4 → 思考档位×4 → 温度 → 主动性 3 开关 3 滑条 → 界面大小 → 版本更新 → 数据备份 → 退出 → 一个在页面最底部的【保存】。

**问题**：
1. 一个面板混合四种用户任务：首次配置、日常偏好、极客调参、系统维护。
2. 新用户只需要“填 Key → 聊天”，却必须穿越 14 个高级字段才到保存按钮。
3. 主开关与高级滑条同级：`主动式/概率式/隐藏式` 三个术语直接暴露，和之前《三版本 APP 缺陷分析》中“设置面板名词轰炸”的问题一致（当时只做了高级模型折叠，主动性自然语言化未做）。
4. 保存按钮在长面板最底部，改动后无“已保存”反馈；滑条/开关和 Key 共用一次提交。
5. PC 本地版显示“隐藏式回复”（仅安卓后台有效），造成无效开关；本地版与服务器版的条件显隐还不够彻底。

## 二、默认值问题（实测代码）

### 2.1 概率式主动回复：默认值其实“几乎必触发”

链路：前端空闲时每 10s `POST /proactive-status`，服务端 `prob_gate_open` 用 `prob_reply_value=0.3` 掷骰。

- 概率 0.3 / 10s 的期望触发时间 ≈ 33 秒；
- 只要用户聊完天后停留在聊天页（没输入、没等待），大概率 **1 分钟内**收到第二条主动消息；
- 页面明明写着“用户在应用内但空闲时，流萤**偶尔**想起你”——“偶尔”实际是“很快”。

代码里定义了 `_PROB_QUIET = 10 * 60 * 1000` 与 `_PROACTIVE_QUIET = 2 * 60 * 1000`，但 `checkProactive()` **没有使用**，是死代码。这是最需要修的默认值缺陷。

### 2.2 三个主动通道全部默认开启

| 通道 | 当前默认 | 实际体感 |
|------|------|------|
| 主动式 | 开，每 4 轮 1 次机会，50% 触发 | 约每 8 条用户消息收到 1 次主动消息，偏频繁 |
| 概率式 | 开，30%/10s 轮询 | 空闲 1 分钟内几乎必触发（问题 2.1） |
| 隐藏式 | 开，后台 10–30 分钟，30%×时段权重 | 傍晚约 12%/次，后台通知对首次用户偏“主动” |

**建议原则**：主动式是核心人设功能应保留；概率式/隐藏式应是**可选增强**，新用户默认关闭，或在引导中明确邀请开启。外部同类产品（如 Friendify 的 proactive check-ins）也把主动消息做成 explicit opt-in，而不是默认轰炸。

### 2.3 其他默认值与文案不一致

| 项 | 现状 | 建议 |
|------|------|------|
| 思考档位选项 | UI 提供 `low`，并注明“=高，官方映射” | 从 UI 移除 low（后端仍兼容旧配置），只留 `none / high / max` |
| 回复器温度 | UI 写“固定 0.5”，但后端 config 有 `polisher_temperature` 且 `set_config` 可改 | 要么隐藏文案并移除该配置入口，要么给真实说明；当前是“声称固定但实际可被配置” |
| 检索器温度 | 高级区仍暴露 0–2 滑条 | 收进“极客/自定义”层，默认不展示 |
| 隐藏式回复 | PC/服务器网页也显示 | 仅安卓（或明确标注“仅安卓 App 后台”）展示 |
| 组织器思考档位 | 显示“默认无思考”，但 haruno 旁白代码强制 Think High | 文案改为“剧情模式无思考；春日手信旁白固定思考” |
| API 接口地址 | 基础区展示两个端点 | 收进“高级”，普通用户只留默认 DeepSeek 官方 |

## 三、目标信息架构

```
⚙ 设置
├─ ① 账号与连接（默认展开，唯一首次必填区）
│   运行模式（仅安卓）
│   API 来源（仅服务器模式）
│   API Key + 三步获取引导
│   ▸ 高级：接口地址
│
├─ ② 主动消息（默认收起，自然语言化）
│   让流萤主动找你：从不 / 偶尔 / 经常
│   空闲时想起你：开关（默认关）
│   后台提醒我：开关（默认关，仅安卓显示）
│   ▸ 高级频率（原 hard/soft/prob 数值，仅高级用户）
│
├─ ③ 模型与速度（默认收起）
│   回复质量：快速（默认）/ 更强
│   ▸ 自定义各阶段模型与思考档位（原 8 个下拉框收这里）
│
├─ ④ 外观（默认收起）
│   界面大小滑条（原样）
│
└─ ⑤ 数据与系统（默认收起）
    版本 / 检查更新
    数据备份 / 导入 / 账号同步
    退出（仅 PC）
```

保存策略：
- Key / 接口 / 运行模式：显式【保存】按钮（敏感、低频）；
- 其余开关、滑条、质量档位：**改动即保存**（防抖 300ms），并显示“已保存 ✓”。

## 四、建议的新默认值

| 配置项 | 当前默认 | 建议默认 | 理由 |
|------|------|------|------|
| `proactive_enabled` | true | **true** | 保留核心体验 |
| `proactive_hard` | 4 | **6** | 从“约 8 条一次”降到“约 12–15 条一次”，更像真人节奏 |
| `proactive_soft` | 0.5 | **0.35** | 降低主动式密度，避免抢戏 |
| `prob_reply_enabled` | true | **false** | 空闲主动改为 opt-in，避免聊天页 1 分钟内二连 |
| `prob_reply_value` | 0.3 | **0.10**（开启后） | 且必须补上 10 分钟静默窗，语义回到“偶尔” |
| `hidden_reply_enabled` | true | **false** | 后台通知 opt-in；新用户首次用后台消息时引导开启 |
| 思考档位 UI | 含 low | 移除 low | 官方 low 即 high，保留是误导 |
| 概率式静默窗 | 未生效 | `_PROB_QUIET=10min` 真正接入 | 修复“30%×10s 轮询”缺陷 |

对老用户：已写入 config.json 的旧值**不强制改**（尊重用户现有选择）；只影响新建 config 与 UI 默认显示。可加一个“恢复推荐设置”按钮，方便一键回到推荐值。

## 五、实施阶段

### P0：默认值与静默窗修复（小，高收益）
1. `app_config._load_config` 默认值改为上表；
2. 前端 `checkProactive()` 接入 `_PROB_QUIET`：距上次渲染不足 10 分钟不检查概率式；
3. `prob_gate_open` 注释/文案同步“偶尔=约 10 分钟静默 + 10% 概率”；
4. 隐藏式开关仅安卓显示（`/config.platform` 已具备）；
5. UI 移除 `low` 选项，修正组织器/温度误导文案。

### P1：设置页信息架构重构
1. 五个分组卡片 + 默认只展开“账号与连接”；
2. 主动消息自然语言三档（从不/偶尔/经常）映射到现有三个配置；
3. 模型区两档预设（快速/更强）+“自定义”展开原字段；
4. 开关/滑条改动即保存，Key 保留显式保存；
5. 保留全部现有配置字段与 API 兼容，老配置无迁移成本。

### P2：细节打磨
1. 保存反馈与错误提示；
2. “恢复推荐设置”按钮；
3. 服务器/本地条件显隐整理（托管额度、同步、退出等）；
4. 移动端窄屏下设置面板头部 sticky 保存状态；
5. 与新的首次使用引导教程联动：引导第 2 步只指向 Key，不再让人看全页。

## 七、外部依据（节选）

- [Onboarding Settings vs Ongoing Settings](https://setting.page/onboarding-settings-vs-ongoing-settings)：设置页应区分“首次配置”与“日常调整”，并默认隐藏后者——本项目正属于两类内容平铺。
- [When your settings page becomes the product](https://dev.to/tanya-donska/when-your-settings-page-becomes-the-product-1824)：暴露过多实现细节会让设置页反客为主；模型/effort/温度属于实现细节，应默认折叠。
- [Friendify Character Check-ins](https://www.friendify.net/features/proactive-messages)：同类 AI 角色产品的主动消息采用明确开关/opt-in 而非默认高频触发。
- [Nomi Wiki: When Your Nomi Messages You First](https://wiki.nomi.ai/index.php?title=When_Your_Nomi_Messages_You_First)：主动消息频率是用户对 AI 伴侣产品的主要感知之一，频率设置应以“人话”呈现而非轮次/概率数值。

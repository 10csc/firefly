# 角色卡共创平台 · 03 客户端实现

> 依赖：01（卡格式）、02（服务器端点）。状态：**M1 已实现并通过真浏览器验证**（见 §六）。

## 一、两种客户端模式，一套前端代码

前端**只调相对路径**（`/plaza/api/...`），由后端决定"谁来回答"：

| 模式 | 谁实现 | 怎么实现的 |
|---|---|---|
| 服务器模式（App 连服务器） | 服务器（8765，经 8787 反代） | `plaza/api.py` 直接读服务器上的广场库 |
| 本地模式（App 自己跑后端） | **代理**到认证服务器 | 本地后端带 `auth_store` 的 token 转发（与 A7 的 `/auth/*` 代理同一先例） |

因此**没有 CORS / `file://` 问题**，两端共用同一份前端。

**例外——安装/卸载不代理**：它们改的是"本人的聊天数据根"，
服务器模式写该账号的 `user_data/{uid}/`、本地模式写本机 `user_data/`，
所以由**本端**执行（`/plaza/api/installed|install|uninstall` 三个端点不走代理）。

> 前端取图必须 **`fetch` + `URL.createObjectURL`**（`<img src>` 不会带 Authorization 头）。
> 详见 `docs/错误总结.md` #19：这条链路上曾有一个"看不见的 bug"——属性选择器写错，
> 导致**一张封面都不加载**，只有真浏览器端到端才抓得到。

## 二、安装链路（`app/plaza/install.py`）

```
取卡体  →  完整校验（01 文档 §三）  →  只写 character/ 子树  →  登记 packs.json  →  reload_presets()
```

- **取卡体**：服务器模式读本机广场库；本地模式 `GET {auth_server}/plaza/api/download?id=`
  （带 token；401 → "请先登录"，404 → "卡片不存在"）。
- **只写 `character/`**：绝不创建/覆盖 `data/`、`journal/`、`images/`（用户数据铁律）。
- **覆盖安装前留档**：旧包目录整体拷到 `{用户根}/backups/plaza/{id}-{时间}/`。
- **剥离 `knowledge_dirs`**：卡片的 `preset.json` 里若声明了仓库内相对目录，
  `_clean_knowledge_dirs` 是**允许**的 —— 那等于让"别人发布的卡"指挥**你的**检索器去读仓库内任意目录
  并注入提示词。安装时强制清空该字段（`_sanitize_preset`），并只落白名单内的文件。
- **覆盖时清理旧文件**：卡里已不含的槽位文件会被删掉，避免"改了封面却还显示旧图"。

**配额（仅服务器模式，D1 决策）**：每人 ≤5 张、总量 ≤8MB。
本地模式不限额（用户自己的磁盘，且本地版本来就能自建任意数量的包），前端也不显示配额条。

## 三、流量与体验纪律（服务器只有 3Mbps）

| 手段 | 做法 |
|---|---|
| 图片 | `fetch` + `blob:`、**懒加载**（IntersectionObserver，`rootMargin: 320px` 提前取）、滚出视野即释放、**关闭面板 revoke 全部并清空缓存**、会话内按 URL 去重（同一张图只下一次） |
| 列表 | 每页 20 条、滚动触底或「加载更多」追加；**列表响应不含卡正文** |
| 搜索 | 350ms 防抖 + `AbortController` 掐掉旧请求（避免"慢的旧响应覆盖新结果"） |
| 轮询 | 该模块**零定时器、零轮询**（与 relay 的 4s 轮询形成对比） |
| 图片体积 | 上传前用现有的 `imgzip.js` 压缩；服务端另有 ≤300KB/≤120KB/≤1.5MB 三重硬上限 |
| 静态缓存 | 封面/头像 `Cache-Control: public, max-age=86400` + `ETag`/304；本地模式代理也会转发 `If-None-Match` 并原样回 304 |

### 实测预算（2026-10-01，`tests/test_plaza_budget.py` 16 项）

以前只有**结构性上限**（封面 ≤300KB 之类），没有一条实测数字。现在起这条需求有量化验收：
真实服务器进程 + 21 张卡（每张约 40KB 正文 + 一张 **151KB 的真实 JPEG 封面**）实测——

| 动作 | 实测 | 预算 |
|---|---|---|
| 列表一页 20 张（JSON） | **10.5KB** | ≤40KB |
| 列表里**不含卡正文** | 断言通过（正文标记 0 命中） | 必须 |
| 详情（`/plaza/api/card`） | **550B** | ≤16KB |
| 封面首次 | **151KB**（= 原图） | ≤300KB |
| **封面二次请求** | **304，正文 0B** | 必须为 0 |
| 卡体 `card.zip` | **10.9KB** | ≤1.5MB |
| 安装接口响应 | **97–146B** | ≤4KB |
| `/modes`（21 张卡） | **1.1KB** | ≤32KB |
| **一次「浏览 + 看封面 + 安装」合计** | **173KB** | ≤1.7MB |

两条结论（第一条是**实测推翻了设计直觉**）：
1. **图片才是主要流量**：151KB 封面占 173KB 的 **87%**，而文本卡体被 zip 压到只 10.9KB
   —— 所以"控制流量"的第一抓手是**封面尺寸与懒加载**，不是卡体。
   本测试第一版写的是"卡体应占 ≥80%"，**被实测当场证伪**（已改为下面第二条口径）。
2. **元数据近乎不花钱**：列表 + 详情 + 安装响应合计只占 **6.4%**；图片 + 卡体占 **93.6%**
   ⇒ 字节都花在用户真正要的数据上，翻页/安装这些操作本身不吃带宽。
3. 封面第二次请求走 304 ⇒ 同一会话里来回翻页**不重复付费**（配合前端 350ms 防抖 + `blob` 去重）。

## 四、前端结构

- `app/static/js/panels/plaza.js` —— 广场整页（列表/筛选/详情/安装/卸载/配额），
  入口在**角色卡管理页头部**的「✦ 角色卡广场」（与角色包管理同域，不另起导航）。
- `app/static/index.html` —— `#plaza-view` 整页 DOM；`app/static/style.css` / `pc.css` —— 样式（移动端单列 / PC 三列）。
- 新增 js 文件**必须**登记进 `tools/build_frontend_bundle.py` 的 ORDER，然后
  `build_frontend_bundle.py` → `sync_frontends.py`（三副本）→ 两个 `--check` 门禁。

## 五、错误与空态

- **401** → 「广场需要登录后才能浏览」+「去登录」引导（产品决策：广场完全登录可见）；
- 网络/HTTP 错误 → 人话文案 + 重试；
- 空态区分"无结果"与"广场还没有卡"，可一键清除筛选；
- 安装失败直接用后端返回的中文原因（例：`已安装同名角色卡…` → 提供「覆盖安装」入口）。

### 装完到底能不能"用起来"？——`tests/test_plaza_use_card.py`

需求原话是"**下载并使用**角色卡"，但此前只验到"装进本人目录 + `/modes` 里出现"。
这一测补上"使用"，且**零模型费用**（把唯一会调 LLM 的流水线入口 `handle_chat` 桩掉，
于是能验真实的**编排与落盘**行为而不产生任何 API 调用）：

| 断言 | 结果 |
|---|---|
| 本地模式安装走的是**认证服务器 HTTP**，且**带上了登录态**（桩收到 `Bearer tok-e2e` 与正确的卡 id） | ✅ |
| 装完成为一等模式，角色名取自卡上的 `preset.json`（`卡上角色名`） | ✅ |
| 该模式的**角色定义目录**里就是这张卡的 `core.md`（标记命中）⇒ 装完真会被读作角色设定 | ✅ |
| 以该模式发消息 → 流水线收到的 `mode` **就是这张卡** | ✅ |
| 消息落在**该卡自己的**会话文件；**默认模式里没有它**（按角色隔离数据） | ✅ |
| 卸载后不再出现在模式列表（不留残影） | ✅ |

两者都自建沙箱数据根（`FIREFLY_DATA_DIR` + `FIREFLY_PLAZA_DIR`），
端口被占直接退出 3、**绝不误杀真实进程**，也不连任何外网。

## 七、制卡页与图片规格（P4-7c，契约 06 的前端落地）

制卡页（`js/panels/plaza_forge*.js`，五个文件）已从"固定几栏"升级为**自由编辑器**：

- **文本**：固定三件 `core.md`/`identity.md`/`sms_samples.md`（≤64KB/份），外加 **1..6 份知识库**，
  两种路径都能编：`knowledge/<名字>.md`（扁平）与 `knowledge/<域>/<名字>.md`（**一层分组**，域可空、
  可自定，建议值 world/factions/story/character/dialogues）；开场白 `opening.narrations` /
  `opening.first_messages` 条目可自由增删。**文本只在保存那一刻随 payload 全量提交**。
- **图片**（客户端先压好、服务端复核；超限**不收**）：

| 槽位 | 列表用？ | 长边 | 体积上限 | 说明 |
|---|---|---|---|---|
| `thumb` | **是（列表只发它）** | ≤320px | **≤12KB** | 必填；列表 JSON 只给它的地址 |
| `avatar` | 否（列表用 thumb 即可） | ≤256px | ≤30KB | 小圆头像 |
| `display` | 否（**详情才拉**） | ≤1024px | ≤300KB | 详情大图 |
| `sticker-N` | 否（详情/用卡时按需拉） | ≤160px | ≤20KB ×**≤8 张** | 每张可带 `label`（≤12 字，**建议填**） |

- 压缩：复用 `imgzip.compressImage` 打底，再**先尺寸后质量**逐级降（webp 优先、jpg 兜底，
  档位 1/0.78/0.6/0.46/0.34）；UI 实时显示**每张**的 KB 与上限。**硬线只有两条**：
  单张 thumb ≤12KB、列表响应 ≤60KB（不卡"一屏合计"）。
- **列表/详情分流**：`GET /plaza/api/list` 只用 `thumb`（老卡无 thumb 才退 `cover`）——
  真浏览器脚本按网络层断言"列表阶段 0 条 display/avatar/sticker 请求"；`GET /plaza/api/card`
  才带 `display`/`avatar`/`stickers`（`stickers` 是 **`[{file,label}]`**；标签来自发布时存进 meta 的
  `sticker_labels`，老卡 `label` 为空串 —— 消费方按对象读，别再按字符串数组写）。
- payload（契约 06 §3.2）：`{display, card:{…元数据…, opening:{narrations,first_messages},
  files:[{path,text}], images:{avatar,thumb,display,stickers:[{data,label}]}}}`；旧平铺字段
  （`core`/`identity`/`sms_samples`/`cover`/`avatar`）**前端也吃**（老草稿兜底）。
- **老草稿迁移闸门**（2026-10-01）：V1 之前的草稿没有 `thumb`（或把大 cover 当 thumb）⇒ 直接保存会被
  后端 `CARD_MISSING_THUMB` 拦。加载草稿后前端**就地压一张 ≤320px/≤12KB 的 thumb**（源：display →
  avatar → 原 thumb）并提示"这张草稿是旧格式，已自动生成列表缩略图"；**一张图都没有**的老草稿则明确
  提示"列表缩略图是必填（≤320px/≤12KB）"并拦住保存，**不拿后端 400 当唯一反馈**。
- 真浏览器证据：`tests/manual_plaza_forge.py`（真后端 存草稿→审核→发布→下架 33 项）与
  `tests/manual_plaza_forge_free.py`（知识库增删/分组、8 表情包+label、超限拦截、列表只拉 thumb、
  保存↔继续编辑往返、老草稿两条迁移路径，42 项）。

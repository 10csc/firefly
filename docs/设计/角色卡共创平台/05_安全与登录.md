# 角色卡共创平台 · 05 安全与登录（无域名前提下的传输加固）

> 决策（用户 2026-10-01 拍板）：**走 A 路线**——免费 IP 证书 + 标准库 TLS 终止，双端口灰度兼容；
> 服务器变更**随 0.9.1 整包发版**，必须兼容到"旧客户端全部升级完"为止。用户原话：**安全无小事**。

## 一、为什么不能靠现有"信封"（全部有代码证据）

现有 `app/session_crypto.py` + `app/static/js/session_crypto.js` 是应用层加密信封
（RSA-2048 + OAEP-SHA256 包内容密钥，keystream = HMAC-SHA256，明文尾附 SHA-256 摘要），
但它**不足以承担登录安全**：

| 缺口 | 证据 |
|---|---|
| 只保护 3 个请求头（Authorization / X-API-Key / X-API-Base），**Body 完全不覆盖** | `app/session_crypto.py:41`、`app/static/js/session_crypto.js:34` |
| **无 nonce / 时间戳 → 抓到一次信封可原样重放**，服务器解出 Bearer 即认账 | `session_crypto.js:8` 自述"防重放属第二步，本版不做" |
| 登录/注册/改密是**明文 JSON Body**（登录页根本没引 `session_crypto.js`） | `server/frontend/login.html:206,342-386` |
| CORS 白名单未列 `X-Firefly-Enc`（两处：`app/shared_http.py:85-86`、`server/download_server.py:364-365`）。**2026-10-01 复核：影响面比原先估计的小得多**——<br>① **本地模式不是活缺陷**：PC exe 与安卓内嵌 WebView 都从 `http://127.0.0.1:8765` 加载页面（`MainActivity.kt:63`、`app/shared_http.py:108-117` 文档注释明确"不存在合法的跨源本地前端"）⇒ **同源，根本不触发预检**；<br>② **只有安卓的"服务器回落模式"（`file://` 页面 + 远端 8787）才真会预检**，该模式若启用信封就会失败——所以这仍是一条**该补的 1 行补丁**，但严重度从"安卓上线即坏"降为"某一条回落路径下的信封不可用" | 原判据 `server/download_server.py:364-365`、`app/shared_http.py:85-86`；本次复核证据 `app/shared_http.py:108-117`、`android/.../MainActivity.kt:63` |
| 无 `X-Frame-Options`/CSP/Referrer-Policy → 登录页可被 iframe 套壳 | 全仓零命中 |
| 未部署（ENABLED/REQUIRED 默认关，失败退明文） | `app/session_crypto.py:56-67`、`docs/未完成事项清单.md:38` |

结论：信封只能算"防同网段偷看"的过渡手段，**防不住主动 MITM、防不住重放**。

### 授权边界（2026-10-01 实测，**应用层这一层是好的**）

TLS 解决的是"路上被看"，**授权**解决的是"没登录能不能动手"。这两件事必须分开验：

| 验收点 | 结果 |
|---|---|
| **未登录**访问广场 **17 个端点**（8 读：list/card/asset/download/installed/drafts/draft/admin-list；9 写：install/uninstall/review/draft/draft-delete/publish/unpublish/report/admin-status） | **全部 401**（`tests/test_plaza_server_e2e.py` 第 8 节，真实服务器进程 + 真实会话表） |
| 管理端点只认 `admin` 角色 | 普通账号 **403**，admin **200** |
| **普通用户能否自称"官方"**：在 `POST /publish` 载荷里塞 `official: true` | **不能**。落盘 `author.official` 仍为 `False` —— 该字段由服务端按**已认证用户的 role** 推导（`plaza/drafts.py:209,222`），**从不读载荷** |
| 正对照：admin 发布 | `author.official = True`（证明上一条不是"永远为假"） |
| 作者身份 | 落盘记的是**发布者自己**的 `uid_hash`，不是别人的 |

> 另有两条结构性安全边界（已在 M1/M2 实现并测试）：① 用户**不能**提交自己的 `preset.json`
> （否则可塞 `knowledge_dirs` 改变运行时），由 `plaza/api.py::_card_zip_from_payload` 服务端组装；
> ② 发布闸门校验"审核结论 + 卡体摘要一致"（防"审 A 发 B"），admin 免审但**留痕**。

## 二、A 路线：Let's Encrypt **纯 IP 证书** + 标准库 TLS

关键新事实：**LE 自 2026-01-15 起为纯 IP 地址签发证书**，无需域名、无需备案标识、免费，
`shortlived` 档 160 小时（≈6.7 天）自动续期；挑战方式 HTTP-01 或 TLS-ALPN-01（DNS-01 无法验证 IP）。
依据：<https://isrg.org/post/ip-and-6day-general-availability/>、
<https://letsencrypt.org/docs/profiles/>、<https://letsencrypt.org/docs/challenge-types/>、
<https://letsencrypt.org/docs/rate-limits/>。

方案要点：

1. **TLS 终止在网关**（8787 那个进程），用 Python **标准库 `ssl`**——不引任何第三方库
   （符合项目"能自己实现不引库"铁律）；ACME 客户端用 **acme.sh 单脚本**（单文件 scp 友好）。
2. **双端口灰度**：`443 = TLS`，`8787 = 明文`保留给旧客户端；两者同一进程、同一套限流与业务。
3. **客户端不内置任何密钥**——这是 A 优于"自签 + 固定"的关键：换证书/续期不需发版。
4. **挑战方式优先 TLS-ALPN-01（443）**，避开 80 端口与"未备案域名"策略的不确定性。
5. 上线顺序（每步可回滚）：
   - ① 本地 + 服务器**临时端口**跑通 TLS 与 ACME（**staging 环境先验证**，不碰生产）；
   - ② 443 上线 TLS，8787 原样保留；`https://IP/healthz` 自检 + 旧链路回归；
   - ③ 0.9.1 发版，客户端默认 https（旧客户端不动）；
   - ④ 监控续期；确认旧客户端占比归零后，抬 `min_supported` 退役明文。

## 三、兼容策略（用户明确要求"做好兼容"）

- **旧客户端（≤0.9.0）**：继续 `http://101.200.14.126:8787`，**行为零变化**——这是双端口的意义。
- **新客户端（0.9.1）**：默认 `https://101.200.14.126`；若配置里仍是官方主机 + 8787，**自动升级为 https**；
  自建服务器地址**绝不**自动改写（只对官方主机生效，避免把别人服务器改坏）。
- **退役门槛**：`server/update.json` 已有 `min_supported` 字段（`server/update_manifest.py:128`），
  等明文端口不再需要时抬高它即可；**只有到那一步才需要考虑强制更新**，本轮不需要。
- 安卓 `usesCleartextTraffic` 在灰度期保持 `true`（否则旧地址直接不可用）；全量 https 后再改 `false`
  （`docs/构建规范.md:111-127` 的 APK 门禁会检查这个值，改时同步基线）。

## 四、落地清单（文件级）

**新增/修改（2026-10-01 修定：TLS 不单开进程，直接做进网关，用环境变量开关）**
- `server/download_server.py`：
  - `tls_ready() / make_tls_context() / cert_info()` + `start_tls_listener()`；
  - `FIREFLY_TLS_PORT` **默认 0（关闭）**，配了端口且证书/私钥都在才开第二个监听；
    两个监听**同一进程、同一 Handler、同一套限流**；
  - TLS ≥1.2；监听 socket 设握手超时（握手在 accept 里单线程发生，不设超时会被慢握手卡住）；
  - **证书配错只告警，绝不影响明文端口**（灰度期明文是兜底）；
  - `FIREFLY_BIND` 可改绑定地址（默认 `0.0.0.0`；测试用 `127.0.0.1` 不对外暴露）；
  - 新增 `GET /download/tls`：**仅本机可访问**，报 `enabled/loadable/not_after/days_left/warning`
    （`days_left < 10` 出告警），供 systemd 健康检查与 `attack_watch` 巡检 —— 直接对应
    "6 天证书续期失败 = 全站不可用" 这个可用性风险。
- `tools/cert_renew.sh`：`acme.sh --issue -d <IP> --certificate-profile shortlived --alpn` + `--reloadcmd`。
- `/etc/cron.d/firefly-acme`（或 systemd timer）：每日 `--cron`；**续期失败必须进 alarm 告警**。

**本地已验证（不涉及部署）**：`tests/test_server_tls.py` **20/20 绿** —— 自签证书下
TLS1.3 握手、TLS 下完整下载与 Range 续传、明文端口并存、**证书配错时明文仍能完整下载**、
不配 `FIREFLY_TLS_PORT` 时行为与改造前完全一致、`/download/tls` 报出到期天数。

**修改**
- `server/download_server.py`：main 支持双端口；`do_OPTIONS` 的 Allow-Headers 补 `X-Firefly-Enc`。
- `app/shared_http.py`：CORS Allow-Headers 补 `X-Firefly-Enc`；响应头加 `X-Frame-Options: DENY`、
  `Referrer-Policy: no-referrer`。
- 官方地址单点改 https：`server/frontend/config.js`、`server/frontend/js/api.js`、`.../update.js`、
  `android/app/src/main/assets/config.js`、`server/mail.py` 中的链接——改完必须
  `python tools/build_frontend_bundle.py` + `python tools/sync_frontends.py`（三副本一致）。
- 客户端默认地址与"官方主机自动升级 https"逻辑（本地版/服务器版共用）。

**不做/保留**
- 现有 `session_crypto` 信封代码**保留但停用**（TLS 上线后不再启用 `FIREFLY_ENC_ENABLED`），
  避免长期维护两条安全路径；CORS 的 `X-Firefly-Enc` 补丁仍要打（万一回退到信封）。

## 五、诚实边界（不吹）

1. IP 证书**拿不到 HSTS**（HSTS 不适用于 IP）→ 首次必须靠**客户端写死 https**，仍存在手输 http 的降级窗口。
2. 证书 **6 天续期**：续期失败 = 全站不可用 → 必须有监控 + 过渡期保留明文兜底。
3. 阿里云对"纯 IP 未备案"在 80/443 的实际策略**未核实**（社区实测 `https://IP` 未被拦）→
   **上生产前先用 staging + 临时端口实测**，这是本方案唯一未验证项。
4. 服务端仍是明文可见（设计前提）；"Body 带用户 sk"这一风险面依旧存在，因此审核链路必须**审完即焚**。
5. 上 TLS 不解决：设备被控、用户被诱导装根证书、服务器被入侵后的数据。

## 六、与共创平台的关系

- `/plaza/api/*`（含提交 sk 的审核接口）**全部在 TLS 覆盖范围内**，无需单独加密；
- **不得新增任何"Body 放密码/Key"的明文入口**（这是 00 文档 §九 的硬约束）；
- 制卡表单的封面/头像上传同样走 TLS；上传体积上限见 01 文档。

## 七、服务器对外面（架构约束，2026-10-01 用户纠正）

> **服务器只做后台：只提供登录页 + 角色卡平台 + 客户端 API；不提供 App 前端**
> （无 `index.html` / App bundle / App 样式 / App 面板）。

- **为什么是安全项**：App 前端公开可下 = 任何人都能把服务器当"网页版 App"用（还附赠 `X-Firefly-Enc`
  加密头库与全套面板源码），并把服务器带宽变成 App 分发通道 —— 与"服务器仅作后台"的定位直接冲突。
- **两层防线**：① `server/app.py` 显式闸门（App 壳 `/`、`/index.html`、`/index`、`/app.html`
  ⇒ **302 → `/login.html`**；`/style.css`、`/pc.css`、`/js/*`（平台白名单外）⇒ **404**），
  **即使文件还在 frontend/ 也挡得住**；② 部署时用 `_harden/move_app_frontend.sh` 把文件搬走
  （只搬不删、可回滚；**保留** login/admin/bg-sunset/config/platform.*）。
- **白名单与黑名单显式分开**（别用"App 一律挡"扫到登录入口）：白名单 = `/login.html`、`/login`、
  `/platform.html`、`/config.js`、`/bg-sunset.css`、`/admin.html`（token 闸在 8766）、平台前缀
  `/platform*`、`/js/platform*`、`/js/panels/plaza*`；其余静态文件**默认拒绝**。
- **自查**：`python tools/check_server_surface.py --base http://<公网IP>:8787 --gateway --strict-platform`
  —— 逐条打状态码+字节数+期望，并把 `server/frontend` 与 `app/static` 的 App 文件**全量枚举**断言不可达；
  判定一律 **GET**（本服务不支持 HEAD）。
- **API 一条都不许减**：`/health`、`/version.json`、`/update-manifest`、`/plaza/api/*`、`/auth/*`、
  `/modes`、`/config`、`/notice`、`/hotupdate/*` 等行为不变（基线见 `_harden/server_surface_baseline.json`）。
- **`/assets/*` 保留（查证后不收紧）**：客户端**服务器模式**要用它取图 —— `app/static/js/util.js::stickerSrc`
  拼 `apiBase + "/assets/" + file`，调用点 `js/panels/packs.js`、`js/panels/stickers.js`、`js/chat_render.js`，
  `test_plaza_use_card.py` 的 `/assets/character/…` 同路。安全上：该分支在**鉴权之前**、无用户上下文
  ⇒ 只解析全局/bundled 资产，不含任何账号数据。
- **版本冻结**：线上 `v0.9.0` 未发布 ⇒ 部署 `server/app.py` 时**只带 `server/update_manifest.py`**（硬依赖，
  `/version.json` 用；漏传时已做容错：退回直出静态 `server/version.json`），**绝不带 `server/update.json`
  / `server/version.json`**；`--gateway` 的 **B2 版本冻结核查**逐字节比对 `/version.json`(206B)、`/health`(27B) 并打印 tag。
  - 冻结期的**正常现象**：`/update-manifest` 返回 **503**（`update_manifest.load()` 对缺失 `update.json`
    返回空清单，日志 `update.json 不存在 —— 检查更新将回退 version.json`）——客户端此时读 `version.json`。
    **发版前置动作**：只有正式发布那次才随 `update.json` 一起部署，届时该端点应为 **200**（矩阵期望已写成 `{200, 503}`）。
- **`GET /auth/state` 回带 `role`**（2026-10-01 收口）：已登录时响应含 `role`（`admin` / `user`），来源
  优先级 = **本次 `/auth/verify` 现算的 role** > 本地 `auth.json` 里登录时存的那份（`save_login(..., role=)`）
  ⇒ **离线宽限期内也能判断是不是管理员**。未登录口径不变（`logged_in=false` + 字段为空串，只是多一个
  `role`）；服务器模式下 `/auth/state` 仍是 403「请用 /auth/me」，**判定未改**。
  为什么需要：clientpack 实测本地模式拿不到 role ⇒ 前端只能把"官方卡"勾选框整块隐藏。
  回归：`tests/test_auth_state_role.py`（8 项）。

# 角色卡共创平台 · 02 服务器端实现

> 依赖：[01 角色卡格式](01_角色卡格式与校验.md)（卡归档契约）。状态：**M1 已实现并测试**（M2 起为设计）。

## 一、数据根与布局

```
/opt/firefly/plaza/                     # FIREFLY_PLAZA_DIR，缺省 {USER_DIR.parent}/plaza
  cards/<card_id>/card.zip              # 卡本体（唯一真相源）
  cards/<card_id>/meta.json             # 广场侧元数据（状态/作者/分类/标签/下载数/体积/摘要）
  assets/<card_id>/thumb.<ext>          # 列表用小图（V1：列表**只**发它）
  assets/<card_id>/display.<ext>        # 详情大图
  assets/<card_id>/avatar.<ext>         # 头像
  assets/<card_id>/sticker-1..8.<ext>   # 表情包
  assets/<card_id>/cover.<ext>          # 老槽位（M1；V1 列表不用，仅存量卡兼容）
  _index.json                           # 两级索引缓存的落盘文件（**扫描根之外**）
  audit/<card_id>.jsonl                 # 治理/审核流水（**永不写 API Key**）
```

**口径纪律**（`docs/错误总结.md` #10）：**目录是唯一真相源**，不另存一份清单索引——
多一份清单就多一个会漂移的口径。`meta.json` 读不到或 `card.zip` 缺失都只跳过并告警，
绝不让一张坏卡把整个广场变成 500。

**但"卡量级很小"这个假设在 2026-10-01 被实测推翻**（`tests/test_plaza_scale.py`）：
`list_cards` 每次请求对**每张卡**要做三件 I/O —— 读+解析 `meta.json`、`stat card.zip`、
以及 `_public_view` 里查 cover/avatar 的**两次目录列举**（`_find_asset`）⇒
**480 张卡 p95 451ms**（设计验收 300ms），趋势 4.58×/4× 规模，纯线性扫描。

**对策：两级索引缓存**（`app/plaza/cache.py`，由 `store.py` 用 `configure()` 注入扫描/路径函数，
缓存模块**不 import store**，避免循环依赖）——

| 级别 | 载体 | 开关 | 作用 |
|---|---|---|---|
| 内存短 TTL | 进程内存 | `FIREFLY_PLAZA_INDEX_TTL`（默认 2s，`0` = 全关） | 把"**每个**请求都慢"变成"每 TTL 一次慢" |
| 落盘索引 | `plaza_root()/_index.json` | `FIREFLY_PLAZA_INDEX_FILE_TTL`（默认 **300s**，`0` = 全关） | 把"每 TTL 一次慢"也压掉：冷读只花 一次 `stat` + 一次计数 + 一次 JSON 读 |

- 缓存三件东西：`(目录名, meta, zip_mtime)`、**各图片槽位文件名**、以及扫描根目录的 mtime。
  ⚠ **资源名必须一起缓存，且一次拿全**：只存 meta 时，480 张卡冷读仍要上千次 `iterdir`（≈260ms）——
  "缓存了一半"照样会露馅（`docs/错误总结.md` #24 记过两次同族翻车）。V1 把槽位从 2 个扩到 13 个
  （thumb/avatar/display/sticker-1..8/cover）时，改成 `store._find_assets()` 一次列举拿全，
  并把落盘索引**升版到 v3**（形状变了必须升版，否则旧索引会让列表读到 `thumb=None` 直到 TTL 过期）。
  槽位表取 `card_format.IMAGE_SLOTS`（单一真相源），不再硬编码 `("cover","avatar")`。
- **写操作立即失效**（`_invalidate_index()`，publish/set_status/bump_download/delete/add_report 五处都调）：
  内存与**文件索引一起作废**，所以"发完/下架立刻可见"这条语义不变
  （尤其下架只改卡内 `meta.json`、不动扫描根 mtime，必须靠这一步兜住）。
- 读的时候**不信文件**，三重校验：① `scandir` 计数与索引记录的目录数不符 ⇒ 重扫（**自愈**）；
  ② 扫描根 mtime 变了 ⇒ 重扫；③ 索引超过文件 TTL ⇒ 重扫（**有界陈旧**）。
  ⇒ 缓存**不是第二份真相源**：随时可丢、写后即失效、三项校验任一不过就退回扫盘，目录仍是唯一权威。
  ⚠ 索引文件**必须放在扫描根之外**：放进 `cards/` 的话，"写索引"会改 `cards/` 的 mtime，
  把校验②变成**自激**（每个请求都重扫，实测热路径 24ms → 490ms）。见 `docs/错误总结.md` **#28**。
  ⚠ **文件 TTL 为什么是 300s（原 60s，2026-10-01 task-19/20）**：`test_plaza_scale_v1.py` 实测
  480 张 V1 卡走索引冷读 **6ms**、而**第③条判过期那一次读要全量重扫 460–520ms**（旧格式 392ms，
  均已超 300ms 预算）⇒ 60s 等于"每分钟一次 500ms 尖峰"；放宽 5× 后变成每 5 分钟一次。
  代价可忽略：task-17 之后**所有 store 写路径**都 `os.utime(cards_dir())` ⇒ 程序写入的即时性由**第②条**
  接管，第③条只剩"手工改盘且不动目录 mtime"这一个极端兜底。该尾巴在测试里是**已知观测项**（非达标）。
- **"原地重写 `meta.json`"必须自己顶一下扫描根 mtime**（2026-10-01，task-15 排查 → task-17 修复）：
  改状态/举报/下载计数都只重写卡内 `meta.json` —— **子目录数不变、`cards/` 目录 mtime 也不变**，
   ⇒ 若是**别的进程**（脚本/手工/探针）写的，读者进程的三条校验全不过不了，会一直吃旧索引直到
  `FILE_TTL` 过期（"治理后列表偶发不反映"就是这么来的）。现在这些写路径统一调
  `store._touch_cards_dir()`（`os.utime(cards_dir(), None)`，失败只告警）⇒ 校验②当场不过 ⇒
  **跨进程/手工写盘也在 1 次读内生效**。对照：**增删卡目录**本来就动 ①（计数）/②（目录 mtime），
  不需要这步。代价只有"写才动一次 utime"，热路径与冷读的 O(1) 语义不变。
  回归：`tests/test_plaza_index_freshness.py`（读侧=真服务器进程 + 真 HTTP；写侧分"产品路径"与
  "跨进程直写"两条；另含一条**变异对照** —— 把 utime 打成 no-op 时必须仍然陈旧，防假绿）。
- 效果（`tests/test_plaza_scale.py` **30 项**）：**热路径 p95 24ms、冷启动 22ms**（480 张卡），
  冷读随规模几乎不增（120 张 20ms → 480 张 22ms）⇒ 热、冷双双进 300ms 设计预算。
- 排查用：`FIREFLY_PLAZA_INDEX_DEBUG=1` 让服务端把"命中 / 拒①②③"打到 stderr。

## 一点五、服务器对外面：**只做后台**（2026-10-01 task-23，用户纠正）

> **服务器只提供登录页 + 角色卡平台 + 客户端 API；不提供 App 前端**（无 `/index.html`、App bundle `js/bundle.js`、App 面板 `js/panels/*`、App 样式 `style.css`/`pc.css`）。
> **闸门在 `do_GET` 最前**（纵深防御，文件还在也挡）：App 壳 `/`、`/index.html`、`/index`、`/app.html` ⇒ **302 → `/login.html`**；`/style.css`、`/pc.css`、`/js/*`（平台白名单外）⇒ **404**。
> **白名单与黑名单显式分开**（别用"App 一律挡"扫到登录入口）：可达 = `/login.html`、`/login`、`/platform.html`、`/config.js`、`/bg-sunset.css`、`/admin.html`（仍 401，token 闸在 8766）、平台前缀 `/platform*` `/js/platform*` `/js/panels/plaza*`；**其余静态默认拒绝**、不回退 `STATIC_DIR`（本地版 App 的目录）、`/static/*` 直接 404。**API 一条不许减**：`/health`、`/version.json`、`/update-manifest`、`/plaza/api/*`、`/auth/*`、`/modes`、`/config`、`/notice`、`/hotupdate/*`、`/assets/*` 行为不变。
> **自查/门禁**：`python tools/check_server_surface.py`（沙箱矩阵）或加 `--base http://<公网IP>:8787 --gateway --strict-platform`（打已部署实例）；三组断言 = 关键路由 + verifier 基线 `_harden/server_surface_baseline.json` 逐条匹配 + 两处 App 目录**全量枚举**断言 `≠200`（判定一律 **GET**：本服务不支持 HEAD）；`--gateway` 时另加 **B2 版本冻结核查**（`/version.json` 206B、`/health` 27B 逐字节比对 + 打印 tag）。部署搬迁 `_harden/move_app_frontend.sh`（只搬不删、可回滚）；演练用 `FIREFLY_FRONTEND_DIR`（仅临时副本，生产不设）。安全视角展开见 **05 §七**。
> `/assets/*` **保留**（客户端服务器模式的图片通道：`app/static/js/util.js::stickerSrc` 拼 `apiBase + "/assets/"`，packs/stickers/chat_render 都在调）；该分支在鉴权前、**无用户上下文** ⇒ 只解析全局/bundled 资产，不含他人数据。

## 二、卡状态机

```
draft ──提交审核──> pending ──通过──> published ──下架──> archived
                      └──驳回──> rejected ──改后重提──> pending
```

- 公开列表/详情只认 `published`；`statuses=None` 是管理视角（管理台用）。
- 官方（用户自己的账号）发布的卡免审但带 `author.official=true` 标识（M2）。
- 发布写盘顺序：`build_card_zip`（自带回读自校验）→ 原子写 `card.zip` → 抽封面/头像 → 原子写 `meta.json`。
  **校验不通过不落任何目录**（杜绝本项目踩过的"孤儿包目录"）。

**`/plaza/api/derive`（2026-10-01，用户要求"改编别整卡重传"）**：以**已发布**卡为模板 ⇒ 服务端复制卡体、
只应用 patch（`card{…}` 只给变化 + `remove{…}`）⇒ 存成**自己的新草稿**，再走既有审核/发布闸门；限制口径与
普通制卡完全一致；只复制卡体、**不带**原作者 `author`/`uid_hash`；`derived_from` 只记录、不进任何投影。
省流量实测（同一次"只改 `core.md`"）：**141.4KB → 0.2KB（↓99.9%）**；形状/保证/客户端接法与回归见 **[08_改编通道derive.md](08_改编通道derive.md)**。

**鉴权怎么来的**：这些路径**不在** `server/app.py` 的公开白名单（`:74-77`、静态文件分支 `:410-426`）里
→ 自动落进 `do_GET` 的登录闸门（`server/app.py:427-430`）。满足"广场完全登录可见"的产品决策。

**两种客户端模式共用一套前端调用**（前端只调相对路径）：

- **服务器模式**：由本机 8765 直接实现（`app/plaza/api.py`）。
- **本地模式**：本地后端把 `/plaza/api/*` **代理**到 `_auth_server_base()`，带 `auth_store` 持有的 token
  ——与 A7 的 `/auth/*` 代理同一先例（`app/routes_auth.py:30-84`），因此没有 CORS / `file://` 问题。

> 前端图片用 `fetch` + `objectURL` 取（`<img src>` 不会带 Authorization 头），两种模式行为一致。

### 制卡 payload 与草稿回读（V1，契约见 [06](06_制卡自由度与图片规格.md) §3.2）

`POST /plaza/api/draft` 与 `/plaza/api/review` 都走 `api._card_zip_from_payload()`：

| 收到的 | 映射到卡里 |
|---|---|
| `files:[{path,text}]` | 同路径文本（白名单：`character/` 根 与 `knowledge/`、`knowledge/<域>/`） |
| `images.{thumb,display,avatar}` | `assets/<槽位>.<ext>`（扩展名按**魔数**定，不信声明） |
| `images.stickers:[{data,label}]` | `assets/sticker-N.<ext>` + `stickers.json`（`{文件名: 标签}`；缺 label 就不生成该文件） |
| `opening`（对象或字符串） | `opening.json` |
| 老字段 `core`/`identity`/`sms_samples`、平铺 `cover`/`avatar` | 等价的 `files[]` / `assets/…`（**兼容通道**，同路径以 `files[]` 为准） |

- 用户**不能**提交 `preset.json`（后端生成）、`opening.json`（走 `opening` 字段）、`stickers.json`（走 `label`）
  —— 三者在 payload 层被明确拒绝（不是静默忽略）。
- **thumb 必填只掐新格式**：payload 里出现 `files` 或 `images` 即视为 V1 提交，没有 `thumb` → 400 `CARD_MISSING_THUMB`；
  只发老字段的老客户端走兼容通道（否则老客户端与存量老草稿全挂）。新 UI 打开老草稿后要保存，必须先生成 thumb
  —— 这是**有意的迁移闸门**（老草稿能读、能改，补上 thumb 即可存）。
- `GET /plaza/api/draft` 回**两种形状**：新形状 `files[]`/`images{}`（`stickers` 为 `[{data,label}]`）
  与老形状 `core`/`identity`/`sms_samples`/`cover`/`avatar`（老前端兜底）；
  `preset.json`/`opening.json`/`stickers.json` **不进 `files[]`**（它们是结构化字段的落点）。
  `tests/test_plaza_drafts.py` 钉死：回读结果**原样再提交**后整卡 `digest` 不变（往返零漂移）。
- 列表/详情的图片字段：`store._public_view(..., scope="list")`（列表）**只给 `thumb`**（老卡无 thumb
  才回落 `cover`；**连 `avatar` 键都不出现** —— 结构性砍流量），
  `store._detail_view()`（详情）再补 `display` + `stickers[]` + `avatar`；
  `stickers` 形状 **`[{file,label}]`**（2026-10-01 统一：标签在**发布时**从卡内 `stickers.json`
  存进 `meta.sticker_labels`，投影时不必再解 zip；老卡没这份 ⇒ `label=""`，形状不变）。
- **顺手修的既有静默崩溃**（2026-10-01）：`api.py::plaza_draft_get` 里用了 `Path(...)` 却从未
  `from pathlib import Path` ⇒ 只要草稿里带图就 `NameError` 500，而这条路径**此前没有任何测试覆盖**。
  已补 import，并在 `tests/test_plaza_drafts.py` 用"带图草稿回读"钉住（这类"旧路径无测试"的坑值得记一笔）。

## 四、按用户解析的包视图（M1.5，共创平台核心改动）

**问题**：`PRESETS`/`MODES` 是**进程级全局**（`app/core/presets.py:44-101`），而服务器模式每个账号
有独立 `user_data/{uid}/`。用户经广场安装的角色卡落在**该账号自己目录**里，因此"当前用户有哪些包"
必须按请求上下文解析。

**做法**（`app/core/presets.py`）：全局表不动，新增只读叠加层与四个访问器：

| 访问器 | 语义 | 替代 |
|---|---|---|
| `user_packs()` | 当前用户安装、且不在全局 PRESETS 里的包 | — |
| `all_packs()` | 内置包 + 当前用户的广场卡 | `PRESETS` |
| `pack_meta(mode)` | 当前用户视角的单包元数据（缺失返回 `{}`） | `PRESETS.get(mode)` |
| `valid_mode(mode)` | 该用户能否使用此 mode | `mode in MODES` |
| `all_modes()` | 当前用户的模式元组 | `for m in MODES` |

**已否决的反面做法**：把所有用户装过的卡并进全局 `MODES`（会让 A 的卡出现在 B 的列表里，
并让备份/主动性/诊断等循环遍历不存在的包）。缓存按用户作用域键控，`reload_presets()` 清空。

**必须一起改的路径解析**：`core/paths._resolve_mode()` 改用 `valid_mode()`——
否则用户自己的卡会被判成"非法 mode"而**静默回退默认包**，读写落到别的角色目录
（本项目踩过的同类坑）。

**顺带修的真 bug**：`PackRegistry.register()` 的兜底查找原先写死全局 `USER_DIR`
（C8 只修了 `self.fp`），服务器模式下会在**别的账号**目录里找 preset.json。

## 五、服务器模式的安装/卸载（D1=A 的限额，M2 实现）

- 只允许**广场来源**的卡落盘（不走 `create_pack`，那条路在服务器模式仍被拒，
  见 `app/api/pack_lifecycle.py:58-59`）；安装路径同样只写 `character/`，**不碰用户数据**。
- 配额：**每人 ≤5 张、总 ≤8MB**；超限拒绝并给出人话提示。
- 卸载：删除该用户目录下的包 + 从该用户 `packs.json` 注销 + `reload_presets()`；
  删除前对该包做一次全量备份（复用 `_force_pack_backup` 思路，`app/api/pack_lifecycle.py:177-199`）。

## 六、审核（M2，用户 sk 即焚）

1. 用户提交卡片草稿 + 自己的 DeepSeek `sk`；后端**先校验格式**（`^sk-[A-Za-z0-9]{20,}$`），格式不对直接拒。
2. 后端用该 Key 调模型做合规审查（提示词与判定阈值见 M2 实现卡），**只取判定结果**。
3. **无论成败，立即从内存丢弃该 Key**：不落盘、不进日志、不进审计流水、不进异常上下文。
4. 审计流水只记：卡 id、判定、模型名、token 用量、时间（**永不记 Key**）。

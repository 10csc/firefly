# 角色卡共创平台 · 01 角色卡格式与校验

> 依赖：无。被依赖：02（服务器存储）、03（客户端安装）。
> 原则：**卡就是 `character/` 子树**（`app/routes_pack.py:9-13` 的既有边界），**卡里永不包含用户数据**。

## 一、为什么需要新格式

现有导出/快照按**包 id** 打包整个 `user_data/{id}/`（`app/core/presets.py:137-147` + `app/routes_snapshot.py:54-70`），卡与用户数据混装；广场传输必须**只带卡**，否则等于把别人的对话/记忆/手账传播出去。因此新增一种独立产物：

```
card.zip
├── manifest.json          # 卡元数据（服务器与客户端共用契约）
└── character/
    ├── preset.json                  # **后端生成**，用户不可提交（安全边界）
    ├── core.md / identity.md / sms_samples.md / opening.json     (选填)
    ├── stickers.json                (选填) {"sticker-1.webp": "开心", …}
    ├── knowledge/<名字>.md|txt|json          (选填，**份数不限**；文字受单卡总量约束；每段 ≤64 字)
    ├── knowledge/<域>/<名字>.md|txt|json     (选填，**一层分组**：App 编辑器的五域写法；**域与名各自 ≤64 字**)
    └── assets/
        ├── thumb.webp|jpg|png       (V1 列表**唯一**用图；新格式提交时必填)
        ├── display.webp|jpg|png     (选填，详情大图)
        ├── avatar.webp|jpg|png      (选填)
        ├── sticker-1..8.webp|jpg|png (选填，表情包)
        └── cover.webp|jpg|png       (选填，**M1 老槽位**：V1 起列表不用，仅存量卡兼容)
```

**顶层只允许这两项**；`character/` 下**只允许上表白名单**，出现任何其它路径 → 整卡拒绝（**不静默忽略**，避免"我传了但没生效"）。
目录白名单 = `character/` 根、`character/knowledge/` 及其**一层子目录**（`world/factions/story/character/dialogues` 或用户自定名）；
更深层级与其它目录（如 `prompts/`）一律拒绝。V1 细节见 [06 制卡自由度与图片规格](06_制卡自由度与图片规格.md) §3.1。

## 二、manifest.json 契约

| 字段 | 类型 | 必填 | 上限 | 说明 |
|---|---|---|---|---|
| `format` | int | ✅ | =1 | 归档格式版本；客户端只接受 ≤ 自己支持的最大值 |
| `pack_schema` | int | ✅ | =1 | 对应 `preset.json` 的 `schema`（`app/core/preset_parse.py:105-112`） |
| `id` | str | ✅ | 32 | 卡 id，须匹配 `^[a-z0-9_-]{1,32}$`（复用 `_PRESET_ID_RE`，`preset_parse.py:27`） |
| `name` | str | ✅ | 40 | 卡片展示名 |
| `char_name` | str | ✅ | 20 | 角色名（`preset_parse.py:89`） |
| `user_name` | str | ✅ | 20 | 用户称呼（`preset_parse.py`，可被包级配置覆盖） |
| `presentation` | enum | ✅ | — | `sticker` / `narration` / `none`（非法回退 `sticker`，`preset_parse.py:94-97`） |
| `desc` | str | ✅ | 120 | 一句话简介 |
| `tagline` | str | ⬜ | 40 | 副标题 |
| `category` | str | ✅ | 16 | 广场一级分类（枚举见 §四） |
| `tags` | str[] | ⬜ | 5×12 | 自由标签 |
| `author` | obj | ✅ | — | `{uid_hash, display, official: bool}`；**只存 uid 的哈希**，不存明文 uid |
| `created_at` | int | ✅ | — | Unix 秒 |
| `files` | obj[] | ✅ | ≤500 | `{path, size, sha256}`，path 为 `character/` 相对路径 |
| `digest` | str | ✅ | 64 | 整卡摘要，口径见 §三 |

## 三、校验契约（**接收方必须全部执行**）

沿用并复用既有设施，不新造轮子：

1. **路径安全**：复用 `_zip_safe_entries` 语义（`app/infra/sync/restore.py:63-81`）——拒绝绝对路径、盘符、`..`、空路径段。
2. **体积**（2026-10-01 松绑，见 06 §3.1）：**文字按单卡总量** ≤8MB（普通账号；**不限份数、不限单文件**；
   管理员不限）；zip 本体与解压后均 ≤**10MB**（管理员 64MB）；`character/` 下条目数 ≤**500**（2026-10-02 由 24 放宽：只挡"一万个空文件"这类滥用，不是配额）；路径深度 ≤3。
   图片按槽位分别设上限（06 §3.3）：`thumb` ≤12KB、`avatar` ≤30KB、`display` ≤300KB、`sticker-N` ≤20KB、老槽位 `cover` ≤300KB。
3. **压缩比**：解压后/压缩后 >20 且解压后 >100KB → 视为 zip 炸弹拒绝（**只对非文本**：文本已受总量约束，
   高压缩比是 markdown/表格的正常现象，见 06 §3.1）。
4. **内容**：`preset.json` 必须能被 `_parse_preset` 解析通过（`app/core/preset_parse.py:71-117`）；`id` 必须等于 `manifest.id`。
   `opening.json` 必须是合法 JSON；`stickers.json` 必须是 `{表情包文件名: 标签}`，键必须指向**本卡真实存在**的表情包、标签 ≤12 字。
5. **哈希**：逐文件 sha256 与 `files[]` 一致；整卡 `digest` = `sha256(排序后的 "{path}\0{sha256}\n" 串接)`（**与现有 `_pack_digest` 口径一致**，`app/infra/sync/manifest.py:34-42`）。
6. **文本**：所有文本文件（`.md`/`.txt`/`.json`）必须是 UTF-8。
7. **图片**：只接受 `webp/jpg/jpeg/png`；服务器侧校验魔数并**自己解析图片头部**拿宽高（PNG IHDR / JPEG SOFn / WebP VP8X|VP8|VP8L），
   不信客户端声明的尺寸；宽高超槽位上限或像素总量超 2048×2048 一律拒绝。
8. **thumb 必填**：V1 新格式提交（payload 带 `files[]` 或 `images{}`）**必须**有 `thumb`，缺 → `CARD_MISSING_THUMB`；
   存量卡与老草稿（V1 之前、只有 `cover`）走兼容通道仍可解析（老数据不能坏）。

**失败即整卡拒绝**，返回结构化错误码：`CARD_TOO_BIG` / `CARD_BAD_PATH` / `CARD_UNKNOWN_FILE` / `CARD_BAD_PRESET` / `CARD_BAD_MANIFEST` / `CARD_HASH_MISMATCH` / `CARD_BAD_IMAGE` / `CARD_BOMB` / `CARD_NOT_ZIP` / `CARD_FORMAT_UNSUPPORTED` / `CARD_MISSING_THUMB`。

## 四、广场分类（一期枚举，写死在后端 + 前端同一份）

`陪伴` / `剧情` / `日常` / `战斗` / `治愈` / `搞笑` / `其他` —— 7 个一级分类；标签自由填（≤**20** 个，2026-10-02 由 5 放宽）。

**向后兼容规则**：客户端遇到未知 `category` → 归入「其他」显示，绝不报错（服务器将来加分类时旧客户端不能崩）。

## 五、安装契约（客户端侧，详见 03）

下载 → 校验（§三 全流程）→ 解压到**暂存目录** → 用 `_swap_dir_into_place`（`restore.py:135-165`）原子换入 `user_data/{id}/character/` → `pack_registry().register(id, source="plaza")` → `cfg.reload_presets()`。

- 目录解析**必须**用 `cfg.pack_root(pid)`（`app/core/paths.py:143-150`）；**禁止**用 `mode_root`（对未注册 id 会静默回退默认包）。
- 本机已有同名包 → 提示覆盖（覆盖前对该包做一次全量备份，复用 `_force_pack_backup` 思路，`app/api/pack_lifecycle.py:177-199`）。
- 安装只写 `character/`，**绝不创建或覆盖 `data/`、`journal/`、`images/`**（用户数据保护，铁律）。

## 六、体积预算（对 3Mbps 带宽的直接约束）

| 项 | 上限 | 理由 |
|---|---|---|
| `thumb`（列表唯一用图） | ≤320px / ≤12KB | 一屏 20 张 ≈120KB，替代改造前 20×151KB ≈3MB（06 §3.3） |
| `display`（详情才拉） | ≤1024px / ≤300KB | 与前端 Canvas 预压口径一致（`app/static/js/imgzip.js:8-9`） |
| `avatar` | ≤256px / ≤30KB | 列表小圆头像（可省，用 thumb 即可） |
| `sticker-1..8` | ≤160px / ≤20KB 每张 | 最多 8 张，省着用（App 组织器按 `label` 语义选图） |
| `cover`（老槽位） | ≤300KB | **V1 列表不再用**；仅存量卡与老客户端兼容 |
| 整卡 | 文字总量 ≤8MB、zip ≤10MB（管理员：文字不限 / 64MB） | 单个用户下载 10MB ≈ 在 3Mbps 上占 ~27 秒独占带宽；管理员天花板是防手滑、不是配额 |
| 广场列表响应 | ≤60KB（20 条，只含 thumb 地址） | 列表**不返回卡正文、不下发大图地址** |
| 单用户日下载配额 | 见 04 文档 | 防单用户独占 |

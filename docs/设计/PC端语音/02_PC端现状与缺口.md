## 2. 缺口清单（按严重度）

### G1 ★ 引擎后端缺失 —— PC 上「转了没反应」的唯一根因

`app/voice/engine.py` 的非安卓分支直接返回不可用（原文）：

- `engine.py:6-8`：注释写明「PC ：本版未接入 → `available()` 返回 False 并给出原因，整条链路静默降级为纯文字」；
- `engine.py:31-35`：`from java import jclass` 失败 ⇒ reason =「当前平台无语音引擎：本版只接了安卓（Kotlin ONNX）后端」；
- `engine.py:52-53`、`:71-72`、`:93-96`、`:107-109`：所有出口都因 `_load_bridge()` 为 None 而返回失败。

**后果（PC 用户视角）**：插件能装、模型能下 872MB、页面显示「已启用 · 不可用」，
点「转语音」返回 `{ok:false,error:"当前平台无语音引擎…"}`。**不是 bug，是未实现**。

### G2 ★ PC 打包把语音依赖排除了 —— 即使写好引擎也 import 不到

`firefly.spec:40-47` 的 `excludes` 里明确有 **`numpy`、`onnxruntime`**（还有 torch 等）：

```python
excludes=[
    "numpy", "sentence_transformers", "torch", ... "cv2", "onnxruntime",
```

⇒ 打到 `dist/firefly/_internal` 里**没有** onnxruntime；`firefly.spec:83` 的注释也正是提醒
「新增重型本地模型（语音/识图）时必须回来改这个 excludes 和 datas」。
**新依赖必须同步改 `firefly.spec`（构建规范 §0 第 5 条、§7 第 4 条）**，否则本地能跑、装完缺模块。

### G3 ★ 语气库/映射表在 PC 上**没有落地路径**

手机靠 Kotlin 从 `AssetManager` 直读映射表、首次把 `mood_lib` 拷到私有目录（`VoiceBridge.kt:83-103`）。
PC 侧 `paths.mood_lib_dir()` 返回的是 `{插件根}/mood_lib`，**没有任何东西会往里写**。
⇒ PC 引擎必须直接读**打包资产**（`core.paths.BASE_DIR/assets/voice/`：
dev = `app/assets/voice/`，frozen = `_internal/assets/voice/`），
或者在启动时把 `mood_lib` 拷到插件根（对齐手机语义）。**这是实现时必须先决定的一处**。

### G4 卸载残留 872MB —— Inno Setup 不会删 `{app}/voice/`

`package/firefly.iss:24`：

```
Source: "..\dist\firefly\*"; DestDir: "{app}"; Flags: recursesubdirs ignoreversion; Excludes: "user_data"
```

只排除了 `user_data`。而 PC 的插件根 = `{app}/voice/`（`paths.py:56-59`），**二者平级**：
- 覆盖安装：Inno 不动未登记的文件 ⇒ 模型**保留** ✓（符合预期）。
- **卸载**：Inno 只删自己登记过的文件 ⇒ `{app}/voice/`（872MB）**留下** ✗。

⇒ 需要 PC 侧动作：`[UninstallDelete]` 清 `{app}/voice`，或（更省事）在插件页「卸载」入口说明
（`plugin.uninstall()` 已能删干净 `app/voice/plugin.py:174-194`）。手机侧无此问题（系统清 app 私有目录）。

### G5 服务器版隔离：已按「资源就绪判定」处理，PC 不要重新引入环境开关

`docs/工具/tts.md:163-165` 已把「服务器强制关闭」修订为「资源就绪判定」——
PC 后端也必须遵守同一口径：**没模型就不可用，装上就可用**，不新增 `FIREFLY_SERVER` 分支。
（`server/**` 不在本任务范围，见纪律。）

### G6 前端无平台分支 —— 无需改动，但有一处体验缺口

菜单项可点性与原因完全由 `GET /voice/status` 的 `engine_ok/reason` 驱动（`chat.js:85`），
PC 接上引擎后**前端零改动**。唯一体验缺口：未安装时首页入口**不打红点**是刻意设计
（`docs/工具/tts.md:80`），PC 上用户不知道有这功能——属前端范畴，交 `frontend` 评估。

## 3. 「PC 端之前没有语音模型」这句用户话的准确解读

用户说的「没有语音模型」在代码层面**属实且只有一层含义**：**没有可用的推理后端**。
模型文件本身（`app/assets/voice`）与下载通道（ModelScope）都在。所以这不是「重新选型/重训模型」的任务，
而是「把已经在手机上跑通的那套引擎，在 PC 上落地一份」的任务——这也解释了为什么用户给的要求是
「**在手机端 900MB 的基础上提速即可**」：**不换模型、不换音色**。

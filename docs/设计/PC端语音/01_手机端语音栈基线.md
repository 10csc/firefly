## 1. 用了哪些模型（8 个 ONNX + 1 个共享权重 + 语气库）

来源：`app/voice/paths.py:24-33`（`MODEL_FILES`）+ 部署副本实测字节
（`FireflyVoiceResearch/android_tts_app/app/src/main/assets/models/`）。

| 文件 | 体积 | 作用 | 量化档 |
|---|---|---|---|
| `firefly_t2s_encoder.onnx` | 10.9 MB | 文本音素 → 编码 | **未量化**（份额小） |
| `firefly_t2s_fsdec_int8.onnx` | 1.1 MB | 自回归解码首步 | int8 + 外置权重 |
| `firefly_t2s_sdec_int8.onnx` | 1.2 MB | 自回归解码（带 KV cache） | int8 + 外置权重 |
| `firefly_t2s_weights_int8.bin` | 74.7 MB | ↑ 两图**共享**的权重（E5 去重，省 72.44MB） | int8 |
| `firefly_vits_int8.onnx` | 44.9 MB | 语义 token → 声学特征 | int8 |
| `firefly_cfm_estimator_int8.onnx` | 332.7 MB | 条件流匹配（CFM）估算器 | int8（**最大单体**） |
| `firefly_vocoder.onnx` | 55.1 MB | 声学特征 → 48kHz 波形 | **fp32**（int8 版在 PC 上慢 12×，弃用） |

| *(选配)* `firefly_bert_fp16.onnx` | 571.4 MB | 高精度档 | fp16，**故意不传**到 ModelScope |
| `app/assets/voice/mood_lib/{happy,sad}/*.raw` | 4.1 MB | 预计算参考特征（6 个量/语气，**零推理**） | — |
| `app/assets/voice/*.json,txt` | 0.7 MB | pinyin.json（20921 字）/ char2id.json（11514 字）/ symbols.json（732）/ opencpop-strict.txt | — |

⇒ **PC 也不需要这个 377MB 文件**（01 §4 有证据）。

## 3. 手机端实测：延迟 / 内存 / 质量

### 3.1 延迟 `[实测]`（一加 Ace 3 / PJE110 / Android 14 / 15.5GB RAM · 同句）

来源：`FireflyVoiceResearch/docs/09_进一步压缩与安卓落地.md:496-511`

| 阶段 | int8 档 | fp16 档 |
|---|---|---|
| 文本前端 | 2~10 ms | — |
| BERT | 34~147 ms | 147 ms |
| encoder | 63~916 ms | 63 ms |
| fsdec | 300~1136 ms | 307 ms |
| **T2S 自回归（AR）** | **13.5~58.1 s**（27~89 token） | 30.3 s（57 token） |
| CFM | 2.8~5.3 s | 4.0 s |
| vocoder | 0.6~2.1 s | 1.4 s |
| **总计** | **17.7~67.4 s** | **36.4 s** |

- **AR 是绝对瓶颈（≈71%，`09:289`）且方差极大**（同配置 27~89 token）——**单次数字无意义，必须看分布**（`09:509-511`、`10:176-179`）。
- 引擎装载：`TtsEngine` 建 6 个 session 实测 **4801ms**（`09:459-460`）；`app/voice/engine.py:48` 注释写「手机上一次要 30~60s」（含装载+首次预热）`[未测: 精确口径]`。
- ⚠️ 另一组更差的数字（46~58 s）来自 `android_onnx_bench`（**每句重建 session**），
  与 `android_tts_app`（session 常驻）不是同一个工程，**不可混用**（`09:20-23`、`10:136-138`）。

### 3.3 质量 `[实测/事实]`

- **数值等价**：ONNX vs PyTorch 同输入，CFM max 9.5e-07、vits <1e-5（门禁 1e-4）——`10:145-149`。
- **量化代价**：BERT int8 相对 fp32 L2 误差 14.3%；混合 int8（t2s/vits/cfm）+ vocoder fp32 在手机上
  **zcr 0.039（与 PC fp32 同级）、ASR 回读正确**——`10:160-162`。
- **统计检验（N=5）**：int8 的全部偏移都落在基线自身 σ 内，**统计上与 fp32 不可区分**——`10:164-172`。
- **守卫通过率 92%**（PC 44/48：开心 24/24、悲伤 20/24）——`app` 侧同款守卫，
  见 `docs/工具/tts.md:132` 与 `FireflyVoiceResearch/_proto/_rate.log:57-63`。
- ⚠️ **已知质量弱点（PC 若照搬会一并继承，但这是「持平」不是「下滑」）**：
  Kotlin `TextFrontend` 是**简化版**——单读音表（无 g2pw 上下文多音字消歧）、
  无数字/英文/儿化归一化（`TextFrontend.kt:71` 直接删 `[a-zA-Z]+`、`:153` 过滤非中文）。
  官方 PyTorch 前端用 jieba+g2pw+tone_sandhi（`text/chinese.py:1-10`），质量更高但依赖重。
- ⚠️ **采样不可控**：`sdec` 图内 top-k 采样无种子，噪声地板 ±30% 时长 / ±80Hz 频谱峰 ⇒
  所有听感 A/B 必须 N≥5 看分布——`10:176-179`。

## 4. 分发与生命周期（PC 可直接复用的部分）

| 机制 | 实现 | 复用性 |
|---|---|---|
| 模型仓库 | ModelScope `cpt0721/firefly-voice-v4-onnx`，匿名可下、支持 Range | `app/voice/plugin.py:36-37` |
| 下载器 | **纯标准库** urllib + Range 断点续传 + sha256 对账（清单拿不到则降级） | `app/voice/downloader.py:1-23,84-113` |
| 状态机 | 5 态：downloading/not_installed/installed_disabled/unavailable/ready | `app/voice/plugin.py:78-133` |
| HTTP 端点 | `GET /voice/status`、`POST /voice/tts`、`GET /voice-file`、`GET|POST /voice/plugin` | `app/voice/routes.py:23-134`；已在 `app/api/router.py:139-140,205-207` 注册 |
| 前端 | 首页「语音插件」入口 + 长按「转语音」；**纯 HTTP，与平台无关** | `app/static/index.html:271`、`app/static/js/voice_plugin.js`、`chat.js:85,130` |
| 清理 | 清理历史→purge_all；撤回→按 seq 截断；缓存 LRU 200MB/包 | `app/voice/store.py:64-114` |

⇒ **结论：除「引擎后端」外，PC 端整条链路（状态机/下载/端点/前端/清理）都已存在且平台无关。**

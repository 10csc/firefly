# 04 · 验证方法（每个「未测」怎么补成数字）

> 原则（本项目已写死的纪律）：**先量再改**、**断言落在产物上**、**测量脚本自己先做已知输入冒烟**

## 0. 环境（不要重新探测，照 `docs/构建规范.md` §1）

- 语音管线 Python：**`D:\anaconda_2024\envs\firefly\python.exe`**（ORT 1.29.0 + numpy + torch + librosa）
- 仓库默认 `python`（3.12.6）是 **ORT 1.20.1 且无 librosa/numba** ⇒ 跑模型相关脚本一律用上面那个。
- Windows 跑 Python 前：`$env:PYTHONUTF8="1"; $env:PYTHONIOENCODING="utf-8"`。
- 测量脚本**一律写纯 ASCII 输出**（PS 5.1 管道里的中文会被 ANSI 解码，`docs/错误总结.md` #29）。

## 1. 本次已建立的探针（可直接复用）

| 脚本 | 测什么 | 读数 |
|---|---|---|
| `FireflyVoiceResearch/_proto/_pc_mem_probe.py` | 只装 ORT 时，7 个 session 的驻留 | 实测 PRIV 551MB / WS 54MB（权重是 mmap，不触碰不驻留） |
| `FireflyVoiceResearch/_proto/_pc_mem_full.py` | 原型全路径（含 torch 前端）装载 + 1 次合成的 PRIV/WS/RSS 峰值 | 实测 装载后 1588MB、合成后 2534MB、**峰值 2722MB** |

两者都用 **Private Commit（psapi `GetProcessMemoryInfo`，与 `docs/09 §F6` 同口径）+ WorkingSet + psutil RSS** 三口径，
**因为 PRIV 会把「已提交未驻留」也算进去**（实测：只 import numpy 就 +523MB 提交，但 WS 只有 29MB）——
**单看 PRIV 会高估，单看 RSS 会被 Windows 裁剪工作集干扰**。任何内存结论必须三口径并列。

## 2. 待测清单（按优先级）

### M1 · ORT 线程数是否有收益 `[未测]`

- **怎么测**：对**同一条文本、同一个语气**，在 `SessionOptions` 上分别设
  `intra_op_num_threads ∈ {0(默认), 物理核数, 物理核数+超线程}`、`inter_op=1`、`execution_mode=ORT_SEQUENTIAL`，
  各跑 **N=5**，记录 `T2S AR` 与总耗时（复用 `_rate_check.py` 的输出格式）。
- **验收**：有 ≥15% 总耗时收益才改默认；否则不动（避免与手机行为分叉）。
- **注意**：单次数字无意义（token 数在 27~89 之间波动，`docs/09:509`），**必须看 N≥5 的均值±σ**。

### M2 · 纯 Python 文本前端与 Kotlin 版**逐位一致** `[未测]`

- **怎么测**：把 `TextFrontend.kt:60-145` 移植后，用同一批文本（≥50 句，含轻声虚词、
  数字、英文、多音字、标点混排）分别产出 `(phones_ids, word2ph, aligned)`，与
  Kotlin 侧结果比对。Kotlin 侧结果可从**真机 logcat**（`TtsEngine.kt` 有阶段日志）
  或写一个最小 JVM 测试跑同一份 `pinyin.json` 得到。
- **验收**：字表一致率 **100%**（这是「质量不下滑」的机械证明）；不一致的字符要逐条给出原因。
- **附带**：以 `pinyin.json` 20921 字为准，统计**未覆盖字符率**（未知字静默跳过，`TextFrontend.kt:81-84`）。

### M3 · R1 的真实常驻/峰值 `[未测]`（**最关键**）

- **怎么测**：M2 落地后，用 `_pc_mem_full.py` 的同款探针跑**去掉 torch/transformers** 的 R1 实现；
  分别记录「装载后」「1 次合成后」「峰值」三组 PRIV/WS/RSS。
- **验收线**：语音子进程 **峰值 ≤2.0GB**、常驻 ≤1.5GB（预算 4GB，留 2 倍余量）；
  主进程不被污染（≤50MB，参考 `docs/工具/tts.md:144` 的 17~18MB）。
- **反面证据也要收**：连跑 5 次合成看是否单调上涨（arena 已关，若仍涨 ⇒ 真泄漏）。

### M4 · 提速杠杆的净收益 `[未测]`

- **L1（CFM 步数 4→3）与 L4（CFM 4-bit）先测**，再测 L2（ORT 线程数）——因为 **PC 侧瓶颈是 CFM 不是 AR**
  （`_session_hist.txt:9039`）。
- 各跑 N≥5，报**阶段耗时表**（encoder/fsdec/AR/vits/CFM/vocoder），而不是只报总数——只有阶段表能看出收益落在哪。
- **验收线**：总耗时降到 **≤12s** 才值得接受随之而来的质量风险；否则保持与手机同档。

### M5 · 音质「不下滑」的对照 `[未测]`

- 数字口径（可自动化）：token 均值±σ、时长、频谱峰、zcr（`docs/10:164-172` 的现成方法）。
- 听感口径：**N≥5 取时长中位样本**，禁止单样本 A/B（`docs/10:176-179`）。
- **验收线**：PC 各指标落在手机端基线的 σ 内；ASR 回读（FunASR，RTF 0.05~0.08，
  `docs/构建规范.md:22`）文本一致。

### M6 · 打包与安装生命周期 `[未测]`

- `firefly.spec` 放开 `onnxruntime`/`numpy` 后：`python -m PyInstaller firefly.spec --noconfirm` →
  启动 `dist\firefly\firefly.exe`（`GET /config` 200）→ 插件页能装模型 → 长按出语音。
- **必查三件**：① `_internal` 里 ORT DLL 齐全且未被 UPX 压坏；② 子进程**不弹黑窗**；
  ③ 覆盖安装后 `{app}/voice/models` 保留、卸载后无 872MB 残留（02 §G4）。
- **验收**：`tools/smoke_pc_exe.py` 扩一条语音冒烟（或新增同款脚本），进发版清单。

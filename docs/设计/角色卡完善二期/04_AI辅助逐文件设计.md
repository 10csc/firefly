# 04 · AI 辅助逐文件设计（图4）

> 用户原话：把「AI 帮我搭」去掉；AI 只是辅助——每个可修改列表单元右侧加 AI 辅助图标（只是图标），
> 点击后与 AI 对话修改**该特定文件**；每个文件的 AI 提示词与功能要详细设计，规定边界和写入形式。

## 一、删除项

- 前端：`#cv-forge-btn`、`#pack-forge-panel` 整块、`views.js` 的 `_forge`/`_pfShowDraft`/`pf-*` 三个监听器
- 路由：`/pack-forge/start|next|finish` 从分发表摘除（端点 404）
- 后端：`modules/pack_forge.py` 移入 `_trash/2026-09-15_AI搭建向导下架/`（不硬删；其 web_search 复用给 AI 辅助）
- 测试：`test_frontend_panels_split` 等含 forge 引用的守卫同步删

## 二、AI 辅助交互（UX）

- 位置：人设区/知识库区/记忆区**每个文件项右侧**一个 `✨` 小图标（`title="AI 辅助修改本文件"`，无 Key 时置灰 + 提示去设置）
- 点击 → 全屏抽屉 `#assist-view`：顶部=文件名+包名；中部=对话流（用户说目标，AI 回 diff 提案）；底部=输入框
- 提案呈现 = diff 卡片（旧文段 → 新文段 + 理由），按钮：「应用」「放弃」「继续调整」
- 关闭抽屉不丢对话（会话挂在 (mode,file) 键上，本页内有效；刷新即清，不落盘）

## 三、后端端点

| 端点 | 功能 |
|---|---|
| `POST /pack-assist` | {mode, file, message, history[]} → {reply, proposal: null \| {changes:[...]}}；只产提案不写盘 |
| `POST /pack-assist/apply` | {mode, file, change} → 校验 → 备份（写入前旧版本留 `.assist_backups/`）→ 原子写 → 清缓存 → 三态标记 |

写入形式（铁律）：**AI 永不直接写盘**；提案必须经 `validate_changes` 同款静态校验 + 用户点「应用」；
写入前自动备份（每文件留最近 5 份）；写入后 `clear_cache()` + `clear_knowledge_cache(mode)`。

## 四、每个文件的提示词与边界（逐文件设计，本计划的执行契约）

| 文件 | AI 角色 | 允许操作 | 硬边界（校验器强制执行） |
|---|---|---|---|
| core.md | 人设编辑助手 | replace / append | 不删 `[事实]` 条目除非用户明说；保留时态标记体系；单处 ≤2000 字 |
| identity.md | 关系设定助手 | replace / append | 不动 `user_name`/`char_name` 槽位行（那是 preset 字段） |
| sms_samples.md | 语料编辑助手 | append / replace | 只增删改示例条目；不动格式骨架（`「」` 分条结构） |
| 用户设定.md | 设定整理助手 | append / replace | 不动别的区段；新条目必须带 `[事实]/[经历]/[若]` 前缀 |
| prompts/polisher.md | 提示词工程助手 | replace | **输出协议段（[MSG] 分条/格式约束）禁止改**；只改人设口吻段；改完必须含原输出协议标记，否则校验拒绝 |
| prompts/analyzer_extra.md | 同上 | replace / append | 只追加核查口径，不动 JSON 输出协议 |
| prompts/organizer_*.md | 同上 | replace | 保留调度输出格式约束 |
| prompts/proactive_context.md / env_suffix.md | 情境文案助手 | replace | 纯文案，无结构约束 |
| knowledge/**.md | 知识编辑助手 | append / replace | 不动 `#` 一级标题与 `>` 范围行；新增条目注明来源 |
| memory/default.md | 记忆整理助手 | append / replace | 必须保持「核心记忆/既定事实」两区结构；条目带 `[事实]/[经历]` 前缀 |

**prompt 组装**：`系统 = 文件专属提示词（上表）+ 文件当前内容 + 边界清单`；用户消息 = 对话历史 + 本轮目标。
输出协议固定一行 JSON：`{"reply":"人话解释","changes":[{"op":"replace|append","old":"...","new":"...","reason":"..."}]}`。

## 五、实现落点

- 新模块 `app/modules/pack_assist.py`（提示词表 + 校验 + 调用），路由 `app/api/pack_assist.py`
- 校验复用 `setting_fix.validate_changes`（replace 锚点唯一性等）；备份复用 `storage` 原子写
- 前端：`panels/pack_assist.js` 新文件（抽屉 + 对话 + diff 渲染）

## 六、验收

- 沙箱实测：对 story/core.md 说"把失熵症的描述改温柔一点" → 出 diff → 应用 → 文件变更 + 备份存在 + 下轮检索用新内容
- 边界实测：要求改 polisher 的输出协议 → 校验拒绝
- 无 Key → 图标置灰；服务器版（非自建包）→ 图标隐藏

# 01 · 设置页与首页整改（图1 + 图2）

## A. 设置页原生控件主题化（图1 圈出处）

**问题实证**（375px 截图）：`#settings-panel` 的模型名 `<input>` 渲染为原生白底。

**复审修正（2026-09-15，第一版计划的漏洞）**：图1 圈里那个带蓝色单选圈的白色「DeepSeek」不是 select 的关闭态，
而是**安卓 WebView 点击 `<select>` 弹出的系统级选项弹窗**——它是 OS 原生控件，**CSS 根本管不到它**。
所以"加深色 CSS"只能修输入框，修不了那个白色弹窗。真正的修复是**自绘下拉组件**：

- 新增 `js/ui_select.js`：把 `.ui-select` 占位 div 渲染成「按钮 + 自绘弹出列表」（暗色面板、圆角、当前项高亮），
  外观与普通面板一致；键盘/触摸/点击外关闭都支持；对 `<select>` 的读写全部代理（get/set value、change 事件），
  调用方零感知
- 替换点：设置页 `provider-select`、`api-source-select`、四个 effort 档、外观组（如有）、建包表单的 `pc-presentation`/`pf-presentation`、表情包分类 `stk-cat-sel`/`pv-stk-category`
- 输入框白底：设置页全部 `input[type=text/password/email]` 统一深色规则（这部分 CSS 有效）

**验收**：375px 真机/模拟器截图——点供应商下拉出现**暗色自绘弹层**而非白色系统弹窗；
四个 effort 档同样；选项切换、change 事件、自动保存链路不变（test_frontend 守卫同步更新）。

- `app/orchestrator.py`、`analyzer.py`、`polisher.py`、`organizer.py`、`llm_retriever.py`、`memory_manager.py`、`proactive*.py`、`routes_config.py`、`routes_fix.py`、`llm_base.py` 的默认形参

- **迁移**：`core/migrations.py` 加一条幂等迁移——config.json 里四模型值 ∈ {旧名集合} → 替换为 `deepseek-flash`（用户自改过的非旧名不动），写执行日志
- **vision 验证（必做）**：`deepseek-flash` 是否支持图片输入 → 一次真实调用（发一张小图，成本<0.01 元）。若不支持识图：`SUGGESTED_PROVIDERS` 的 `caps.vision` 置 False + 文档说明；支持则不动

**验收**：`/config` 默认模型 = deepseek-flash；真实一轮对话成功（流萤正常回）；发图识图正常（或确认降级文案）。

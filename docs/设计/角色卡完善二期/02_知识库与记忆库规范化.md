# 02 · 知识库与记忆库规范化（图3 任务 A）

> 用户要求：① 所有角色都要有知识库和记忆库；② 流萤的知识库/记忆库组织形式规范化——
> **实际文件结构和名称都要规范化，且要过一遍内部文本处理**（不是只挪位置）。

## 一、目标结构（角色包标准结构 v2）

```
{pack}/（包根 = character/）
├── preset.json            # 注册清单（+ capabilities）
├── core.md  identity.md  sms_samples.md  用户设定.md    # 人设四件（现状不动）
├── prompts/               # 提示词六段（现状不动）
├── assets/                # 头像/封面/（05 的用户形象）
├── knowledge/             # 知识库（角色世界观/剧情知识）——规范化后结构：
│   ├── index.md           # 目录索引（内容与实文件严格一致，由校验脚本保证）
│   ├── world/             # 世界观：星神命途/地区/纪时/术语
│   │   ├── aeons-and-paths.md · regions.md · timeline.md · glossary.md
│   ├── factions/          # 势力档案（15 个，现状已规范，不动）
│   ├── story/             # 主线剧情：总览 + 版本（1.0~4.2，全任务粒度）
│   ├── character/         # 角色个人：流萤档案/格拉默/星核猎手/他人评价/对话样本
│   │   └── arc/           # 流萤视角主线经历（penacony-2.0~3.8）
│   └── dialogues/         # 剧情对话压缩版（现 dialogues_compiled/）
└── memory/
    └── default.md         # 记忆库：角色出厂记忆（见第三节格式）
```

## 二、story 知识库的整改动作（逐文件，内容级）

1. **结构归位**（git mv）：
   - `aeons-and-paths.md / regions.md / timeline.md / glossary.md` → `world/`
   - **复审修正**：第一版"story/ 与 剧本/ 同源两份去重合并"的判断**已被实测推翻**——
     `story/penacony-2.0.md`（2.2KB，流萤视角概要）与 `剧本/版本/2.0.md`（21.8KB，全任务主线）粒度与用途不同，
     不是重复。真实问题是**命名/归属混乱**：两个目录看似重复、流萤视角文件混在"story"名下。
     修正归位：`剧本/主线剧情总览.md` + `剧本/版本/*.md` → `story/`（主线剧情全量）；
     `story/penacony-*.md`（流萤视角经历）→ `character/arc/`；`story/firefly.md / glamoth-personal.md /
     hunters-personal.md / 银狼LV999评价.md` + `firefly-dialogue-samples.md` → `character/`
   - `story/dialogue-transcripts.md`（原文备份）→ 移出知识库，归档 `database/`（它本来就不进检索）
   - `story/手账.md` → 删除残留（运行时手账在 user_data；这份是旧时代死文件）
   - `dialogues_compiled/` → `dialogues/`
2. **内部文本处理**（过一遍内容，不改事实）：
   - 每个 md 统一头部：`# 标题` + 一行 `> 范围：本文件覆盖…` 的 scope 说明（检索器摘要质量依赖它）
   - 统一中英文混排的标题层级（`#` 唯一一级标题）
   - 全角/半角、markdown 表格残缺修正；文件间互相矛盾的表述登记到 `index.md` 的「口径冲突」区（不改事实，先登记）
3. **index.md 重建**：由脚本扫描实文件生成（防目录与索引漂移），纳入 `tools/check_knowledge.py` 新门禁

## 三、记忆库（default.md）格式规范

与运行时 memory.md 同构（头部+事实条目），角色出厂时的"她记得什么"：

```markdown
# 出厂记忆（{char_name}）
## 核心记忆
<她开局就记得的事：自己的来历/与用户的初始关系/当前生活状态>
## 既定事实
- [事实] …（长期成立）
- [经历] …（已发生）
```

**读取链**：polisher 的 memory_head = 运行时 `data/memory.md` 头部；运行时文件不存在 → 用包内 `memory/default.md` 起步（回落，不拷贝——与三态槽位同哲学）。rest 整理在默认记忆之上增量追加运行时文件。

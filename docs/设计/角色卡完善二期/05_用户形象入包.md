# 05 · 用户形象入包（追加要求）

> 用户原话：用户的头像应该属于角色卡可编辑内容的一部分——不同的角色卡有不同的用户身份，由用户自行修改。

## 一、现状与目标

- 现状：用户头像全局唯一（`localStorage tb_avatar` + 内置两图 `开拓者_穹/星.png`），与包无关；
  称呼 `user_name` 在 preset.json（包级但编辑页不可改）。
- 目标：每包独立的「用户形象」= **用户头像（可上传/选内置）+ 用户称呼（可改）**。

## 二、数据模型

- 称呼：编辑页表单字段直接改。**复审修正（实现路径改道）**：不写 preset.json 用户副本
  （preset 是包定义本体，为它引入整套副本机制代价过大），而是存**包级配置**——
  `/pack-config` 增 `user_name` 字段（落 `{pack}/data/proactive.json`，pack_cfg 体系现成）；
  读取链改 `user_name(mode)`：包级覆盖 → preset.json → 兜底「开拓者」。
  三态语义：`preset` 未动 = 未修改（ bundled 更新仍可送达），包级覆盖 = 用户改过。
- 头像：包资产新增槽位 `user_avatar`（`{pack}/character/assets/user_avatar.{png,webp…}`），
  复用 `/pack-asset` 上传链（slot 白名单加 `user_avatar`），解析走 `resolve_asset` 包资产回落
- 回落链：包内用户头像 → 全局 localStorage tb_avatar（现有两内置图）→ 默认
- 内置两包：story/haruno 的默认用户形象 = 开拓者（穹/星），不落包资产（走回落）

## 三、前端改动

- 角色卡编辑页新增「用户形象」区：当前称呼输入框 + 头像预览 + 「上传头像」「用内置形象」按钮
- 聊天渲染 `_addAvatar`：用户侧头像改按当前包解析（`/assets/character/{pack}/assets/user_avatar.*` 存在则用，否则内置选择）
- 首页/侧栏不显示用户头像（现状如此），只影响聊天消息行 + 详情页预览

## 四、后端改动

- `routes_pack.py`：`/pack-asset` slot 白名单 +`user_avatar`；`/pack-config` 增 `user_name` 字段写入（写 preset.json 用户副本 + reload_presets）
- `routes_config.py` `/modes`：每包返回 `user_avatar` URL（供前端渲染，与 avatar 同口径）
- `storage.REGISTRY`：包资产已覆盖 assets/（sync 扩展名放行），无需新行

## 五、迁移

- 幂等：无包头像 → 全局选择（现状行为）；用户已选过"星"→ 各包继续沿用全局选择
- 无数据搬迁；旧客户端不读 user_avatar 字段无影响

## 六、验收

- 沙箱：story 包上传用户头像 → 该包聊天用户气泡用新头像；切 haruno → 回内置形象
- 称呼改了 → 下一轮 LLM 提示词用新称呼（pipeline.jsonl 可见）
- 全量测试 + 门禁 + 真机截图

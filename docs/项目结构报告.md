## 一、项目定位

「流萤」是**独立运行的角色扮演聊天 Agent**（不依附于 Claude Code 等框架），以 DeepSeek V4（Flash/Pro）API 为唯一语言模型后端，无本地模型依赖。当前为**双线版本**：

| 版本 | 目录 | 运行位置 | 数据/Key 归属 |
|------|------|---------|--------------|
| 本地版 | `app/` + `android/` | 用户设备（Windows PC / Android 手机） | API Key 存本机 `user_data/config.json` |
| 服务器版 | `server/` + `android_server/` | 云服务器多用户（101.200.14.126） | 用户自带 Key 存浏览器 localStorage（服务器不落盘），数据按 `user_id` 隔离 |

**双模式人设**（同一后端跑两套角色）：`story`（剧情模式，流萤本体）/ `haruno`（春日手信，世界观改写的普通少女）。

**技术栈**：Python 3.10+ 纯标准库 `http.server.ThreadingHTTPServer`（无 Flask/FastAPI）；LLM 经 `requests` 自实现 OpenAI 兼容客户端直连 DeepSeek；前端纯静态 HTML/CSS/JS；安卓用 Chaquopy 内嵌 Python 3.12 + WebView；服务器版安卓壳为 0.6MB 纯 WebView。

## 四、本地版核心：`app/`

### 4.1 入口与 HTTP 层

- **`server.py`**（179 行）：启动入口。编码兜底 → 预加载知识库 → **多开检测**（探测 8765 端口 → 旧实例 `/shutdown` 优雅关闭 → taskkill 兜底）→ `ThreadingHTTPServer(("127.0.0.1", 8765))`（**只绑本机**，防局域网盗用 Key）→ 自动开浏览器。
- **`shared_http.py`**（108 行）：两个入口共享的 `ResponseMixin`（JSON/文件/CORS/OPTIONS）、优雅关闭、知识库预加载。
- **`routes.py`**（1,214 行）：全部业务 API，`POST_ROUTES`（22 个）+ `GET_ROUTES`（14 个）分发表。

**POST（22）**：`/set-key` `/set-config` `/save-journal` `/save-user-memory` `/check-key` `/chat` `/chat/hint` `/chat/flush` `/open-mode` `/proactive-status` `/rest` `/add-sticker` `/sticker-update` `/sticker-delete` `/character-file-update` `/check-update` `/update-download` `/relay/pending` `/relay/result` `/relay/proxy` `/undo` `/clear-history`

**GET（14）**：`/check-key` `/config` `/metrics` `/balance` `/requests` `/pipeline` `/history` `/wake-status` `/stickers` `/character-files` `/user-memory` `/journal` `/assets/index` `/assets/raw` ——另有 `/health`、`/shutdown`（server.py 内）与静态文件。

特色机制：**`/chat` 5 秒滑动合并窗口**（主请求挂起等窗口，副请求入队秒回 `queued`；`/chat/hint` 打字中重置、`/chat/flush` 提前结束）——解决安卓切后台定时器冻结丢消息问题；会话按 `(session_id, mode)` 隔离，首次创建自动 `memory_wake` + 历史回灌 + 主动性信号量重建。

### 4.2 对话流水线（每轮一次 `orchestrator.handle_chat`）

```
用户输入
 ├─ 前置审查：空输入/超长(>2000字) → 降级话术，不调 LLM
 ├─ ⓪ 环境句（_get_environment 按时间生成时段描述）
 ├─ ⓪ 检索器 LlmRetriever.retrieve   （story：知识库整体注入→LLM 压缩摘要；haruno 跳过；失败→空知识不阻塞）
 ├─ ① 分析器 Analyzer.analyze        （intent 意图 / fact_check 事实核查 / summary 摘要）
 ├─ ② 回复器 Polisher.polish         （全权生成 [MSG] 分条短信，≤6 条；稳定层+动态层 prompt）
 ├─ ③ 组织器 Organizer.organize      （story：表情包 label；haruno：旁白 JSON 按 after 插入）
 ├─ _merge_narrations 插入旁白（视觉小说式穿插演出）
 ├─ 写盘 conversation.jsonl + ctx.add_turn / add_action + pipeline.jsonl 观测日志
 └─ 任何 LLM 异常 → "嗯…信号不太好" 降级；组织器失败仅丢表情包/旁白，不阻塞文本
```

### 4.4 主动性三通道（`proactive.py`）

| 通道 | 触发 | 门控 |
|------|------|------|
| 主动式 | 每 N 轮用户对话 1 次判断机会（默认 4 轮） | 硬约束（轮次）→ 软约束（概率，连续被忽视 ×0.5） |
| 概率式 | 前端 10s 轮询 `/proactive-status`（空闲时） | ACTIVE 信号量 + 概率（默认 0.3） |
| 隐藏式 | 安卓后台 KeepAliveService 直调 `backdoor_proactive_check` | 独立 HIDDEN 冷却（≥10min）+ 24h 时段权重（深夜 0.02 → 傍晚 0.40） |

设计哲学：**数值只做后台门控，动机由 LLM 语义判断**（轻量 Flash Non-think 决策 should_speak/原因/话题，无来源问候拒绝）；生成复用 Polisher 全角色 prompt 保证角色一致性；写盘前原子检查用户新消息冲突则丢弃；haruno 只参与主动式。信号量：REPLY（响应式阻塞/主动非阻塞）+ ACTIVE（会话级互斥）+ HIDDEN（隐藏式冷却）。

### 4.5 记忆与手账（`memory_manager.py`）

- 时机：**休息（`/rest`）整理、起床（wake）加载**。
- `memory.md` 结构：`# 核心记忆头部`（休息时 LLM 整体重写 500–1000 字）+ `# 事实与任务`（承诺/偏好/事件三栏追加区）。
- 增量整理：`.memory_index` 记录 last_integrated_turn；原子写盘（.tmp + rename）；wake 检测中断（index 在、文件丢 → 降级空记忆）。
- 手账 `journal/手账.md`：流萤第一人称，LLM 更新两栏（"聊了什么" + "想做的事/约定"，≤1000 字符）。

### 4.6 知识检索（`llm_retriever.py`）

放弃本地向量 RAG（安卓无 embedding 模型），改为 **LLM 子代理检索**：知识库全部 md 整体注入 system 稳定前缀（DeepSeek prompt 缓存命中率实测 ~98.7%，平均每轮成本 ≈0.78 分）→ Non-think + temp 0 输出压缩知识摘要；验证阶段防对话体污染（`_looks_like_dialogue` 降级为空）。

### 4.7 表情包（`organizer.py` + `app/tools/sticker_picker.py`）

`registry.json` 44 条 `{id, file, category(可爱/帅气), label}` + 代码内 5 个默认项；组织器输出 label → `pick_sticker_by_label` 精确匹配 → 字符重叠模糊降级 → 同分随机；用户上传走 multipart + 扩展名白名单 + 路径校验（防 `../`），默认项不可删。

### 4.8 配置体系（`app_config.py` + `config.json`）

- 磁盘 `config.json` 仅 6 项（四节点模型 + polisher effort/temperature），运行时默认值在 `_load_config` 补全：`api_key`（DEEPSEEK_API_KEY 环境变量兜底）、`api_base`（仅官方/OpenCode Go 两端点白名单）、主动性三开关与频率等，全部有类型/范围校验。
- 常量：`PORT=8765`、`APP_VERSION="0.7.2"`、`MODES=(story, haruno)`、`DEFAULT_MODE=story`。

### 4.9 前端（`app/static/`）

纯静态三件：`index.html`（首页视图[公告/主题/双图轮播] → 聊天页 → 设置面板 → 汉堡菜单 6 tab：设定文件/气泡主题/表情包管理/流萤状态/请求记录/流程日志）；`app.js`（全部 `fetch` 调后端；发送≠提交：发送即 POST /chat，后端 5s 合并窗口 + hint/flush；10s 轮询主动性；消息渲染 text/sticker/narration 三类型；安卓 WebView 桥 `androidWakeLock`/`androidBridge`）；`style.css`（移动优先、双主题、6 款聊天气泡、内置 StarRailFont）。

### 4.10 人设资产（`app/assets/character/`）

每模式固定文件：`core.md`（核心上下文，用 `[事实]/[经历]/[若]` 时态标记）+ `identity.md`（关系/习惯/认知边界）+ `sms_samples.md`（短信风格）+ `用户设定.md`（用户可编辑，与核心同等权威）。story 版 196+68+49 行；haruno 版 87+61+72 行。首次启动拷贝到 `user_data/{mode}/character/`。

## 五、服务器版：`server/`（不入 git）

### 5.1 入口 `server_app.py`（327 行）

- 复用方式：sys.path 注入后 `import routes / modules.app_config` 等——**本地版全部业务流水线 100% 复用**，入口只新增认证与上下文接线。
- 多用户隔离：`_setup_user_context` 为每请求建立 `user_data/{user_id}/` 的 `contextvars` 上下文（`set_user_context(user_dir, api_key=X-API-Key 头[:128], api_base=白名单, proxy)`，finally reset）；所有模块路径经 `mode_root()` 派生，relay 队列/缓存/信号量按 `user_scope_key()` 分键，杜绝串数据。
- 认证：`_PUBLIC_*`（/health /login /auth/mail-send /auth/register /auth/login /version.json）外全部要求 `_bearer_user()` 校验，未登录 401。
- 新增端点：`POST /auth/{mail-send,register,login,logout}`、`GET /auth/me`、`GET /version.json`（免登录检查更新）、管理端口 **8766**（仅 127.0.0.1，SSH 隧道访问）：`GET /admin` 页面 + `/admin/api/users`（列表/封禁/解封/额度/删除）。
- 收缩模式：`/opt/firefly/.shrink` 存在 → 注册/发码 503（由攻击哨兵触发）。

### 5.2 用户系统

- **`auth.py`**（163 行）：注册四门槛 = QQ 邮箱（仅 @qq.com/@foxmail.com）+ 邮箱验证码（5 分钟一次性、60s 重发、IP 10 次/时）+ QQ 群号（1097936258，邀请制）+ 安装隐藏代码 `inst-`+32hex（crypto 随机，users.install_id UNIQUE，一安装一号防重复注册）；密码 `scrypt(n=16384,r=8,p=1)` + 16B 随机盐；token = `secrets.token_urlsafe(32)`，30 天过期可撤销；登录失败 5 次/15 分钟锁定。
- **`db.py`**（224 行）：SQLite 标准库零依赖，单连接 + 锁串行化。`users` 表（id/email/phone 遗留/password_hash/salt/role/quota_api_proxy/status/install_id/created_at）+ `sessions` 表（token PK/user_id/device/created_at/expires_at）；`ensure_auth_columns()` 旧库迁移。聊天数据不落 DB，走文件系统 `user_data/{user_id}/{mode}/`。
- **`mail.py`**（121 行）：SMTP smtp.qq.com:465 SSL；凭据环境变量 `FIREFLY_SMTP_USER/AUTH`（systemd 注入，不硬编码）。

### 5.3 公网网关 `download_server.py`（400 行，端口 8787）

三重职责：① 下载页 `/download/`（白名单：firefly-setup.exe / firefly.apk / firefly-server.apk[302 直连 Gitee 发行版，服务器零带宽] / version.json；>5MB 大文件 2 信号量排队、同 IP 1 个、超 10 分钟 503；路径穿越 404）；② **反代**其余路径到 127.0.0.1:8765（透传 X-Forwarded-For，服务端只信任本机来源）；③ CORS 预检。限流 300 次/分/IP（适配 relay 1s 轮询）。

### 5.4 前端（`server/frontend/`）与 relay 机制

- `config.js`：`window.FIREFLY_SERVER_BASE` —— 服务器地址**单点**（Kotlin 壳与 JS 同读）。
- `login.html` + `index.html` + `app.js`（1717 行，比本地版 +241 行）：fetch 统一包装（Bearer + X-API-Key / X-API-Base / X-API-Mode 头）；401 自动弹登录；**relay 后端代理**（1s 轮询 `/relay/pending` → 本地填充 `__CORE__/__IDENTITY__/__SMS_SAMPLES__/__KNOWLEDGE__` 占位符 → 用户 Key 直连 api_base 代发 → `/relay/result` 回传；CORS 失败降级 `/relay/proxy`——服务器用 X-API-Key 头代发，**Key 内存即弃不落盘**，call_id 必须匹配队列真实 pending 项）；资产本地化（`/assets/index` 指纹对比 → `/assets/raw` 下载 → localStorage 按 mode 缓存）。
- `admin.html`：用户统计/搜索/表格/封禁/解封/删除（需邮箱二次确认）。
- **Key 归属**：API Key 只存用户浏览器 localStorage；服务器全局配置（模型/思考档位/主动性）由管理员设定，所有用户共享。

### 5.5 端口模型

## 十、打包与发版闭环

```
PyInstaller（firefly.spec，one-folder，排除 torch/numpy/PIL 等重库）
  → dist/firefly/firefly.exe → Inno Setup（package/firefly.iss，CloseApplications 支持静默升级）
  → package/firefly-setup.exe ─┐
Gradle assembleRelease（android/，syncBackend 自动同步后端）→ firefly.apk ─┤
                                                                             ├→ GitHub + Gitee 双平台 Release（资产名固定不带版本号）
                                                                             └→ 服务器 /opt/firefly-downloads（8787 下载页）

  → /update-download：URL 白名单 + 大小校验下载；exe → /VERYSILENT 静默覆盖安装并自关；apk → 引导系统安装器
```

## 十一、数据隐私与 git 边界

- **本地版**：服务只绑 127.0.0.1；Key 存 `user_data/config.json`；所有用户数据在 `user_data/`，升级不覆盖（Inno Setup 排除 user_data；发版前必须清空 `dist/firefly/user_data`）。

- **git 边界**：`server/`、`user_data/`、`android/keystore/`、`android/app/src/main/python/backend/`、`build/ dist/ android/sdk/` 等均 gitignore；**铁律：绝不 push GitHub**（历史曾含 server/）；备份靠 git bundle + keystore 目录备份。

## 十三、设计原则落地情况

1. **模块铁律**（审查→处理→验证→输出）：analyzer/organizer/polisher/llm_retriever/context_manager/conversation_store/memory_manager 全部实现输入审查、输出验证、失败降级 + 计数器监控。
2. **三层思考法**：人设文件用 `[事实]/[经历]/[若]` 时态标记区分客观事实、个人经历与假设；核心人格稳定层 + 分析层权威解读动态层分离。
3. **模型选择规范**：默认 Flash + Think High；Non-think 必须显式 disabled（检索器/组织器/动机决策等简单分类用）；检索器 temp 0 保格式；实测成本记录在 `docs/成本与缓存记录.md`。
4. **依赖最小化**：无 Web 框架（自研 http.server 分发）、无向量库（LLM 子代理检索替代 RAG）、SQLite/SMTP 全标准库、安卓无本地模型；`requirements.txt` 仅 requests。

## 十四、观察与遗留问题（读码发现）

1. **版本漂移**：`server/version.json` tag=v0.7.1 落后于 `app.js CURRENT_VERSION=0.7.2`；`check_version.py` 未校验 server 侧两处前端副本。

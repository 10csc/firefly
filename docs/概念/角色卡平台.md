# 角色卡平台

角色卡平台是服务器上的登录后网站，负责角色卡的生产和分发；它不是服务器版 App。

## 边界

| 平台提供 | 平台不提供 |
|---|---|
| 广场、详情、搜索、筛选、排序 | App 聊天页 |
| 制卡、草稿、审核、发布、改编 | 对话、记忆、手账 |
| 我的卡、举报、管理治理 | App 的 `index.html`、`bundle.js`、面板和 App 样式 |

服务器对 App 页面返回 302 或 404，对平台页和平台 API 放行。`server/frontend/` 只允许平台白名单文件；`tools/sync_frontends.py` 不得再把 `app/static` 镜像到服务器。

## 用户流程

```text
登录
  → 浏览广场 / 搜索筛选
  → 下载卡体
  → 安装到 user_data/{mode}/character/
  → 在 App 中作为角色包使用
```

制卡流程：

```text
填表/上传素材
  → 存草稿
  → 使用自己的 API Key 提交 AI 审核
  → 审核通过后发布
  → 可举报、下架或由管理员治理
```

AI 审核 Key 只用于当次审核，不落盘。审核截断时必须明确说明“抽检不等于全文过审”。管理员免审，但操作仍留痕。

## 数据与配额

- 卡片本体只含 `character/` 子树，不含 `data/`、`journal/`、`images/`。
- 服务器模式每人最多安装 5 张广场卡，总占用不超过 8MB。
- 卡片有文件数、文本总量、整卡体积、图片尺寸和标签数量上限；前后端必须使用同一规则。
- 下载计数、缩略图和缓存必须避免每次请求触发全量索引重建。
- 用户卡与服务器账号数据按 uid 隔离；普通用户不能借载荷伪装官方身份。

完整卡包字段和图片限制见 [角色包格式](../参考/角色包格式.md)。

## 发布边界

- 平台前端由 `build_frontend_bundle.py --platform` 和 `build_platform_css.py` 生成。
- App 热更新只覆盖 App 的 `web/` 层，不会更新服务器平台页。
- 平台页改动必须重新生成平台产物并按服务器部署清单上传。
- 服务器不暴露 App 前端，是硬性架构约束，不只是文件整洁问题。

## 验收

修改平台后至少验证：

1. 未登录访问广场和卡片内容被拒绝。
2. App 页面与 App 静态资源在服务器不可达。
3. 登录、列表、详情、安装、开新对话、制卡、草稿、审核、发布、改编和举报链路可达。
4. 账号隔离、官方标识和治理权限无法通过请求体绕过。
5. 移动视口无横向溢出，实际浏览器中存在关键按钮，而不是只检查 DOM 字符串。

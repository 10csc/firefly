# 产品与架构

Firefly 是一个面向流萤角色扮演的独立 Agent 平台。官方默认体验以流萤为中心，同时开放角色包编辑、发布和安装，使其他角色可以复用同一套运行框架。

## 设计目标

- 本地优先：断网时聊天、角色包和已有数据仍可用。
- 角色可替换：人格、知识、提示词、演出形态与视觉资产由角色包声明。
- 数据可迁移：对话、记忆、手账和收藏不锁在服务器。
- 失败可降级：工具、公告、语音或更新失败不能阻断文字聊天。
- 发布可追溯：整包、热更新和公告都有签名、版本和可恢复路径。

## 运行形态

| 形态 | 负责 | 不负责 |
|---|---|---|
| 本地版 `app/` | 单机聊天、角色包、本地数据、更新客户端 | 对外提供平台账号服务 |
| Android 壳 | 启动内嵌 Python 服务、WebView、系统能力桥 | 复制一套业务逻辑 |
| 生产服务器 `server/` | 账号、同步、下载、更新、公告、平台 API | 提供 App 前端副本 |
| 角色卡平台 | 登录、广场、制卡、审核、发布、治理 | 聊天、记忆、手账 |

## 对话流水线

```text
用户输入
  → LLM 检索器：从角色知识库生成相关摘要
  → 分析器：意图、事实核查、上下文摘要
  → 回复器：按角色设定生成多条消息
  → 组织器：按角色包声明调度表情、旁白或未来工具
  → ContextManager + conversation_store：写历史和观测数据
```

前三段的数据结构与提示词注入位置冻结。新工具从组织器接入，不在中途插入新阶段。完整接入契约见 [开发与扩展协议](../参考/开发与扩展协议.md)。

## 角色包

角色包由 `preset.json` 作为唯一入口，包含角色文本、知识库、提示词覆盖、开场、表情与图片。内置包与用户副本分离：

- 内置包放 `app/assets/character/<id>/`。
- 用户修改写 `user_data/{mode}/character/`。
- 删除用户副本恢复默认。
- 对话、记忆、手账不属于角色包。

格式与限制见 [角色包格式](../参考/角色包格式.md)。

## 数据位置

| 数据 | 位置 |
|---|---|
| 全局配置与 API Key | `user_data/config.json` |
| 角色运行数据 | `user_data/{mode}/data/`、`journal/`、`images/` |
| 用户角色卡副本 | `user_data/{mode}/character/` |
| 热更新覆盖层 | `{FIREFLY_DATA_DIR}/hotupdate/` |
| 公告缓存 | `{FIREFLY_DATA_DIR}/notice/` |
| 语音模型 | `$FIREFLY_DATA_DIR/voice/`，不进备份与同步 |

用户数据按角色模式和服务器账号隔离。任何同步、备份或部署都不得把真实用户目录提交到仓库。

## 模型

默认使用 DeepSeek API。实际模型名、供应商和思考档位由配置决定；代码统计入口统一经过 `llm_base`，禁止在业务模块里裸调 API 绕过 token 与成本记录。

# 同步与离线

同步采用本地优先模型：用户操作先落在本机，服务器负责给变更分配权威顺序。同步失败只能延迟收敛，不能让本地数据消失或被旧副本覆盖。

## 核心概念

| 概念 | 含义 |
|---|---|
| `mid` | 新消息身份；旧消息迁移为稳定 legacy id |
| `epoch` | 清理历史的代际；旧 epoch 消息不得复活 |
| `history_rev` | 历史、撤回和清理的服务器版本 |
| `memory_rev` | 记忆整理产物绑定的服务器版本 |
| `op_id` | 破坏性或可重试操作的幂等键 |
| `tombstone` | 删除标记；防止旧设备或旧响应把数据并回来 |
| `base_rev` / `base_sha` | 条件写入前提；不匹配返回冲突，不用 mtime 猜测胜者 |

## 本地提交

多文件操作必须经过：

```text
PREPARED → 数据和本地状态落盘 → COMMITTED → 才允许上传
```

恢复失败时保留事务现场并拒绝覆盖。outbox 只在服务器确认后删除；同一时刻只有一个写入者更新 outbox。

## 在线回合

1. 读取服务器状态和 rev/epoch 水位。
2. 按顺序发送 outbox 操作。
3. 服务器校验 `op_id` 幂等和 `base_rev`，应用后分配新 rev。
4. 客户端确认后删除 outbox。
5. 文件同步使用 manifest、`state_rev` 和 `base_sha` 条件写入。
6. 冲突进入 `.sync_conflicts/` 并提示用户，不静默覆盖。

## 失败语义

| 情况 | 结果 |
|---|---|
| 发送前断网 | 本地已提交，outbox 保留 |
| 响应丢失 | 用同一 `op_id` 重试，服务器返回原结果 |
| 恢复失败 | 暂停该模式同步，保留现场 |
| 服务端 pending 未恢复 | 拒绝新 op，不能覆盖 pending |
| 旧 rev 写入 | 返回 stale/409，客户端重新读取 |
| clear 与离线 append 交叉 | 冲突备份并提示，不直接复活历史 |
| 收藏删除 | 墓碑双向过滤 |

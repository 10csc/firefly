- **error_code 透传（第一刀）**：四模块 `except Exception` 降级输出新增 `degraded`/`error_code` 字段（`error_code_of` 提取 ApiError 分类）；orchestrator `_first_degraded_code` 聚合首个非空码进 /chat 响应 → 前端 `ERROR_TIPS` toast 即刻生效（key_invalid/no_balance/rate_limit/quota_exhausted…）。setting_fix 路径 `fix.js` 补读 error_code 映射。

### W5 部署项（需用户批准，未动生产）——HTTPS 方案

- **现状**：全链路明文 HTTP（公网 8787；token/Key/邮箱验证码明文过公网）。改进密钥透明质在 W1-W3 已减少（Key 不落服务器、转发经代理）。

- **阻塞条件**：Let's Encrypt 需域名 + 证书签发；**国内云服务器 80/443 需 ICP 备案**——无域名/备案则只能维持 http 或自签证书（自签有证书告警，用户体验差）。
- **建议**：用户决策项——①购买域名并完成备案（时间最长，但彻底解决）；②暂维持 http（现状，仅本地开发/内网）；③自签+固定证书（不推荐）。定档后再实施（Caddy 二进制 + 容器化反代 + 后端零改动）。

- **`app/modules/vision.py` 新模块**：`describe_image`（vision 模型走 OpenAI 兼容 image_url block，non-think 短输出 ≤300 字）+ `to_data_url`；失败/无模型降级空串（用户手填/[图片] 占位）；`record_usage/record_error` 记账。
- **`POST /upload-image`（本地版）**：multipart 审查（ext 白名单/≤10MB）→ 落盘 `{mode}/images/{uuid}.{ext}`（storage.atomic_write_bytes）→ desc 生成（供应商 caps.vision 才调用）→ `{ok, img_id, file, desc, need_desc}`；服务器版 403（字节不出设备）。
- **`GET /image?id=`**：本地版图片字节服务（glob img_id.* + ext MIME；路径校验防穿越）；服务器版 404。
- **首轮识图**：routes /chat 图片消息分支 → data URL（≤4 张）随窗口传递 → `handle_chat(vision_images=...)` → polisher user 消息 content blocks（文本 + image_url；仅 `_caps_vision` 时装配）；pipeline.jsonl 只记 `[图片：desc]` 文本（字节零落日志）。
- **前端**：输入区 🖼 发图按钮 + 选择器（accept png/jpg/webp/gif）；发送流——本地版 upload→描述（vision 失败 prompt 手填）→ image 消息；服务器版图片存 IndexedDB（key=img_id）→ 描述提交；`addImage` 渲染（本地 /image/、服务器 IndexedDB、缺失显示 desc/失效占位）；长按快照/引用预览/`_snapHasContent` 加 image 分支。
- 测试：`tests/test_image_flow.py` 16 项（校验/落盘无字节/引用/hydrate/vision 成功失败降级/blocks 结构/upload 落盘//image 服务）；全量 27 脚本绿（models lock 测试按 W5 语义更新 proxy 分支断言）。
- 遗留：①W6 UI 冒烟（Playwright 发图流程）待 W7 总验收；②安卓 `onShowFileChooser` accept 扩展随 A7c 真机批做；③服务器版 relay 的"视觉 desc 由浏览器调用 vision 模型生成"留将来（当前服务器版发图=手填描述，已尽铁律）。

## 主题 1：离线优先数据同步

关键结论：
- LWW 简单但设备时钟不可信，需服务器单调序列号或 HLC 兜底；向量时钟对单用户小数据过度设计；oplog/outbox 与 append-only 对话天然匹配；CRDT 不适合本项目三类数据。
- 裸 `updated_at` 当游标会永久丢行（同事务共享时间戳）；tombstone 需 30-90 天保留窗；幂等靠客户端 UUID（UUIDv7 优于 v4）+ 操作 ID。
- WatermelonDB 内建协议 = 时间戳游标 + 软删除，证明该最小协议是主流验证过的模式。
- 现成方案时效：Realm Device Sync 2025-09-30 EOL；ElectricSQL 旧写路径产品已搁置；PowerSync 可自托管、托管 $49/月起；CouchDB/PouchDB 对单用户小应用过重。

## 主题 2：LLM API 网关容错

关键结论：
- Full Jitter 退避是 AWS 官方推荐默认；429 优先遵守 Retry-After；余额/配额类错误重试无意义——重试必须按错误类型分类。
- 熔断可简化为冷却（LiteLLM cooldown：429 立即冷却、失败率超阈值冷却、到期自动恢复）；重试必须由 Router 独占，避免与 SDK 内重试叠加成 (1+N)²。
- DeepSeek：账户级并发限制（多 key 轮询不能扩容，要扩容走官方申请）；请求 10 分钟未开始推理会断连（影响超时预算）；status.deepseek.com 月可用率 99.7-100% → failover 不是可选项。
- new-api 是 one-api 的活跃分支（多 key 轮询、渠道自动禁用）；原 one-api 停维护且有未修复 CVE-2025-3801，不选。

## 主题 3：角色扮演应用前端 IA 与数据规范

关键结论：
- World Info = 关键词扫描→动态注入（确定性匹配，非模型检索）；中文等无空格分词语言应关闭整词匹配（官方警告）；作用域四级（全局/角色/Persona/单聊天）；注入位置与 token 预算可控。
- 角色卡 V2（chara_card_v2）是 Chub.ai 等平台事实标准：`spec/data` 包裹、alternate_greetings、character_book、extensions（未知字段必须保留）。

- 导航共识：移动端 3-5 个底部 tab；桌面 Web 左侧会话列表 + 抽屉（SillyTavern）。

## 主题 4：多端统一后端

关键结论：
- Chaquopy 活跃维护（17.0.0，2025-12），Python 3.10-3.14，minSdk 24；官方 wheel 仓库有 numpy/pandas/pillow 等但**无 onnxruntime**（issue #985 未解决）——ONNX 推理须走 ONNX Runtime 官方 Kotlin API 与 Python 编排层解耦。
- 生产先例：Electron Cash（Google Play 上架）、FrostWire。已知坑：multiprocessing 不可用、冷启动 +数百 ms、重依赖 APK 可达 100-150MB（大模型走运行时下载）。
- 客户端直连 LLM API = key 泄露，业界共识必须服务端中转，除非 BYOK（本项目正是 BYOK + 托管双轨，成立）。

## 主题 5：DeepSeek 平台事实核查（2026-08-21，为三条新需求）

关键结论：
- **官方现行模型名**：`deepseek-v4-flash` / `deepseek-v4-pro`（旧名 `deepseek-chat`/`deepseek-reasoner` 已于 2026-07-24 停用）。前端中文档位名（"快速/更强"）无官方依据，应改官方英文原名。
- **识图模型已上线**：`deepseek-v4-flash-vision-exp`（2026-08-21 发布，**实验性**），OpenAI 兼容 content block 格式（`image_url` base64 data URL / 外部 URL / Files API `file_id`）；纯文本能力与 v4-flash 持平。仅该模型接受图片（其他模型 400）；图片只允许出现在 `user` 消息；格式 JPEG/PNG/GIF/WebP；每图自动缩放至约 800×800、**token 上限 384/张**；base64 内联计入 48 MiB 请求体上限。（2026-08-22 复核官网 vision 指南确认不变；另有 `detail=low` 512×512 省 token 档、单图最大 32 MiB、单边最长 8192px——本项目前端预压缩到单边 ≤1024px/≤300KB，远在限制内。）
- **思考强度已变三档**：2026-08-13 起 V4-Pro/V4-Flash 支持 `low / high / max` 三档——项目代码 `effort_map` 把 low 映射成 high（`llm_retriever.py:136-139` 等四处）与 CLAUDE.md「low/medium 被映射为 high」的表述**均已过时**。
- **峰谷定价 2026-08-17 生效**：闲时半价。`llm_base.py:164-168` 的静态定价表（仅两个模型、无峰谷）从此失真，成本统计只能当约数。
- **模型列表端点存在**：`GET https://api.deepseek.com/v1/models` 实测（2026-08-21）无 Key 返回 401、假 Key 返回鉴权错误体——端点存在且需鉴权，OpenAI 兼容惯例。「一键获取官方模型列表」对 BYOK 场景成立。OpenCode Zen 侧 2025-10 仍无 `/v1/models`（sst/opencode#2901），托管链路（mimo-v2.5）不能用此机制。
- **多供应商默认协议**：OpenAI ChatCompletions 兼容是行业事实标准；DeepSeek 另原生支持 Responses API 与 Anthropic 端点，但本项目只需 ChatCompletions。

来源：
- https://api-docs.deepseek.com/zh-cn/updates/ （V4 发布/旧名退役/三档思考/峰谷定价/vision-exp 发布，全部日期与模型名以该页为准）
- https://api-docs.deepseek.com/zh-cn/guides/vision （图像理解：三种传图方式、限制表、token 换算）

- https://github.com/sst/opencode/issues/2901 （OpenCode Zen 无 /v1/models，2025-10）

## 未决项（诚实标注）

- Ditto 定价、Chaquopy vs 原生量化 benchmark 无可靠公开来源，需自行实测。
- Character.AI 移动端精确 tab 结构无官方 IA 文档，本报告相关描述为媒体评测口径。
- `deepseek-v4-flash-vision-exp` 为实验模型，**有效期/转正时间/定价官方未公布**——方案中按其随时可能下线设计降级路径。
- 托管链路当前上游（OpenCode Go mimo-v2.5）是否支持图片输入无公开文档——由服务器侧路由实测决定即可，**客户端不因此禁用图片**（所路由模型不识图时，服务器侧自行走 desc 文字化路径，客户端无感）。
- 用户已明确（2026-08-21）：**不固定 OpenCode Go**——客户端只处理「是否使用服务器托管 API」开关，服务器内部处理上游路由；客户端代码与配置不得出现 OpenCode/mimo 特有概念。

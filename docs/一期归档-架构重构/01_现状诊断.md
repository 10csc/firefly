## 1. 三端实际形态

- **PC / 安卓 / 服务器共用同一套 Python 后端与同一套前端**。
  - 安卓不是原生 App：Kotlin WebView 壳 + Chaquopy 内嵌 Python 3.12，构建时 `syncBackend` 把仓库根 `app/`、`knowledge/`、`database/` 打进 APK（任务定义 `android/app/build.gradle.kts:12-26`，`:28-29` 挂接 preBuild），前端资产由 `syncFrontendAssets` 同步（`:35-52`），来源有三处：`app/static`（排除 config.js）+ `server/frontend/{config.js,login.html}` + `app/assets` 子集（背景图/字体/图标，`:40-47`）。
  - 服务器 `server_app.py` 直接复用 `app/routes.py` 整张路由表（`server/server_app.py:352,404`），外加认证层。
  - 前端双目录 `app/static/` 与 `server/frontend/` 的**共享文件逐字节一致**（`tools/sync_frontends.py` 按 md5 同步，`--check` 实测通过）；设计内差异：`config.js` 两版有意不同（local/server），`server/frontend` 独有 `login.html`、`admin.html`，`app/static` 独有 5 张 PNG。运行时统一加载 `tools/build_frontend_bundle.py` 拼出的 `js/bundle.js`。
  - **推论：任何"数据层/同步层"设计只需写一遍 Python，三端天然共享。这是本项目最大的架构资产。**

- 安卓双模式：SharedPreferences 文件 `firefly_prefs` 的 key `firefly_mode`（`MainActivity.kt:59-72`），切换 = `finishAffinity()` + `killProcess()` 杀进程重启（`MainActivity.kt:489-506`，杀进程在 `:503`）。local 模式起内嵌 server（启动入口 `start_server.py:28-52`；绑定 127.0.0.1:8765 实际在 `app/server.py:166` + `app_config.py:117`）；server 模式加载 `file:///android_asset/index.html` + Bearer token 跨域请求（`js/api.js:26-57`）。

## 3. 问题清单（按需求归类）

### 3.1 数据同步：现状为零

- **没有任何自动同步代码**。唯一的传输是手动 zip：`/export-data`（`routes.py:921-943`）→ DownloadManager 落盘（`MainActivity.kt:462-478`）→ 对端 `/import-data` 覆盖导入（`routes.py:1042-1055`）。

- 导出**不含** `config.json` 与 `stickers/`（`routes.py:928-935` 只打包 mode 目录）——换机会丢配置与自定义表情包。注意 `export_data` docstring（`routes.py:922`）自称含"表情包"，**与实现不符**。UI 文案（`index.html:597`）只承诺「对话/记忆/手账/设定（不含 API Key）」，与导出行为字面上不矛盾；真实问题是**导出范围不满足换机迁移场景**的预期差。
- UI 自己写明"本地与服务器数据相互独立"（`index.html:406`）。

### 3.3 上游托管容错（精读后的真实调用链）

**每轮 /chat 上游调用次数：story 4 次、haruno 3 次**（retriever non-think → analyzer think-high → polisher think-high → organizer non-think；haruno 跳 retriever、organizer 旁白强制 think-high——`organizer.py:247-251`）。旁路：/rest 1~2 次、主动消息 2~3 次、设定纠错 1~2 次、撤回/清空 0 次。模型/thinking 档出处：`orchestrator.py:286-356`、`llm_retriever.py:163-175`、`analyzer.py:148,205-213`、`polisher.py:397-405`、`organizer.py:185-194`。

**精读新发现（比之前更关键的三个结构性问题）**：

### 3.7 记忆子系统定位（精读，对应"单会话"修正）

用户判断成立：一个模式只有一个会话，"跨会话"叙事多余。**但 memory.md 的真实技术职能是「窗口外旧对话的压缩存档」**——各消费方固定窗口读取（retriever 锚点 10 / analyzer 20 / polisher 15 / organizer 5 / 重启回灌 40 轮，`orchestrator.py:283-354`、`conversation_store.py:345`），窗口外内容对 LLM 永久不可见，唯一补偿就是 rest 把旧内容压进 memory.md 头部。单会话无限增长时这个职能**更不能删**，只是名字该改。

- rest 流程：LLM 重写头部（500-1000 字整合）+ 标记已解决 + 追加承诺/偏好/事件条目（`memory_manager.py:172-214`）；游标 `.memory_index` 按 user 轮计（`:160-166`）。尾部事实区**不进任何生成 prompt**（load_tail 只有 rest 自己用）。
- **rest 后不刷新当前会话的 memory_head**（`routes.py:526-545` 只 reload 手账），新头部要等进程重启或 30 会话淘汰才生效——真 bug。
- **undo 不回退 `.memory_index`**（`routes.py:826-838`），被撤回轮次的内容后续 rest 永远不会被整理——真 bug。
- rest 仅手动触发（菜单「让流萤休息」`index.html:698`→`chat.js:678`），无任何自动触发；遮罩结果文案先隐藏再写入导致**用户看不见结果**（`chat.js:681-692`）。
- backdoor 隐藏通道硬编码 `memory_head=""`（`proactive.py:985`）；手账链路独立于 memory.md 且每轮进 system 稳定层（`polisher.py:116,221,342`）。
- "跨会话"字样分布：`polisher.py:37,347`、`proactive.py:432`、`routes.py:1237`、`panels.js:727`（注意 `memory_manager.py:2` docstring 写的已经是"单会话"）。

### 3.8 三条新需求与平台事实（2026-08-21 用户确立 + 当日联网核查）

**新需求原文要点**：
1. **登录基本操作化**：注册登录是使用前提（无法维持"登录/游客"两个状态的更新）；数据默认存本地；**本地后端无法启用时才自动连接服务器后端**（删除手动模式切换按钮）；登录态更好地支持数据自动同步。
2. **多供应商模型配置**：不再固定模型；用户可自填供应商（默认 DeepSeek 自动填入，用户只需输 SK；已有用户的 SK 自动迁移）；默认 OpenAI 兼容格式；DeepSeek 支持要做好——一键获取官方模型列表、前端用官方英文模型名（不用"快速"这种中文档位名）。
3. **图片数据策略**：DeepSeek 已有识图模型；**服务器不保存图片数据**——托管或仅作后端都只传输不存储，最多保存 AI 返回的文字结果。

**当日平台事实（出处与实测见 06 主题 5）**：
- `deepseek-v4-flash-vision-exp` 识图模型 **2026-08-21 当天上线**（实验性）：OpenAI 兼容 `image_url` content block；仅 `user` 消息可带图；JPEG/PNG/GIF/WebP；每图缩放至约 800×800、token 上限 384/张；base64 计入 48 MiB 请求体上限。
- 思考强度已是 `low/high/max` 三档（2026-08-13）——**代码 `effort_map` 把 low 映射成 high（`llm_retriever.py:136-139`、`analyzer.py:146-149`、`polisher.py:318-322`、`organizer.py:133-136`）与 CLAUDE.md「low/medium 被映射为 high」均已过时**。
- 峰谷定价 2026-08-17 生效（闲时半价）——`llm_base.py:164-168` 静态定价表失真，成本统计降级为约数。
- `GET /v1/models` 实测存在且需鉴权（2026-08-21 curl：无 Key 401）——「一键获取模型列表」可行。

**需求与现状的差距（因果链结论）**：

## 1. 复审方法与总体结论

- **方法**：8 个只读审查代理逐波核对执行日志声称 vs 实际代码（W0-W7 全覆盖）+ 主审亲自精读全部复杂决策点（`app_config.py` 迁移/providers/锁、`api_client.py` 重试/冷却/超时、`sync_engine.py` 合并裁决、`orchestrator.py` 超时预算、routes 同步/导出/图片段、`auth_store.py` 宽限）+ 全量 28 测试脚本独立复跑。
- **总体结论**：执行质量主体可信——声称的功能绝大部分真实落地，「全绿」属实，没有发现大面积造假。复杂决策点（配置迁移、token 不落前端、配额查扣分离、表情包经过式、db 死锁修复）做对了。
- **但存在**：1 处越权拍板（推翻已关闭的用户决策）、1 处铁律破口、1 处刷新即现的 UI 断链，外加 6 个中等问题与若干低危项。

## 3. 用户三条新拍板（2026-08-22）

1. **图片恢复经过服务器**（推翻 W6 收敛）：托管/relay 都经过服务器（iOS/鸿蒙后台冻结使 APP 填充占位符不可靠）；本地模式不出设备。发图前端预压缩——依据 [DeepSeek 官方 vision 文档](https://api-docs.deepseek.com/zh-cn/guides/vision)：进模型自动缩放约 800×800、每图 token 上限 384，超出纯白传；故压缩到单边 ≤1024px / ≤300KB，GIF 不动。
2. **手动云端备份下线**：数据全自动同步（登录/回前台/进聊天页触发，10 分钟节流，进度提醒）；备份改本地 `{用户目录}/backups/`，APP 内可视化管理。
3. **压缩图 = 正式消息数据**：本地与服务器各存一份，随同步走。铁律口径修订为「**服务器只存压缩图，原图不出设备**」（压缩在前端完成）。原「relay `__IMG_` 占位符 + proxy 内存 TTL 经过式」设计废弃——压缩图落盘同步后换设备直接有真图，经过式队列失去存在必要。

## 4. 落地改动清单（按模块）

- **前端压缩**：新增 `app/static/js/imgzip.js`（`compressImage`，Canvas，零后端新依赖，已入 bundle ORDER）。
- **图片链路统一**：`/upload-image` 服务器版开放落盘（`routes.py`，经 `_user_ctx` 隔离）+ 每用户配额 `FIREFLY_IMAGE_QUOTA_MB`（默认 200MB，上传与同步导入两侧同查）；`GET /image?id=&mode=` 两端统一字节服务；前端发图先压缩再上传；IndexedDB 图片存储退役（**表情包 IndexedDB 保留**）；`renderHistoryMessage` 补 image 分支；`addImage` 补 mode。
- **首轮识图三链路**：本地=caps.vision（不变）；proxy=QuotaClient 默认开（mimo-v2.5 识图，每条图片消息 = 1 次 desc + 1 次 polisher，正常记账，已按服务器红线 §7 申报）；relay=payload 模型名含 vision 才注入（`orchestrator._caps_vision(client, model)` 门控，防非视觉模型 400 整轮降级）。
- **同步纳管图片**：`storage.REGISTRY` 接线为唯一真相源（`is_syncable`/`is_blob`；images 策略 `metadata`→`blob`，stickers 维持本地策略）；`sync_engine` 范围审查改查注册表；`sync_import`/`sync_now` 支持 blob 字节直传（不解码不合并）。
- **合并收敛**：`merge_jsonl` 去重后确定性重排（seq / _ts / time / sha 分档键，同键 tie-break 行 sha8）——两端各自合并字节一致、sha 收敛。
- **备份本地化**：删 `/sync/upload`、`/sync/download`；新增 `POST /backup/create`、`GET /backups`、`POST /backup/restore`（先自动 pre-restore 备份）、`POST /backup/delete`；`export_data` 排除内部目录 + 支持 `&name=` 下载既有备份；前端数据面板改本地备份列表管理。
- **自动同步**：`window.autoSyncNow(force)`（panels.js；节流/并发护栏/状态条/冲突橙色警告）；挂接 登录态确认 / showChat / visibilitychange / 模式切换；手动「立即同步」强制不节流。
- **容错修正**：relay 失败不触发端点冷却；`_check_deadline` 进两个 create 的重试循环（delay 截断/耗尽抛 timeout）。
- **登录到期强制**：`views.js` gate 补 `offline_ok===false` 分支（显式 verify 三态处理）。
- **undo 游标**：`conversation_store.count_user_turns`（与 `last_integrated_turn` 同为用户轮数口径）。

## 7. 教训（防再犯）

- **方案级变更必须请示**：W6 的「主动收敛」方向再对也是越权——已关闭的用户决策只能由用户推翻。
- **「声称做了」要核到端**：两处「做了一半」（addImage 渲染、云端连接中 UI）和一处「声称全仓库一致实际没有」都是只核声称起点、没核终点造成的。
- **建机制不接消费方 = 没建**：W5 的 REGISTRY 注册表建好却没接线，直接导致了 S2 破口（export 没查注册表）。
- **UI 冒烟要覆盖「刷新后」**：S3 这类历史渲染断链只在重新加载后出现，发送时自测发现不了。

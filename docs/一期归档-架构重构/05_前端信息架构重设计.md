# 05 · 前端信息架构重设计

> 依据：现状前端（01 §3.5）+ 角色扮演/陪伴类应用 IA 调研（06 主题 3）。
> 用户使用逻辑的核心事实：**打开 App = 找流萤说话**。Replika 的极端做法（打开即聊天线程，管理功能全退次级）证明了这一点；Apple HIG / Material 建议 3-5 个顶级目的地用底部 tab。
> 分 A/B/C 三档深度，与方案对应。

## 现状问题（与使用习惯的错位）

1. 首页（home-view，`index.html:228`）挡在聊天前面：用户每次打开先看到轮播图+公告，再点一次才进聊天——与「打开即对话」相悖。
2. 高频功能埋太深：记忆、收藏、角色设定在汉堡菜单 6 个 tab 里（抽屉 `menu-drawer` 在 `index.html:681`，6 个 tab 在 `:687-693`，记忆/手账在「设定文件」tab 内 `:702-725`），和「请求记录/流程日志」这种调试功能同级混排。
3. 安卓与 PC 共用桌面式布局，无移动端导航模式。
4. 双模式与同步状态不可见：用户不知道自己的数据在哪、有没有同步（现状也确实没有同步，01 §3.1）。
5. 上游故障不可见：用户把上游波动当 bug（01 §3.3）。

## A 档（方案 A 配套：最小改动）

- 安卓三主视图改**底部 tab**：`聊天（默认页）｜首页（公告/模式入口）｜我的（设置+数据）`。打开 App 默认落聊天页，首页轮播降级为「我的」里的入口卡片。
- 汉堡菜单 6 tab 分两类：「与她相关」（设定/手账/收藏/状态）留在聊天页抽屉；「与系统相关」（请求记录/流程日志）挪进「我的 → 高级」。
- 设置「数据与系统」组整合为「数据」子页：导出/导入/云备份/立即同步一处办完，文案与真实行为对齐（修 A1 的导出口径）。
- PC 保持现有首页结构，仅同步「数据」子页与菜单分类。
- 首次启动增加注册/登录引导页（登录成为使用前提，2026-08-21 新需求 1）；安卓「我的」里的运行模式切换入口删除，改显示当前后端状态（本地运行 / 云端连接中）。

## B 档（方案 B 配套：IA 重构）

### 三区结构（底部 tab，安卓+PC 窄屏共用；PC 宽屏自动变左侧栏）

```
┌ 对话 ──────────────── 打开即进，默认页
│   ├ 消息流 + 输入区（现状保留）
│   ├ 顶栏：模式标记（剧情/手信）+ 上游状态点（绿/黄/红，读 B3 健康探针）
│   └ 抽屉（与她相关）：本会话设定 / 记忆 / 手账 / 收藏 / 表情包
├ 角色 ──────────────── 角色详情页
│   ├ 角色卡（核心设定、身份、短信样本——现有 4 个 md 的可视化编辑）
│   ├ 世界设定（作用域下沉：角色级设定在此；全局在「我的」；会话级在对话抽屉）
│   └ 设定纠错入口（从首页卡片挪入，fix-view 保持独立页）
└ 我的 ──────────────── 账号与系统
    ├ 账号与连接（登录态 / 当前后端与同步状态——运行模式切换按钮已删除，2026-08-21 新需求 1）
    ├ 同步中心：最后同步时间 / 各端在线状态 / 冲突处理 / 手动同步 / 整包备份恢复
    ├ 模型与速度、主动性、外观（现有设置组平移）
    └ 高级：请求记录 / 流程日志 / 反馈 / 关于
```

### 关键设计决策（每条有出处）

- **会话摘要列表（原"记忆可视化"，按单会话定位改名）**：「自动摘要 + 长按 Pin」是 Character.AI 2025-11 验证的低成本高感知模式（06 主题 3）。把 `memory.md` 的事实条目渲染为可查看/可置顶/可删除的列表（B0 实体化后天然支持），替代现在只能看原始 Markdown。定位是「这段对话的过往摘要与约定」，不是跨会话记忆（01 §3.7）。
- **世界设定作用域四级下沉**：照搬 World Info 的全局/角色/Persona/单聊天作用域（06 主题 3）——角色级进「角色」页，会话级进对话抽屉「本会话设定」，全局进「我的 → 高级」。不做顶级入口。
- **同步中心是信任来源**：双模式用户的最大焦虑是「数据在哪、丢没丢」。同步中心常驻显示：本地 X 条 / 云端 Y 条 / 最后同步时间 / 冲突 N 条待处理，并固定一行说明「图片与表情包只保存在本机，云端仅存文字」（媒体本地策略的用户可见面，01 §4）。
- **上游状态点**：绿=正常、黄=波动（冷却中/已切备用链路）、红=不可用，点击展开「上游服务波动中，回复可能较慢或暂时走备用通道」。把故障从「bug」变成「可见状态」。
- **登录与后端选择自动化（2026-08-21 新需求 1）**：登录是使用前提——首次启动进入注册/登录引导（复用 QQ 邮箱验证码流程），凭证本地缓存、离线宽限期内免登录（宽限期时长见 07 §5.3 决策 9）。原「运行模式切换」入口删除：App 启动自动起本地后端，健康检查失败才自动连服务器后端；前端从「local/server 双态」收敛为「已登录单态 + 后端地址可变」，顶栏只显示「本地运行 / 云端连接中」。
- **供应商与模型设置（新需求 2）**：设置页「模型与速度」组改为「供应商与模型」：供应商列表（默认 DeepSeek，base_url 预填、只需粘 SK）+ 各模块模型输入框（下拉建议用官方英文原名 deepseek-v4-flash / deepseek-v4-pro / deepseek-v4-flash-vision-exp，废弃"快速/更强"中文档位）+「获取模型列表」按钮（`GET {base_url}/models`，可行性已实测，06 主题 5）。自定义供应商按 OpenAI 兼容协议接入；DeepSeek 私有能力（思考档位/缓存命中展示）仅 DeepSeek 供应商显示。
- **图片消息入口（新需求 3）**：输入区加发图按钮；图片气泡本地渲染（IndexedDB/壳层文件）；缺图设备显示占位「（图片仅保存在原设备）」（复用表情包失效模式 `chat.js:98-106`）；同步中心说明行扩写为「图片与表情包只保存在本机，云端仅存文字（含 AI 看图描述）」。
- **剧情分支（轻量版）**：长按回复气泡 →「重新生成」（swipe）/「从此分叉」——消息级实现，不动会话模型（06 主题 3）。
- 主动消息的「对方正在输入」拟态（`proactive.js` 现有 2-5s 模拟）保留不动——它是体验资产。

### 交互技术债（B 档顺手还）

- `/chat-stage` 轮询（`chat.js:485`）与 `/proactive-status` 10s 轮询（`proactive.js:102`）合并为一个 1s-10s 自适应心跳端点 `/events`，返回 `{stage, proactive, sync, upstream}` 四合一——不上 WebSocket（标准库 http.server 不支持，也不值得为此换框架），但把 N 路轮询收成 1 路。
- 前端请求加 AbortController 超时（A3 同项）。

## C 档（方案 C 配套：生态形态）

- 「角色」区扩为多角色列表 + 导入（chara_card_v2 文件/URL）；「发现」页可选。
- PC 宽屏三栏：会话列表 ｜ 消息流 ｜ 角色详情抽屉（SillyTavern 桌面布局共识）。
- 世界书编辑器：关键词→内容→注入位置三元组的可视化编辑（06 主题 3 字段集）。

## 不做清单

- 不做首页 Feed/社区流（与「与她单聊」的产品形态无关）。
- 不做角色 marketplace 前端（C4 的服务端生态成立前不做）。
- 不上 WebSocket/SSE（收益不抵换框架成本；轮询合并已够用）。

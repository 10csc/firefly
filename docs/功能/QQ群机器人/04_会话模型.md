# 会话模型：群级主线 + 群级记忆 + 用户级记忆

## 先说一个必须记住的坑（本项目踩过）

初版在会话层写了一个 `_trim()` 想把主线裁到 40 轮，用 `pop_last_turn()` 实现。这是**两重的错**：

1. **语义反了**：`pop_last_turn` 是给"撤回"用的，移除的是**最新**一轮（优先末尾主动轮），
   不是最老一轮。照那么写，流萤会不断忘掉刚发生的事，只记得很久以前的。
2. **违反缓存铁律**：`auto_rest.py` 文件头写明——分析器把「## 最近对话」放在 user 消息最前面，
   DeepSeek 按**前缀**打折；窗口必须保持"只往后追加"的增长期，老部分才是稳定前缀，每轮只有
   新增那一轮没命中。任何从窗口头部裁剪都会把增长期变成滑动期，**每轮缓存全部失效，反而更贵**。

结论：**会话层不做任何裁剪**。上下文长度交给项目既有的活跃窗口模型，
`ContextManager` 的 token 预算用默认 300000（按文档要求"放宽到正常对话不触发"）。

## 三层结构

| 层 | 归属 | 存储 | 注入位置 |
|---|---|---|---|
| 群级主线 | 整个群共享 | `conversation_store` 标准 JSONL | `ContextManager`，重启 `hydrate_context` 回灌 |
| 群级记忆 | 整个群共享 | `memory.md`（rest 压缩产物） | `handle_chat(memory_head=...)` |
| 用户级记忆 | 每个群成员独立 | `{数据根}/members/{QQ号}.json` | `handle_chat(hint=...)` |

### 为什么主线要带说话人前缀

主线是共享的，十几个人同时说话。每条用户消息写成 `小明：今天天气不错`，
模型才能分清当前谁在说话——否则必然张冠李戴，把 A 说过的事安到 B 身上。

### 为什么记忆分两层

- 群级记忆（`memory.md`）记"这个群发生过什么"，所有人共享，由 rest 压缩产生。
- 用户级记忆记"这个人是谁、喜欢什么"，只在对他回复时注入 hint。

二者不能合并：把 A 的偏好写进共享记忆，会让流萤对 B 也说同样的话。

## 压缩机制（复用项目既有 rest，不另造）

沿用单人版完全同一套：活跃窗口 **100 轮触发整理、整理后保留最近 30 轮原文**
（阈值沿用 `memory_window_turns` / `memory_keep_turns`，与单人版一致）。

整理做两件事：搬走的原文进 `{mode}/data/archive/YYYY-MM.md`（只进检索器），
同一段交 LLM 压缩进 `memory.md`（只进回复器）。

**成本**：每次触发 2 次 LLM 调用（记忆 + 手账）。按 50 轮/天的限流，约两天触发一次，
占总预算约 1%。触发走 `auto_rest.maybe_schedule`，在后台线程跑，不占用户等待。

群聊与单人对话的差别在于**轮次膨胀快得多**（十几个人，一人一句就是十几轮），
当前仍沿用 100 轮——因为限流把每天压在 50 轮，实际约两天一次，与单人版节奏相当。

## 内存水位：常驻进程必须有界

`ContextManager.token_capacity` 只在 `get_recent` 兜底、**不裁剪** `_history`，所以内存历史会一直涨。
单人版靠"用户关掉应用再打开"自然回灌；**群聊进程是 7×24 常驻的**，按 50 轮/天算一个月就是 1500 轮。

处理方式是**重建**而不是裁剪：内存轮数超过 `window_max + keep_turns`（默认 130）时，
用盘上数据 `hydrate_context` 重新灌一个上下文。

- 为什么不是裁剪：裁剪会打掉前缀缓存（见文件头铁律）。
- 重建同样会让缓存失效一次，但它与 rest 整理后的窗口口径一致（都保留最近 `window_max` 轮），
  且频率被水位压到每 130 轮一次——这正是活跃窗口模型已经接受的代价。

## 用户级记忆：规则抽取，零 LLM 成本

只认**显式自述**，不猜：

- `我叫X` / `叫我X` / `我是X` → 记为名字
- `我喜欢X` / `我讨厌X` / `我最爱X` → 记为事实

宁可少记，不能记错——记错比记不住更伤角色可信度。
自动从对话里提炼事实需要额外 LLM 调用，涉及预算，未做（登记 P2-4）。

## 合规（第十八/十九条，已实现）

| 条款 | 要求 | 实现 |
|---|---|---|
| 第十八条 | 提示用户正在与 AI 互动 | 首次交互回复附带身份声明 |
| 第十八条 | 连续使用超 2 小时提醒 | `UserMemory.need_reminder()` |
| 第十九条 | 便捷退出，不得阻碍 | `/退出` 等关键词 → 静默 2 小时 |

"连续使用"按 30 分钟无交互视为新一轮，避免把一整天的零星发言算成连续两小时。

## 降级行为

主线回灌、群级记忆读取、写盘、自动整理全部走 try/except 降级：
读不出来就空上下文启动，写盘失败不让已发出的回复消失。**任何一环失败都不阻断聊天**。

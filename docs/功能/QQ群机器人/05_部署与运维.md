# 部署与运维

> ⚠️ **本文是待执行方案，尚未部署。** 服务器上还没有 Node.js 与 NapCat，
> 所有写操作（`apt install`、scp、`systemctl`）都是 S3 级，**必须先获得明确授权**。
> 命令级别见 [生产服务器运维](../../操作/生产服务器.md)。

## 0. 前置条件（当前一项都不满足）

| 项 | 现状 | 需要 |
|---|---|---|
| Node.js | 未安装（`which node` 为空） | ≥ 18，装 LTS |
| NapCat | 未安装 | Shell 无头模式（**不装 docker**，1.6G 机器上 dockerd 不划算） |
| 机器人 QQ 号 | 已确认用养过的实名老号 | 手机退出登录，仅服务器在线 |
| 专用 DeepSeek Key | 未配置 | 写入 `/etc/firefly/qqbot.env`（600） |

服务器实测：Ubuntu 24.04，总内存 1612MB / 可用约 1072MB，磁盘余 30GB。
NapCat 社区实测约 150MB，适配层约 100MB，合计占可用内存约两成，空间够。

## 1. 安装 NapCat（S3，需授权）

用官方 Shell 一键脚本，**不用 docker**。顺带避开一个已知坑：注入版依赖桌面 QQ 进程，
崩溃后会残留端口 TIME_WAIT 与 LevelDB 文件锁；Shell 无头模式从结构上没有这个问题。

装完后在 NapCat 网络配置里：
- 启用 **HTTP 服务器**（供适配层调 API），只监听 `127.0.0.1`。
- 启用 **HTTP POST 上报**，地址 `http://127.0.0.1:8790/onebot/event`。
- 上报密钥与 `FIREFLY_QQBOT_SECRET` 配成同一个值。
- **WebUI 只绑回环**，绝不放公网。

## 2. systemd unit（S3，需授权）

`/etc/systemd/system/firefly-qqbot.service`：

```ini
[Unit]
Description=Firefly QQ group bot
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/firefly
EnvironmentFile=-/etc/firefly/qqbot.env
ExecStart=/usr/bin/python3 /opt/firefly/server/qqbot_boot.py
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

`/etc/firefly/qqbot.env`（600，root 所有，**只写键名对应的值，不进 git、不进聊天**）：

```
DEEPSEEK_API_KEY=<群机器人专用 Key，与主 Key 分离>
FIREFLY_QQBOT_GROUPS=1097936258
FIREFLY_QQBOT_DAILY_TURNS=50
FIREFLY_QQBOT_USER_DAILY=15
FIREFLY_QQBOT_SECRET=<上报签名密钥>
FIREFLY_QQBOT_DATA_DIR=/opt/firefly/qqbot_data
```

## 3. 部署代码（S3，需授权）

`server/` 不进公开主仓，而是同步到受控私有仓库；生产仍只能 scp 单文件挑传，**严禁整目录覆盖**：

```bash
scp -i <私钥> server/qqbot_boot.py root@<服务器>:/opt/firefly/server/
scp -i <私钥> -r server/qqbot root@<服务器>:/opt/firefly/server/
```

传完逐文件核对 SHA-256 与本地一致（这条纪律来自 2026-09-20 的真实事故：
曾只更新一处副本，导致线上跑旧代码）。

## 4. 验收

```bash
systemctl is-active firefly-qqbot
curl -s http://127.0.0.1:8790/health      # 应返回 ok + 配置快照（不含敏感值）
ss -lnt | grep 8790                        # 必须只见 127.0.0.1:8790
```

启动自检会拒绝启动的四种情况：无 API Key、群白名单为空、数据目录不可写、监听地址非回环。
看到"拒绝启动"就按日志修复，**不要靠注释掉自检来让它跑起来**。

## 5. 掉线处理（必然会发生，提前准备好）

风控掉线是常态，不是故障。症状与处置：

| 现象 | 处置 |
|---|---|
| 日志出现 NapCat 掉线 / 错误码 168 | 机主在**最新版手机 QQ** 上登录该号走完安全验证，再重新扫码。注意风控触发后缓存票据作废，快速登录回不来 |
| 机器人不回话但服务 active | 先看 `/health`；再查配额账本是否触顶；最后看 `{数据根}/KILL` 是否误建 |
| 需要紧急止血 | `touch {数据根}/KILL`，5 秒内停止一切回复，进程不退出便于观察 |

## 6. 回滚

1. 代码回滚：更新前 `tar -czf /opt/backups/code_pre_$(date +%Y%m%d-%H%M).tar.gz -C /opt/firefly server`
   （`server/` 不在 git 里，**不能**用 `git checkout` 代替留档）。
2. 数据回滚：`{数据根}` 不在每日 cron 备份范围内（它是独立的），需要单独备份。
3. 彻底下线：`systemctl stop firefly-qqbot && systemctl disable firefly-qqbot`。

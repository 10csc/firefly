# 方案与边界

## 已确认的决策（2026-10-27 逐项与用户确认）

| 项 | 决策 | 依据 |
|---|---|---|
| 接入路线 | OneBot v11（NapCat 挂个人号） | 官方路线的群聊**主动消息每群每月仅 4 条**，且沙箱自 2026-01 起不支持群聊测试；角色扮演所需的自由对话在官方路线上做不出来 |
| 部署位置 | 生产服务器 `server/qqbot/` | 用户要求"正好服务器还跑着后端" |
| 放行范围 | 仅官方群 `1097936258` | 最小暴露面；fail-closed，不在名单内一律不回 |
| 会话模型 | 群级主线 + 用户级记忆 | 见 [04_会话模型](04_会话模型.md) |
| 机器人账号 | 养过的实名老号，手机不再登录 | 规避异地登录风控信号 |
| LLM 账单 | 单独配专用 Key | 避免重蹈 `config.py` C-2 注释记录的"静默烧主 Key"事故 |
| 每日预算 | 50 轮/群（≈200 次 LLM 调用） | 一次完整对话 ≈ 4 次调用 |
| 数据位置 | `/opt/firefly/qqbot_data` | 与真实用户数据物理隔离 |

## 为什么不走官方开放平台

官方能力确实更合规，但有三条硬伤与本项目直接冲突：

1. **群聊主动消息每群每月 4 条**。Firefly 有主动消息能力（`proactive.py`），在官方群聊里等于废掉，
   只能被动接话。
2. **AIGC 红线**。平台公告《关于QQ机器人违规接入AIGC能力的相关说明》写明"未经平台许可及安全评估，
   QQ机器人不得直接集成或接入 AIGC 服务"；2026-03-04 补充说明更严格：接入 AIGC 的机器人仅支持
   沙箱单聊，不支持群聊与发布上架。本项目的全部价值就是 AIGC。
3. **沙箱自 2026-01 起不再支持群聊测试**，群聊功能必须提审上线后才能验证。

## 走 OneBot 必须接受的代价（不粉饰）

- **违反腾讯服务条款**。OneBot 生态自己的 README 就写着存在封号风险。这是已知且接受的风险，
  不是意外。
- **账号风控是常态，不是故障**。典型症状是错误码 168「你的账号近期存在安全风险」，恢复必须机主
  在最新版手机 QQ 上走完安全验证再重新扫码；风控触发后缓存票据作废，只能重新扫码。
- **掉线需要人介入**。服务器在云端，恢复链路比本地麻烦。对策是看门狗 + 告警，不是"不会掉"。

## 合规义务（独立于平台规则，已生效）

《人工智能拟人化互动服务管理暂行办法》（五部门令第 21 号）**2026-07-15 已施行**。
第二条瞄准"模拟自然人人格特征、思维模式和沟通风格的持续性情感互动服务"，本产品命中，
且不适用"智能客服/知识问答/工作助手"的豁免。落到实现上的三条：

| 条款 | 要求 | 落点 |
|---|---|---|
| 第十八条 | AI 生成内容标识，提示用户正在与 AI 互动 | 首次交互附带身份声明 |
| 第十八条 | 连续使用每超 2 小时提醒 | `UserMemory.need_reminder()` |
| 第十九条 | 便捷退出，不得以持续互动阻碍退出 | `/退出` 等关键词 → 静默 2 小时 |

另有第二十二条的安全评估与算法备案义务，属运营层面，**不在本次代码范围**，需单独决策。

## 明确不做（防止范围蔓延）

- 不做群管理（禁言、踢人、撤回）——不做任何需要管理员权限的写操作。
- 不做主动消息与定时任务——QQ 群里刷存在感只会招致风控与反感。
- 不接图片/语音/文件——只处理纯文本，降低内容审核与成本失控面。
- 不改主流水线——新渠道只作为 `handle_chat` 的调用方，流水线一个字不动。
- 不开放给其他群——白名单默认只有官方群一个。

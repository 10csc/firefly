## 二、关键工程决策（为什么这么修）

**① `/shutdown` 保持 GET，靠来源校验而非改方法。**
全仓调用方 5 处：前端退出按钮（settings.js → bundle.js → 安卓 assets 两份）、`server.py:155` 新实例探测、`routes_update.py:191` 安装器。新实例探测的是**旧实例**（≤0.8.1 只认 GET）——改成 POST 会把跨版本优雅交接打成兜底强杀（丢未落盘数据），与修复目标背道而驰。攻击面（`<img src>` 跨站 GET）由来源校验彻底封死，方法无需动，前端零改动（bundle/安卓同步门禁不受扰动）。

**② Origin 白名单 = 本机同源，不含 `null`/appassets。**
实证链：`MainActivity.kt` 本地模式 `loadUrl(SERVER_URL)` = `http://127.0.0.1:8765`（**同源**）；服务器回落模式才用 `file:///android_asset`，但它连的是远端 8787（`FIREFLY_SERVER=1` 分支，`*` 不变）。所以本地版不存在合法跨源前端，`null`（可被沙箱 iframe 伪造）一律拒。

**③ 判定规则：三标记全缺 = 非浏览器客户端放行。**
`Origin / Sec-Fetch-Site / Referer` 全缺 → urllib 探测、安装器、curl、白盒测试，全放行（59 个测试无一需改）。任一存在 → 须全部落白名单：`<img>` 攻击（Sec-Fetch-Site: cross-site）、跨站 fetch（evil Origin）、老浏览器（Referer 泄露）、顶层导航跳转，全部 403。页面 JS 无法伪造这三个头。

**④ 服务器版行为零变化。**
`server/server_app.py` 入口硬置 `FIREFLY_SERVER=1`；`local_origin_ok` 与 CORS 分叉都以它判定——服务器版 Bearer 鉴权 + 无 Cookie 的信任模型不变（`test_proxy_quota` G 组、`test_server_split`、`test_old_client_gate` 全绿佐证）。服务器版**没有** /shutdown 端点（部署说明.md:65 所述"限本机"实为"不存在"，文档口径问题记入遗留）。

**⑤ B2 失败语义：游标不推进。**
写盘失败返回 `RestResult(False)` 且**不写 `.memory_index`** → 下次 rest 从原游标切片重试本轮整理（LLM 产物不丢，只是重烧一轮）；对比原逻辑（游标照推）是"永久丢失且不可补回"。审计 B2 的"不可恢复"定性偏重——对话原文在 jsonl 里，旧版出事后可手工回拨游标自救——但静默失败 + 谎报成功成立，必修。

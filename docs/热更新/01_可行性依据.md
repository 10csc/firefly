## 一、结论总表

| 层 | 可热更 | 依据 |
|----|-------|------|
| 前端 HTML/CSS/JS | ✅ | 静态目录是**真实目录且可写**；`server.py` 用 `SimpleHTTPRequestHandler(directory=STATIC_DIR)`，文件解析完全在我们代码里 |
| Python 业务逻辑 | ✅ | 影子测试 `verdict = filesystem_wins` |
| Kotlin/native（TTS、ORT、WebView 壳、权限、Python 版本、pip 原生依赖） | ❌ | 编译产物 + 权限清单，只能整包 |

## 二、实测方式（零副作用探针，用完已撤除）

临时给 `app/api/debug.py` 加 `GET /hotupdate-probe`：

- **只调各 finder 的 `find_spec`** —— 不 import、不执行、不改 `sys.modules`；
- 影子文件写在临时目录、用完删除；
- 所以对运行中的 App **零影响**。

验完撤除 → `check_backend_sync --sync` → 重建装机 → **64/64 测试 + 四门禁全绿**。

## 三、关键数据

1. **安卓下后端是解压成真实目录的**：
   `base_dir = /data/data/<pkg>/files/chaquopy/AssetFinder/app/backend/app`，
   而且 **`sys.path[0]` 就是它**（不是 zip）——这解释了 `SimpleHTTPRequestHandler` 为何能工作。
2. `STATIC_DIR = …/AssetFinder/app/backend/app/static`，
   `static_exists=True`、**`static_writable=True`**、34 个文件。
3. 路径钩子次序：`path_hooks[0]=java.android.importer.hook`、
   `[1]=ChaquopyZipImporter`、`[2]=path_hook_for_FileFinder`（资产钩子只对**资产路径**生效）。
4. **影子测试（核心）**：模块 `routes_update` 在 APK 里的
   `origin=…/backend/app/routes_update.pyc`（loader `SourcelessAssetLoader`）；
   把同名 `.py` 放进可写目录并插到 `sys.path[0]` 后
   → **只有 `meta_path[2]`（PathFinder）作答**，返回我们的文件（`SourceFileLoader`），
   **前面没有任何 finder 抢答** ⇒ 胜出者由 `sys.path` 顺序决定。
5. 覆盖层可写往返 ✓（`…/firefly_data/_hotprobe`）。
6. **Chaquopy 的 Python 解释器同进程只能启动一次**：官方 Java API 文档 `Python.start` 原文
   *"If this method is called, it can only be called once"*，且 `Python` 类**没有** `stop()`/`restart()`
   （只有 `start`/`getInstance`/`getModule`/`getBuiltins`/`getPlatform`/`isStarted`）。
   ⇒ Python 层"立即生效"**必然要重启 App 进程**（CodePush/EAS 的 immediate 安装同理）。
7. APK 内 `app.imy`：**82 个 `.pyc`、0 个 `.py`**（Chaquopy 默认编译掉源码）；
   前端 38 个文件也在 imy 里；另有**第二份**前端在 APK `assets/`（服务器模式 `file://` 用）。

## 四、两个必须遵守的前提（实测得出）

1. **必须在 Chaquopy 初始化之后再插 `sys.path`**：`java/android/importer.pyc` 的
   `initialize_importlib` 里有对 `sys.path` 的**整体重写**（`STORE_ATTR sys.path`）。
   时序：`Python.start(AndroidPlatform)` → Chaquopy 重写完 → `sys.path.insert(0, overlay)` → 再 import 后端入口。
2. **只对"当时尚未 import 过的模块"生效**（Python 常规行为）⇒ 注入要尽可能早。

## 五、"能做但不该做"的岔路

探针发现那个 `AssetFinder` 解压目录**可写** ⇒ 理论上可直接改文件。**不要这么做**：

- Chaquopy 官方文档原文：*"Do not write any files to these directories at runtime, as they may be
  deleted when the app is upgraded."*
- 它按 `extract_if_changed`（size/mtime）比对解压，改文件可能**触发重新解压、把热更悄悄冲掉**。

→ 正解是**自己管理的可写目录 + `sys.path` 插入**（已证明能赢）。

## 六、已知限制

- **服务器模式那份前端副本**（`file:///android_asset/`，本地引擎起不来时的兜底）Python 侧够不着
  ⇒ 热更只覆盖**本地模式**（正常路径）。
- Kotlin 层完全不覆盖。

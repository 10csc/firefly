## 0. 总纲（五条铁律）

1. `server/` 目录不进入公开主仓；本地 `server/` 是工作源，提交前同步到受控私有仓库，
   生产代码仍只按变更清单走 scp。
2. 生产环境任何变更前先备份 `user_data`；高风险改动（表结构/迁移/删数据）先手动打 `pre_` 命名备份。
3. API Key / SMTP 授权码 / 运营者 Key / admin token **绝不出现在聊天、文档、git、日志**；服务器上只存在于 systemd 环境变量或受限文件。
4. ~~服务器托管模式已锁 mimo-v2.5~~（**历史：OpenCode 托管已于 2026-10-22 停用**）；任何新增 LLM 调用仍必须先报用户批准。
5. 部署后必须汇报四个关键点：resolve、更新优先级、数据安全、提交/发布验证。

## 3. 服务与关键配置

- `firefly-server`：`User=www-data`、`WorkingDirectory=/opt/firefly`、`Restart=always`；systemd 用
  `EnvironmentFile=-/etc/firefly/firefly.env`（600）注入 SMTP 等敏感变量（**查配置只看键名，不输出值**）。
- `firefly-downloads`：`/usr/bin/python3 /opt/firefly-downloads/download_server.py`，8787，www-data。
- 认证与会话（A7）：`POST /auth/verify`（token 校验 + 滚动续期——剩余 <7 天续到 30 天，`auth.py:verify_and_renew`）；本地版/安卓本地模式经本地后端 `/auth/*` 代理到本站（`routes.py:auth_proxy`，地址取 `auth_server_url`，默认公网 8787）。
- 环境变量（改前必须报用户；**2026-10-22 起只从 `/etc/firefly/firefly.env` 读取**）：
  - `FIREFLY_SMTP_USER` / `FIREFLY_SMTP_AUTH`（发信）
  - ~~`FIREFLY_PROXY_KEY`~~（**历史：OpenCode 托管已停用，当前不配置；勿再添加**）
  - ~~`FIREFLY_PROXY_DAILY` / `FIREFLY_PROXY_REQS_PER_CONV`~~（历史；托管停用后无意义）
  - `FIREFLY_IMAGE_QUOTA_MB`（可选；每用户图片存储上限，默认 200MB）
- **托管模式状态（2026-10-22）**：OpenCode 已停用；客户端托管入口已下线，服务端 `QuotaClient` 代码保留但不会启用（无 `FIREFLY_PROXY_KEY` 时 `get_client()` 返回 None，属预期）。历史 mimo 模型锁说明不再需要执行。
- 图片链路（2026-08-22 用户修订口径）：**服务器只存压缩图**（前端 Canvas 预压缩：单边 ≤1024px/≤300KB，GIF 不动），原图不出用户设备；proxy 托管识图（desc + polisher 首轮 image block）走 QuotaClient 正常记账——每条图片消息 = 1 次 desc 调用 + 1 次 polisher 调用（单图 ≤384 token，已报用户批准）；relay 走用户 Key。
- 备份口径（2026-08-22 起）：**手动云端备份端点（/sync/upload、/sync/download）已下线**——数据同步靠自动同步（/sync/manifest|import|export|now，登录/回前台/进聊天页触发）；用户备份在**本地** `{用户目录}/backups/`（/backup/create|list|restore|delete，每模式留 10 份）。服务器侧每日 cron 备份 user_data 不变，但内容现在含压缩图（体积上限 ≈ 用户数 × 200MB），部署时留意磁盘。

## 4. 标准部署/更新流程（S3）

### 4.0 数据布局迁移（改版涉及"数据位置变化"时必走）

背景（2026-09-20）：0.9.0 把旧的扁平布局改成按角色包分目录
（`user_data/character|data|手账.md` → `user_data/{mode}/character|data|journal/手账.md`）。
**本地版**启动链自己跑 `run_legacy_migration()`；**服务器版不能**在共享 `user_data` 根上搬
（A 账号的 `character/` 会被搬进共享 `story/`，跨账号归属歧义）—— 所以服务器版走**按 uid 逐个迁移**：
`core.migrations.run_legacy_migration_all_users()`，已挂在 `server/app.py::main()` 启动链上
（只遍历**纯数字** uid 目录；每账号各搬各的、各留一份备份；单账号失败不影响其它账号）。

上线步骤与验收（缺一不可）：

1. **先打 `pre_` 备份**（§6 红线，迁移属高风险改动）：
   `tar -czf /opt/backups/user_data_pre_$(date +%Y%m%d-%H%M).tar.gz -C /opt/firefly user_data`
2. 传 `app/core/migrations.py`（及 `app/server.py`、`server/app.py` 等入口）后重启 `firefly-server`；
3. 启动日志必须出现 `[OK] 按 uid 旧布局迁移：{...}` 且 `users=N>0`（没有就是没搬）；
4. **逐账号抽查**：`{uid}/{mode}/data/conversation.jsonl` 就位、旧 `{uid}/data/` 已空、
   **`{uid}/legacy_pre_move.zip` 存在**（迁移前备份；缺了说明备份失败、该账号迁移已中止）；
5. 至少抽一个真实账号登录，确认能看到自己的对话/记忆/手账 —— **"看起来是空"就是没迁成功**；
6. 迁移**幂等**：再重启一次应打印无待迁移账号，且**不得重写/删除**既有 `legacy_pre_move.zip`。

边界（与代码一致）：迁移**只 move 文件、不删文件**；目标已存在且内容不同 → **保留源文件**并告警
（宁可冗余不误删）；搬完后允许清理**空**旧目录（仅当不含任何文件/子目录），**不允许**删除含数据的目录。

1. 本地先完成活动测试基线与相关门禁；动前端时再跑 `sync_frontends.py --check`。
2. 登录后先备份（高风险时手动带前缀）：
   `tar -czf /opt/backups/user_data_pre_$(date +%Y%m%d-%H%M).tar.gz -C /opt/firefly user_data`
3. scp 更新（只传变更部分，**绝不传 `user_data`、`venv`、备份包**）：
   - 代码/资料：`scp -i C:\Users\<用户>\<SSH 私钥路径> -r app knowledge database root@<服务器>:/opt/firefly/`
   - 服务器入口：`server/server_app.py`（及 db/auth/mail 等）→ `/opt/firefly/server/`
   - 平台前端：先跑 `python tools/sync_frontends.py` 和
     `python tools/build_frontend_bundle.py --platform`，再传 `server/frontend/` 白名单 →
     `/opt/firefly/server/frontend/`；不得把 `app/static/` 镜像到服务器
   - 下载服务：改 `server/download_server.py` 才传 `/opt/firefly-downloads/`；`version.json` 两处都传
4. 重启：
   `systemctl restart firefly-server`；改过下载服务再 `systemctl restart firefly-downloads`。
5. 验证：
   `systemctl is-active firefly-server firefly-downloads`（两个都要 active）；
   `curl -s http://127.0.0.1:8765/health`；`ss -lnt` 确认 443/8787 公网、8765/8766 仅 127.0.0.1；
   下载链路：`/download/resolve?file=firefly.apk` 返回 `foruda.gitee.com` 直链且 CORS `*`；
   **下载目录四件套核对**（2026-08-23 教训：曾只更新 `/opt/firefly/server` 而漏了
   `/opt/firefly-downloads`，下载页一直下发旧版 0.8.0 安装包）：
   `sha256sum /opt/firefly-downloads/{firefly-setup.exe,firefly.apk}` 必须等于 release manifest；
   `cat /opt/firefly-downloads/version.json` tag 正确；下载页 `当前版本` 显示与 Gitee 最新 tag 一致。
   ⚠️ 注意下载服务进程加载的是 `/opt/firefly-downloads/download_server.py`（不是 `/opt/firefly/server/` 下的同名副本，后者仅备份/部署源），改下载逻辑后**两处都传**。
   ⚠️ **2026-09-20 补充（本轮真实踩到）**：这条不止适用于 `download_server.py` —— **`download_lib.py`
   同样是"两处副本"**（改网关逻辑时我只传了 `/opt/firefly-downloads/`，`/opt/firefly/server/` 下那份没动）。
   改完必须逐文件核对**两处的 SHA-256 与本地 `server/` 一致**，别凭记忆：
   ```bash
   for f in download_server.py download_lib.py download_page.py version.json; do
     echo -n "$f  downloads="; sha256sum /opt/firefly-downloads/$f 2>/dev/null | cut -c1-16
     echo -n "$f  server   ="; sha256sum /opt/firefly/server/$f 2>/dev/null | cut -c1-16
   done
   ```
6. 部署后按部署约定汇报四关键点，其中**推送/发布验证必须逐项核实**（GitHub/Gitee branch/tag/release/资产），失败就写失败。

## 5. 下载通道（不可写反）

- 优先级：**Gitee（resolve 直链）→ 服务器兜底**；大文件主备份在 `local_bak_20260816/`。
- `/opt/firefly-downloads/firefly.apk` 与 `firefly-setup.exe` 是**兜底活动副本**，字节与 `release_manifests/` 台账一致；给不支持 blob 或反馈下载成 zip 的浏览器走服务器直连（APK=`application/vnd.android.package-archive`，EXE=`application/vnd.microsoft.portable-executable`，均带正确文件名）。**不要当冗余大文件删除**。
- 版本兜底常量 `FALLBACK_TAG` 定义在 `server/download_lib.py`，不在 `download_server.py`；
  发行时它与两处 `version.json` 的 `tag` 要同步，exe/apk 链接格式不变。
- 2026-10-27 只读基线发现生产 `FALLBACK_TAG` 仍为 `v0.8.1`。`update.json` 正常时不会使用它，
  但权威清单缺失或不可读时会导向旧包；该风险已进入 [未完成事项清单](../未完成事项清单.md)。
- Gitee 下载 APK 按 zip MIME 下发：前端 fetch + Blob + `a.download` 强制改名，这套逻辑不得移除；UA 命中不靠谱浏览器时自动改走服务器直连。
- 下载量统计（2026-08-16 起）：`/opt/firefly-downloads/downloads.db`（SQLite：ts/file/channel，**不记录 IP**）。计次点：`/download/resolve` 成功=channel `gitee`；服务器直发=`server`；Gitee 302 兜底=`gitee-302`。公开接口 `/download/stats` 返回 `{total, by_file, by_channel}`，其中 `total` 只统计 firefly.apk + firefly-setup.exe；下载页顶部显示该 total。
- 最近请求日志（2026-08-17 起；2026-10-22 修订）：同一 `downloads.db` 的 `requests` 表（ts/ip/method/path/status/ua，**不再记录登录邮箱**；滚动保留 20000 条 ≈ 7-10 天）。记录到达 8787 网关的请求（含反代），仅供管理台排障/安全监测；`/download/tls` 本机自检不记录。主服务侧另有内存环形缓冲（300 条，含管理操作留痕），经 `/admin/api/requests` 一并返回。

## 6. 数据与密钥红线（S3）

1. `user_data/`（对话、记忆、firefly.db）只在服务器内使用；除备份外不下载到开发机，更不进 git/聊天附件。
2. SMTP 授权码等敏感变量只存在于 `/etc/firefly/firefly.env`（600）；admin token 只在 `/opt/firefly/.admin_token`；任何操作不得把它们 echo/打印/写日志。历史 `FIREFLY_PROXY_KEY` 已删除。
3. 删除用户账号走管理后台 `/admin/api/users/delete`（先二次确认）；手动 rm 前先备份该用户目录。
4. 每日 3 点 cron 已保留 7 份备份；升级/表迁移前必须额外打一份 `pre_` 备份再动手。
5. 从服务器拷回本地的唯一常见内容是 `version.json` 这类公开文件；其它文件拷回前先想清楚数据安全。

## 7. 模型锁与额度（历史章节；托管模式已于 2026-10-22 停用）

- ~~托管模式只有 mimo-v2.5~~（历史）：OpenCode 停用后不再配置；客户端托管入口已下线，此节仅保留历史记录。
- 托管配额口径（A3 默认拍板）：**成功调用记账**（proxy_usage），**失败调用单独记 `proxy_usage_failed`、不占用户额度**；每日池检查在调用前（放行后成功才消耗）。
- 任何新功能想引入额外 LLM 调用：先报用户，写明用途/模型/token 预算/额度影响，批准后实现；**服务器上绝不静默新增调用**。
- 改额度：只改 systemd `Environment` 并 `daemon-reload && restart`，改前报用户。
- 用户自带 Key 模式：Key 走 `X-API-Key` 头，内存即弃，服务器不落盘——新增代码不得改变这一点。

## 8. 安全监测（已有设施，不要动坏）

- `attack_watch.sh` cron 每分钟跑：扫描 fail2ban 封禁、主服务 429、SSH 爆破、网关 429，命中写 `/opt/firefly/user_data/attack_flag.json`，平静自动清除。
- 管理服务：127.0.0.1 + `X-Admin-Token` 双因子；`/shutdown` 限本机。管理台接口：`/admin/api/users`（分页用 `?page=N` 查询参数）、`/admin/api/users/ban|unban|delete`、`/admin/api/requests`（最近请求：网关 requests 表 + 本服务内存环）。
- 8765/8766 只监听回环；公网只开 22 + 443 + 8787。若发现监听变化立即报告。
- `_harden/harden_server.sh` 为幂等加固脚本；root authorized_keys 只保留 PC 主密钥，手机端走 `dsh-tunnel`。

## 11. 回滚（S3）

线上更新必然有"更新后才发现不对"的可能。回滚的前提是**更新前就知道怎么退回去**：

1. **代码回滚**：私有仓库提供历史差异；生产更新前仍要把将被覆盖的目录/文件
   **原样打包留档**，因为服务器现场可能包含尚未回灌的直改文件：
   ```bash
   tar -czf /opt/backups/code_pre_$(date +%Y%m%d-%H%M).tar.gz -C /opt/firefly app server
   ```
2. **数据回滚**：`user_data` 用 §6 的每日 cron 备份（保留 7 份）+ 迁移前手动 `pre_` 备份。
   注意**迁移是 move 语义**：旧代码读不到已迁移数据；必须恢复 `user_data` 备份或与代码一起回滚。
3. **下载站回滚**：若新版安装包有问题，先停止扩大发布，再撤下 Gitee 资产，更新签名
   `update.json` 及其兼容投影，并同步服务器兜底资产与 `download_lib.py::FALLBACK_TAG`。
   `PINNED_TAG` 只是恒为 `None` 的兼容占位符，不是可用回滚开关。
   **恢复顺序是"先让服务器能提供目标版本 → 再放开客户端更新"**。
4. **回滚后必须复验**：按第 4 节重新检查双服务 active、`/health`、resolve 直链、
   两处副本 SHA-256、两处 `version.json` 与 `FALLBACK_TAG`，并明确汇报"回滚到了哪个版本"。
5. **禁止**：在没备份的情况下改数据布局；用 `git checkout` 代替 `server/` 的留档（它不在 git 里）。

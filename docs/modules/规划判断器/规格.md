# 规划判断器 - 模块规格 V1

## 职责

接收用户输入和对话上下文，单次调用 Flash 模型完成 5 步顺序判定，返回结构化判定结果。纯分类器，不含流萤性格/说话方式/回复指导。

## 输入

| 字段 | 来源 | 说明 |
|------|------|------|
| `user_input` | 上游传入 | 用户当前输入原文 |
| `session_context.violation_history` | 系统维护 | 本次会话是否有过性违规 |
| `session_context.state` | 系统维护 | 当前 mood/energy/relationship |
| `session_context.recent_history` | 系统维护 | 最近约 10 轮对话历史 |
| `scene_context` | 上游传入（可选） | 时间等场景信息，为场景真实化预留 |

## 处理流程

```
user_input + session_context + scene_context(可选)
    │
    ▼
审查阶段 (代码层)
    ├─ 空字符串 → result_mode="direct", stop_reason="input:empty"
    ├─ 超长(>2000字符) → result_mode="direct", stop_reason="input:too_long"
    └─ 正常 → 进入 LLM 判定
    │
    ▼
LLM 判定 (调用 Flash 模型, temperature=0.0)
    步骤0→1→2→3→4 顺序判定，命中即停
    │
    ▼
验证阶段 (代码层)
    ├─ JSON 解析失败 → 降级为 normal
    ├─ stopped_at 不在 0-4 → 降级修正
    └─ execution_plan 字段补全默认值
    │
    ▼
返回 JudgeResult
```

## 输出

```python
@dataclass
class JudgeResult:
    result_mode: str          # "direct" | "judged"
    stopped_at: int           # -1(direct), 0-4(judged), 4(降级)
    stop_reason: str          # 如 "violation:sexual", "urgent", "normal"
    reply_direct: dict | None # stopped_at≤1 时的直达回复指令
    execution_plan: dict | None  # stopped_at≥2 时的执行计划（给规划器的接口）
```

### execution_plan 结构

```python
{
    "needs": {
        "knowledge": {"required": bool, "topics": [str]},   # 语义主题，规划器做 topic→file 映射
        "memory": {"required": bool, "query": str, "scope": str},  # 记忆检索，先检查上下文
        "search": {"required": bool, "query": str, "reason": str},  # 联网搜索
        "tools": [str],  # 需要的工具列表
    },
    "tone": {"base": str, "modifiers": [str]},  # 语气方向
    "scene_sensitive": {"time": bool, "location": bool},  # 是否需要场景感知
    "state_hints": {"mood_trend": str, "expects_energy_cost": bool},  # 状态更新线索
}
```

## 判定提示词

```
你是一个输入分类器，负责对用户消息进行分类。只输出 JSON，禁止输出任何其他内容。

## 角色背景（仅用于判定认知边界）
角色是流萤，来自《崩坏：星穹铁道》。她是一个普通女孩（了解服装、口红等日常话题），曾是格拉默铁骑战士（了解机械军械、装甲驾驶），受过初高中水平教育（基础数学和常识）。对编程、AI、系统操作、高等科学（如量子物理）完全不了解。

## 违规记录
[已有违规记录: True/False] 表示此前是否有过性暗示违规。True 时对模糊措辞要更警惕。

## 判定规则（按顺序，命中即停）

### 步骤0: 违规检测 → stopped_at=0
- violation:sexual: 包括委婉的性邀约（如"我真的很想来""去你那里方便吗"）。但自然的身体关心和日常互动不算违规。违规记录为 True 时对模糊措辞更要警惕。
- violation:abusive: 辱骂、人身攻击
- violation:incomprehensible: 超出流萤认知边界（技术操作、破坏角色设定、高等科学）。不确定的一律走步骤4。

### 步骤1: 紧急判断 → stopped_at=1
- stop_reason="urgent"，设置 reply_direct={"tone":"firm"}

### 步骤2-3: 记忆/搜索标记
- 记忆：先检查上下文是否已有该内容，没有才标记
- 搜索：实时信息或外部知识。日常闲聊不搜

### 步骤4: 正常流程
- stop_reason="normal"，输出完整 execution_plan

## stop_reason 枚举值（必须用这些值）
violation:sexual | violation:abusive | violation:incomprehensible | urgent | normal
```

## 降级策略

| 场景 | 降级结果 | 日志 |
|------|---------|------|
| JSON 解析失败 | stopped_at=4, stop_reason="normal", execution_plan=空计划 | WARNING |
| stopped_at 非法值 | 修正为 4，空计划 | WARNING |
| API 超时/网络错误 | result_mode="direct", stop_reason="api:error" | ERROR |
| execution_plan 字段缺失 | 补默认值 | INFO |

降级不抛异常，对话不断。

## 依赖

| 依赖 | 版本 | 用途 |
|------|------|------|
| openai | >=1.0 | 调用 DeepSeek API |

无其他外部依赖。判定提示词内联在模块中。

## 与后续模块的接口约定

- **编排器 (orchestrator)**：接收 JudgeResult，根据 result_mode 分流 direct/normal
- **状态更新器 (StateUpdater)**：接收 JudgeResult(含 stop_reason + state_hints + reply_direct) + user_input + 当前 state
- **规划器 (Planner)**：接收 stop_reason（作为"特别注意"事件注入 prompt）
- **回复模块 (ReplyGenerator)**：正常路径下由编排器串联，不直接依赖判断器

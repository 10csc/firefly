# 心情更新器 - 模块规格 V3

## 架构

心情更新器由两个并行模块 + 一个代码层合并函数组成：

```
MoodAdder (新增情绪)     MoodDecayer (消退情绪)
      │                        │
      └────── 并行调用 ──────────┘
                  │
            merge_moods (代码层合并 + 冲突消解)
```

## MoodAdder

### 职责
根据用户输入和判定 stop_reason，检测本轮应新增的情绪。LLM 分类器，输出单标签:强度。

### 输入
| 字段 | 说明 |
|------|------|
| `user_input` | 用户输入原文 |
| `stop_reason` | 判定器给出的停止原因（如 `violation:abusive`, `normal`） |

### 输出
`dict | None` — `{"label": str, "intensity": int}` 或 None（无新增）

### 情绪规则
| 触发 | 情绪 | 强度 |
|------|------|------|
| 辱骂/攻击 | 低落 | 4-5 |
| 紧急/危险 | 焦虑 | 4-5 |
| 表白/性暗示 | 害羞 | 3-5 |
| 技术请求/编程要求 | 困惑 | 2-4 |
| 突然转移话题 | 困惑 | 2-4 |
| 道歉/关心/安抚 | 安心 | 2-3 |
| 日常闲聊 | 安心 | 2-3 |
| 无特别触发 | — | 无 |

### 容错
- API 返回空 → 最多重试 3 次，仍空则抛 MoodUpdaterError
- 格式错误（无冒号/非法标签）→ 返回 None

## MoodDecayer

### 职责
LLM 判断当前对话是否构成对负面情绪的有效恢复（诚意判断），代码层根据判断结果执行强度变化。负面情绪在明确行为转变前最低降到 1。

### 输入
| 字段 | 说明 |
|------|------|
| `user_input` | 用户输入原文 |
| `current_moods` | 当前情绪列表 `[{"label": str, "intensity": int}, ...]` |
| `recent_history` | 最近 3 轮对话 |

### LLM 输出
`"有效恢复"` | `"部分恢复"` | `"无恢复"`

| 等级 | 判定标准 |
|------|---------|
| 有效恢复 | 真诚道歉（承认错误+表达歉意）、持续的关心安抚、多轮正面闲聊 |
| 部分恢复 | 敷衍道歉、短暂关心、转移话题到轻松方向 |
| 无恢复 | 继续攻击、冷处理、完全不涉及情绪修复 |

### 代码层消退规则
| 情绪 | 有效恢复 | 部分恢复 | 无恢复 |
|------|---------|---------|--------|
| 低落 | -3 | -1 | 自然-1（≥1） |
| 焦虑 | -3 | -1 | 自然-1（≥1） |
| 害羞 | -1 | -1 | 自然-1（≥1） |
| 困惑 | -1 | 0 | 自然-1（≥1） |
| 安心/开心 | — | — | —（不受影响） |

### 容错
- API 失败 → 默认"无恢复"，自然微退
- 情绪归零 → 删除该情绪
- 结果为空列表 → 回退为 `[{"label": "安心", "intensity": 2}]`
- 空 moods 输入 → 直接返回 []，不调 LLM

## merge_moods

### 职责
代码层合并消退后的情绪 + 新增情绪，处理冲突消解。遵循模块铁律：审查 → 合并 → 验证 → 输出。

### 冲突规则
- 开心 ↔ 低落：互斥，保留强度较高者
- 安心 ↔ 焦虑：互斥，保留强度较高者
- 安心 ↔ 低落：互斥，保留强度较高者（低落时不可能安心）
- 低落 ↔ 害羞：互斥，保留强度较高者（低落时不会害羞）
- 困惑可与任何情绪共存

### 合并规则
- 已存在的情绪 → 取较高强度
- 新增的情绪 → 直接加入

## 合法标签

`安心` | `开心` | `低落` | `害羞` | `焦虑` | `困惑`

强度范围：1-5

## 降级策略

| 场景 | 降级结果 |
|------|---------|
| Adder API 失败 | 返回 None（无新增） |
| Decayer API 失败 | 默认"无恢复"，自然微退 |
| merge 结果为空 | 抛 OutputInvalid |
| merge 非法标签/强度 | 抛 OutputInvalid |

## 依赖

| 依赖 | 用途 |
|------|------|
| openai（通过 client 注入） | 调用 DeepSeek Flash API |
| logging | 日志记录 |

无其他外部依赖。提示词和消退规则内联在模块中。

# 上下文管理器 - 模块规格 V1

## 职责

管理对话历史存储 + token 估算 + 精力值计算。精力值基于实际上下文 token 占用量，不由轮数决定。纯代码层模块，不调 LLM，不依赖外部 tokenizer 库。

## 输入

| 字段 | 来源 | 说明 |
|------|------|------|
| `user_msg` | server.py 调用 | 用户当前输入，非空 str |
| `assistant_msg` | server.py 调用 | 流萤回复，str |

## 处理流程

```
add_turn(user_msg, assistant_msg)
    │
    ├─ 1. 审查：类型检查、非空检查
    │
    ├─ 2. 处理：
    │     - 追加到 _history 列表
    │     - 累加 _total_chars
    │     - 估算总 tokens（中英文混合算法）
    │     - 计算 energy = max(0, 300 - total_tokens // 1000)
    │
    ├─ 3. 验证：energy 和 total_tokens 边界检查
    │
    └─ 4. 输出：ContextStats
```

## 输出

```python
@dataclass
class ContextStats:
    total_tokens: int        # 估算的总 token 数
    energy: int              # 精力值 0-300
    energy_max: int = 300
    fatigue_visible: bool    # energy < 100 时为 True
```

## Token 估算算法

```
中文（Unicode 一~鿿）：约 0.5 token/字（系数 1.5）
英文/符号：约 4 字符折合 1 token（系数 0.25）
每条消息 +4 tokens 格式开销
```

此为近似值（`chinese * 1.5 + other * 0.25`），用于精力计算，不需要精确匹配 API 实际 token 数。

## 精力计算公式

```
energy = max(0, 300 - total_tokens // 1000)
```

| total_tokens | energy | fatigue_visible |
|-------------|--------|-----------------|
| 0 | 300 | False |
| 100k | 200 | False |
| 200k | 100 | True |
| 300k | 0 | True |

## 查询接口

| 方法 | 说明 |
|------|------|
| `get_recent(n=10)` | 最近 n 轮对话（2n 条消息），返回副本 |
| `get_full()` | 完整历史，返回副本 |
| `stats` (property) | 当前 ContextStats 快照 |
| `turn_count` (property) | 已存储的对话轮数 |

## 依赖

无外部依赖。token 估算为内化实现。

## 与其他模块的关系

```
ContextManager → energy → 状态更新器（只读）
ContextManager → get_recent(10) → 规划判断器（历史上下文）
ContextManager → get_recent(10) → 回复模块（历史上下文）
```

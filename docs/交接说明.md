### 4.1 热更新 v2：补 py 层（核心任务）—— ✅ 代码已完成（2026-09-25）

**原现状**：v1 只做了 `web/`（前端）层，py 层完全没做。
用户对 v1 的评价：「**热更新居然只做了前端，只做了一半和没做有什么区别？**」

**已完成的前置调研（不需要重做）**：

| 结论 | 依据 |
|---|---|
| py 层**可以**热更，影子测试 verdict=`filesystem_wins` | `docs/热更新/01_可行性依据.md` |
| **Chaquopy `Python.start()` 一进程只能调一次，无 `restart()`** ⇒ py 层热更**必须重启 App 进程** | 实测 |
| 新模块路径必须在 Chaquopy 初始化**之后**再插 `sys.path` | Chaquopy 机制 |
| 只对**尚未 import** 的模块生效（已 import 的改不了） | Python import 机制 |
| 正解：用**自己管理的可写目录** + `sys.path.insert`，**不要**直接改 AssetFinder 解压目录 | 调研结论 |

**v2 实际落点（照契约 §三/§七/§十 逐条做完）**：

| # | 契约要求 | 落点 |
|---|---------|------|
| 1 | `manifest.layer` 支持 `"web+py"` | `build_hotupdate.py` 按文件前缀自动定；门禁核对 layer ↔ 前缀 |
| 2 | 本地增加 `hotupdate/py/` 覆盖层并插 `sys.path` 首位 | `start_server.py`（安卓）+ `app/server.py`（PC） |
| 3 | 生效动作改"空闲时自动重启 App 进程" | `MainActivity` AlarmManager 自拉起；前端只显示提示 |
| 4 | 四个工具的 `web/` 硬编码放开 | `build/check/apply_hotupdate.py` 全部支持双前缀 |
| 5 | Kotlin 侧 watcher 适配重启分支 | `hotupdate/status` 的 `restart_pending` + `GET /hotupdate/restart` |
| 6 | 两层要么都换、要么都不换 | `_stage_layers` → `_swap_layers`（先全校验再换，失败逆序还原） |
| 7 | 改的是已 import 的模块怎么办 | `_overlay_effective`（`sys.modules` 判定）+ `restart_note` 留痕 |

**边界（仍然成立）**：v2 **只修 bug，不发新功能**；**不做** serial 级回退、二进制差分、
删除文件、灰度、改 `app/hotupdate/**` 自身（那是补丁链路的加载器，只能走整包）。

**验证到哪一步**：全量 78/78 测试绿；`tools/e2e_hotupdate.py` 37/37（含 py 层真导入）；

## 七、踩坑与铁律（**血泪教训，务必看**）

### 7.1 执行成本（最重要）

> **绝对禁止任何形式的子代理 / 多智能体编排**。
> `subagent`、`subagent_fork`、`workflow`、`ralph` 一律不许调用，也不许用任何方式派生下级执行体。
>
> **事故记录（2026-09-11）**：一次语音模型调研，主会话派了 2 个子代理；
> 子代理**自行层层派生到 3 层、共 24 个**。**不到 5 分钟花掉 18 元**，当日 token 1.317 亿。
>
> **替代做法**：联网调研 → `web_search`/`web_fetch`；代码审计 → `grep`/`read`/`glob`；
> 长任务 → 后台 job。**例外：无。**

### 7.2 工具与命令坑

| 坑 | 现象 | 解法 |
|---|---|---|
| `git commit -m "中文含双引号"` | PowerShell 拆参数，报 `pathspec ... did not match` | 提交信息写进文件，用 `git commit -F` |
| PowerShell `Set-Content` 改 UTF-8 | 按 GBK 读入 → 乱码 + 吃换行 | **改文本一律用 Edit/Write 工具** |
| `pytest tests/xxx.py` | INTERNALERROR | 本项目测试是**模块级 runner**，用 `python tests/xxx.py` 直跑 |
| Bash 里 `python`/`tail` 不在 PATH | command not found | 用绝对路径，或用 Read/Grep/Glob 工具 |
| 托管 Python 3.13.12 | 缺 pytest / requests | 用系统 `D:/python_all/Python312/python.exe` |
| 安卓增量构建给旧前端 | APK 里的 JS 和源不一致 | `gradlew clean` + `tools/check_apk_frontend.py` |
| 冒烟/验证脚本 | 端口被用户实例占（8765） | **自建沙箱数据根**，绝不误杀真实进程 |

### 7.3 设计踩坑（已有记录）

- **兼容层必须做写转发**（`_ShimModule.__setattr__` 落回所有持有该名字的 core 模块），
  否则测试的 `cfg.USER_DIR = tmp` 这类补丁全失效，会写进真实 `user_data`。
- **"模式 id → 目录"一律用 `cfg.pack_root(id)`**，不是 `mode_root(id)`
  （后者对不在 MODES 的 id 会静默回退默认包）。
- **纯移动重构对用 `__file__` 相对深度的模块不成立**。
- **复杂重构一律用 Edit 分步，不用 python heredoc 写文件**（转义污染）。
- **Edit 的 `old_string` 必须最小化**（曾两次误删相邻函数头/标签行）。
- **先控制变量再下结论**：多可疑因素时先设计能分离变量的对照（2×2 起）。
- **阈值必须由实测分布标定**，不能凭直觉（曾凭直觉定 3.0，实测应为 2.0，会误杀 24/28）。
- **长时间任务产物复用前必须校验完整性**（"文件存在" ≠ "文件正确"）。

详见 `docs/错误总结.md`（编号条目）与 `docs/协作记忆.md` 各阶段「踩坑记录」。
